3 ปัญหาคลาสสิกที่ตามมา

1Compatibility / Dependency

service คนละตัวต้องการ library คนละเวอร์ชัน แต่เครื่องเดียวลงได้เวอร์ชันเดียว — ดูตัวอย่างจริงทางขวา

2Long setup time

เครื่องใหม่ หรือคนใหม่เข้าทีม ต้องไล่ติดตั้งใหม่ทั้งหมด เสียเวลาเป็นวัน และมักตกหล่นบางขั้น

3Different Dev / Test / Prod

รันได้บนเครื่องตัวเอง แต่พังบน production — "it works on my machine"

ต้นเหตุร่วมของทั้ง 3 ข้อคือ ทุกอย่างมัดรวมอยู่บน OS และ Libs ชุดเดียวกัน แยกออกจากกันไม่ได้

Docker คือ open-source platform ที่ทำให้การ deploy แอปพลิเคชันเป็นอัตโนมัติ โดยรันแอปไว้ใน software container — เป็นการทำ OS-level virtualization บน Windows และ Linux

แล้ว Docker เปลี่ยนอะไร?

งานเดียวกัน — เทียบก่อนกับหลังมี Docker

ก่อนมี Docker

1. ติดตั้งแพ็กเกจของ OS ให้ถูกตัว
2. ติดตั้งโปรแกรมและ library ทั้งหมด
3. ไล่แก้เวอร์ชันที่ชนกันด้วยมือ
4. ตั้งค่าให้ครบทุกอย่าง
5. ทำซ้ำทั้งหมดนี้อีกรอบบนเครื่องถัดไป

ใช้เวลาเป็นชั่วโมง · พอเปลี่ยนเครื่องก็พังอีก

หลังมี Docker

ทั้งหมดที่ต้องทำ เหลือแค่บรรทัดเดียว :

docker run nginx

→ ได้เว็บเซิร์ฟเวอร์ที่ทำงานอยู่แล้ว ไม่ต้องติดตั้งอะไรเพิ่ม

ใช้เวลาไม่กี่วินาที · ได้ผลเหมือนกันทุกเครื่อง

Dockerfile

Image เป็นชั้น ๆ

ชั้นที่ซ้ำกับของเดิมไม่ต้องโหลดใหม่ ประหยัดทั้งพื้นที่และเวลา

Docker Hub

คลังกลาง มีของสำเร็จรูปให้ดึงมาใช้ได้ทันที ไม่ต้องสร้างเอง

คำสั่งเดียวจบ

docker run แค่นี้ก็ได้ของที่ทำงานอยู่จริง ไม่ต้องตั้งค่าอะไรอีก

Container คืออะไร?

สภาพแวดล้อมที่ถูกแยกออกจากกัน แต่ยังใช้ kernel ร่วมกัน
โลโก้ Docker คือวาฬที่แบกตู้คอนเทนเนอร์ — ตัววาฬคือ Docker ที่รันอยู่บนเครื่อง ส่วนตู้บนหลังคือ container แต่ละตัวที่มันแบกไว้ ตรงกับรูปทางซ้ายพอดี
Docker — Week 8 · Overview

อยู่ในกล่องแล้วมองเห็นอะไรบ้าง?

3 อย่างที่แต่ละกล่องมีเป็นของตัวเอง — ลองสั่งคำสั่งดูได้จริง

1. โปรแกรมที่รันอยู่

เข้าไปในกล่อง A แล้วดูรายชื่อโปรแกรม จะเห็นแค่ของกล่องตัวเอง ไม่เห็นของกล่อง B และไม่เห็นของเครื่องแม่

docker exec -it A ps

2. เครือข่ายและเลข IP

แต่ละกล่องมี IP ของตัวเอง — กล่อง A เป็น 172.17.0.2 กล่อง B เป็น .3 ทั้งคู่จึงเปิด port 5000 พร้อมกันได้โดยไม่ชนกัน

3. ไฟล์และโฟลเดอร์

สั่งดูไฟล์ในกล่อง จะเห็นไฟล์ของกล่องนั้น ไม่ใช่ไฟล์ในเครื่องเรา เว้นแต่เราเอาไปแปะให้เองด้วย -v

docker exec -it A ls /
ทั้ง 3 อย่างนี้ Linux ทำให้อยู่แล้ว — Docker แค่สั่งให้มันทำงานให้อัตโนมัติ ไม่ได้สร้าง OS ใหม่ซ้อนเข้าไป
ไม่มี OS ซ้อน → กล่องจึง เล็กและเริ่มทำงานเร็ว

ดึงลงมาใช้ — pull

Image กับ Container ต่างกันอย่างไร?

เทียบกับของใกล้ตัว แล้วดูจากคำสั่งจริง

Image = ไฟล์ติดตั้งที่เก็บไว้ในเครื่อง

เหมือนไฟล์ติดตั้งโปรแกรมที่โหลดมาเก็บไว้ แต่ยังไม่ได้เปิด
· ตัวมันไม่เปลี่ยนแปลงเอง
· ก๊อปส่งให้เพื่อนแล้วได้ของเหมือนกันเป๊ะ

Container = โปรแกรมที่กำลังเปิดอยู่

พอสั่งเปิด ก็ได้ของที่ ทำงานอยู่จริง
· เปิดพร้อมกันหลายตัวจากไฟล์เดียวได้
· สิ่งที่แก้ตอนเปิด จะหายไปเมื่อลบทิ้ง

docker build -t myapp:1.0 .    # ได้ image 1 อัน
docker images                  # เห็น myapp:1.0

docker run --name a myapp:1.0  # container ตัวที่ 1
docker run --name b myapp:1.0  # ตัวที่ 2 จาก image เดิม
docker ps                      # เห็นทั้ง a และ b
ลบ container a ทิ้ง — image ยังอยู่ครบ สร้างตัวใหม่จาก image เดิมได้เสมอ
Image = แม่พิมพ์  ·  Container = ของที่ปั๊มออกมา แม่พิมพ์อันเดียว ปั๊มของออกมาได้ไม่จำกัดจำนวน

ภาพรวมการติดตั้ง 3 ช่วง

1เตรียม Repository

อัปเดต apt → ติดตั้ง ca-certificates, curl, gnupg → เพิ่ม GPG key และ repository ของ Docker

2ติดตั้งและเปิดใช้งาน

ติดตั้ง docker-ce + plugin → systemctl enable และ start ให้ service ทำงานทุกครั้งที่เปิดเครื่อง

3ตั้งสิทธิ์ + ตรวจสอบ

เพิ่ม user เข้ากลุ่ม docker → ตรวจด้วย docker --version และ docker compose version

ทำไมต้องเพิ่ม repository เอง? เพราะ Docker เวอร์ชันใน apt ปกติของ Ubuntu มักเก่ากว่ามาก การเพิ่ม repo ทางการทำให้ได้เวอร์ชันล่าสุดและอัปเดตต่อเนื่อง
Docker — Week 8 · LAB 1
LAB 1

ช่วงที่ 1 — เตรียม Repository ของ Docker

# 1) อัปเดตรายการแพ็กเกจ
sudo apt-get update -y

# 2) ติดตั้งเครื่องมือที่จำเป็นก่อน
sudo apt-get install -y ca-certificates curl gnupg

# 3) สร้างไดเรกทอรีเก็บ GPG key
sudo install -m 0755 -d /etc/apt/keyrings

# 4) เพิ่ม GPG key อย่างเป็นทางการของ Docker
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# 5) ตั้งสิทธิ์ให้อ่าน key ได้
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# 6) เพิ่ม Docker repository เข้า apt sources
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 7) อัปเดตอีกครั้ง เพื่อให้ apt เห็น repo ใหม่
sudo apt-get update -y

ช่วงที่ 2 — ติดตั้งและเปิดใช้งาน Service

# 8) ติดตั้ง Docker Engine + CLI + containerd + plugin
sudo apt-get install -y docker-ce docker-ce-cli containerd.io \
                        docker-buildx-plugin docker-compose-plugin

# 9) เปิดใช้งานและสั่งให้ service เริ่มทำงาน
sudo systemctl enable docker   # ให้เริ่มเองทุกครั้งที่บูตเครื่อง
sudo systemctl start  docker   # เริ่มทำงานเดี๋ยวนี้

# 12) ติดตั้ง Compose plugin
sudo apt-get install -y docker-compose-plugin
แพ็กเกจหน้าที่
docker-ceDocker Engine ตัวจริง (daemon ที่คอยรัน container)
docker-ce-cliคำสั่ง docker ที่เราพิมพ์ใน terminal

docker ps vs docker ps -a

docker run ubuntu     # ubuntu ไม่มีคำสั่งค้างไว้ จึงจบทันที

docker ps             # แสดงเฉพาะที่ "กำลังทำงาน" → ว่างเปล่า
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS

docker ps -a          # แสดงทั้งหมด รวมที่หยุดไปแล้ว
CONTAINER ID   IMAGE    COMMAND       CREATED          STATUS                     PORTS
45aacca36850   ubuntu   "/bin/bash"   43 seconds ago   Exited (0) 41 seconds ago
บทเรียนสำคัญ : container มีชีวิตอยู่ตราบเท่าที่ process หลักในนั้นยังทำงาน
พอ /bin/bash จบ container ก็ Exited (0) ทันที — ไม่ใช่ว่ามัน "พัง" แต่มัน "ทำงานเสร็จแล้ว"
เลข (0) คือ exit code — 0 = จบปกติ, ตัวเลขอื่นคือจบด้วยข้อผิดพลาด

5 คำสั่งที่ทำให้เกิดภาพเมื่อกี้

docker run -p 80:5000   myname/simple-webapp   # -> webapp  172.17.0.2 : 5000
docker run -p 8000:5000 myname/simple-webapp   # -> webapp  172.17.0.3 : 5000

อ่านเลขสองฝั่งของ -p ตามแนวตั้ง — ฝั่งซ้าย ไม่ซ้ำกันเลยสักตัว ส่วนฝั่งขวา ซ้ำได้ นั่นคือกฎทั้งหมด

สั่ง -p 8306:3306 ซ้ำอีกครั้ง จะไม่ได้ container ตัวที่ 3 แต่ได้ error
Bind for 0.0.0.0:8306 failed: port is already allocated

ทำไม container port ซ้ำได้

เพราะแต่ละ container มี network stack ของตัวเอง — port 5000 ของกล่องหนึ่ง ไม่ใช่ port 5000 ของอีกกล่อง

อ่าน Dockerfile ทีละบรรทัด

FROM node:current-slim          # 1. เลือก base image (Node.js รุ่นเล็ก)

WORKDIR /usr/src/app            # 2. กำหนด working directory ในกล่อง

COPY package.json .             # 3. คัดลอกเฉพาะ package.json เข้ามาก่อน
RUN npm install                 # 4. ติดตั้ง dependencies

EXPOSE 8080                     # 5. ประกาศว่า container ฟังที่ port 8080
CMD [ "npm", "start" ]          # 6. คำสั่งที่รันเมื่อ container เริ่มทำงาน

COPY . .                        # 7. คัดลอกซอร์สโค้ดที่เหลือทั้งหมด
EXPOSE ไม่ได้เปิด port ให้จริง — เป็นเพียงการ "ประกาศเจตนา" ว่าแอปในกล่องฟังที่ port ไหน การเปิดจริงต้องใช้ -p ตอน docker run
ข้อสังเกต : ไฟล์นี้วาง COPY . . ไว้หลัง CMD ซึ่งยังทำงานได้ปกติ (เพราะ CMD เป็นแค่การประกาศ ไม่ใช่การรันตอน build) แต่ตามธรรมเนียมที่ดีควรวางไว้ก่อน EXPOSE/CMD

docker logs bb         # ดู log ของ container ชื่อ bb
docker logs -f bb      # ตามดู log แบบ real-time
docker exec -it bb sh  # เข้าไปใน shell ของ container
docker stop bb         # หยุด container
docker rm bb           # ลบ container

LAB 5 — สร้าง image ของตัวเอง

docker build -t bulletinboard:1.0 .
# สร้าง image จาก Dockerfile
# จุดท้ายสุด = โฟลเดอร์ปัจจุบัน

docker run -p 8085:8080 -d \
  --name bb bulletinboard:1.0
# รัน container จาก image ที่เพิ่งสร้าง
# --name ตั้งชื่อไว้เรียกใช้ง่าย

ดูแล container ที่รันอยู่

docker logs bb       # ดู log
docker logs -f bb    # ตามดูสด ๆ
docker exec -it bb sh
# เข้าไปใน shell ของกล่อง

docker stop bb       # หยุด
docker rm bb         # ลบ container
docker rmi bulletinboard:1.0
# ลบ image

ล้างระบบทั้งหมด

ใช้เมื่อต้องการเคลียร์เครื่องเรียนให้กลับมาสะอาด
⚠ คำเตือน : ชุดคำสั่งนี้ลบ ทุกอย่าง ทั้ง container, image, volume และ network ที่ไม่ได้ใช้ — ข้อมูลใน volume จะหายถาวร 
docker stop $(docker ps -a -q)            # หยุด container ทั้งหมด
docker rm   $(docker ps -a -q)            # ลบ container ทั้งหมด
docker rmi  $(docker images -q)           # ลบ image ทั้งหมด
docker volume rm $(docker volume ls -q)   # ลบ volume ทั้งหมด
docker network prune -f                   # ลบ network ที่ไม่ได้ใช้
รูปแบบ $(...) คือการเอาผลลัพธ์ของคำสั่งข้างในมาเป็น argument — -q หมายถึงให้แสดงเฉพาะ ID

Checklist สำหรับผู้เรียน

ทบทวนว่าทำได้ครบทุกข้อหรือยัง
  • อธิบายได้ว่า "The Matrix from Hell" คือปัญหาอะไร และ Docker แก้อย่างไร
  • บอกความต่างระหว่าง Container กับ Virtual Machine ได้ (size, boot, kernel)
  • แยกแยะ Image กับ Container ได้
  • ติดตั้ง Docker บน Ubuntu และตรวจด้วย docker --version ได้
  • อธิบายได้ว่าทำไม docker run ubuntu ถึง Exited ทันที
  • ทำ Port Mapping ให้เข้าถึง Nginx จากเบราว์เซอร์ได้ (LAB 3)
  • ทำ Volume Mapping ให้แก้ไฟล์บน host แล้วเว็บเปลี่ยนทันทีได้ (LAB 4)
  • เขียน / อ่าน Dockerfile และ docker build เป็น image ของตัวเองได้ (LAB 5)
  • เปิด firewall rule บน cloud ให้เข้าถึงจากภายนอกได้
  • ใช้ docker logs และ docker exec ตรวจปัญหาเบื้องต้นได้
