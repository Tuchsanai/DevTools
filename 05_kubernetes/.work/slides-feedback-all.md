# feedback จาก yolo1 เรื่องสไลด์ (2026-09-02) — ใช้กับทั้ง 3 ไฟล์

ตรวจหน้าหลังรอบแก้ของ cyolo1 แล้ว: command/Expected output อ่านออกดีขึ้นมาก แต่ยังมีปัญหาเชิงเลย์เอาต์ที่ต้องแก้ทุกหน้าที่เข้าข่าย:

1. **หน้า "ประกอบระบบ — อ่าน topology ก่อนรัน" (และหน้าอื่นที่วางไดอะแกรมคู่กับกล่องโค้ด)** — ไดอะแกรมถูกย่อจนตัวอักษรภายในเล็กกว่า 10px และพื้นที่ล่างของสไลด์ว่าง ~40%
   → แยกเป็น 2 หน้า: (ก) หน้าไดอะแกรมเต็มความกว้าง ให้ภาพสูงอย่างน้อย 70% ของพื้นที่ใต้หัวเรื่อง (`.fig` กว้าง ~1180px จัดกึ่งกลาง) (ข) หน้าคำสั่ง + Expected output ตามเดิม
   หรือถ้าต้องอยู่หน้าเดียว: ไดอะแกรมต้องกว้าง ≥ 760px และโค้ดใช้คอลัมน์ขวาแคบ ห้ามเหลือพื้นที่ว่างเกิน 15% ของหน้า
2. **หน้าไดอะแกรมทฤษฎี ("โมเดลทางเทคนิค")** — บางหน้าไดอะแกรมสูงเพียง ~45% ของสไลด์และมีคำอธิบายด้านขวาเล็ก → ขยายภาพให้เต็มความสูงที่มี วางคำอธิบาย 2-3 บรรทัดใต้ภาพ (ตัวอักษร ≥ 20px)
3. **screenshot หน้าเว็บ** — เมื่อวาง 3 ภาพเรียงกัน ตัวอักษรบนการ์ดสถานะอ่านไม่ออก → วาง 1 ภาพต่อหน้าหรือ 2 ภาพ (ก่อน/หลัง) และ crop ให้เห็นการ์ดสถานะชัด (ใช้ `--selector` ของ shot.js หรือ crop ภาพเฉพาะส่วนบน 1280×260) เมื่อจุดประสงค์คือ "ชื่อ Pod เปลี่ยน"
4. **จำนวนหน้า** อาจเพิ่มได้ถึง 90 หน้าตาม spec (ปัจจุบัน 65) — เพิ่มหน้าได้ตามข้อ 1-3 อย่ายัดให้พอดี 65
5. **การนำทาง/เทคนิค** ต้องยังผ่าน check-slides.js หลังแก้ (ไม่มีภาพแตก ไม่มี external ref ปุ่มลัดครบ ขนาด ≤ 15 MB)
6. ครั้งที่ 3: คำสั่ง `curl` ในเครื่องเรียนต้องชี้ `http://localhost/…` (port 80) ไม่ใช่ :8080 (พบ 3 จุด)

## รอบ 3 (หลังดูผลรอบ 2 ของครั้งที่ 2)
7. **screenshot ที่ครอปแล้วยังติดขอบ sidebar สีเข้มพร้อมก้อนสีขาว (เมนูที่ active) ทางซ้าย** — ดูเป็นภาพตัดผิด → ครอปใหม่จากไฟล์ต้นฉบับใน images/ โดยเริ่มที่ขอบซ้ายของพื้นที่เนื้อหาหลัก (x ≈ 264 px จากซ้ายของภาพ 1280 px) ไปถึงขอบขวา และสูงเท่าที่ต้องการ (การ์ดสถานะ + หัวข้อ ≈ 260-420 px) · ใส่เงา/กรอบบางตามคลาส .fig.shot ของต้นแบบ · ทำกับทุกหน้าที่ใช้ภาพครอป
8. หน้า topology เต็มความกว้าง: ถ้าตัวอักษรในไดอะแกรมยังเล็กกว่า 14px ให้ครอปพื้นที่ว่างรอบภาพ (ตัดขอบขาวของ SVG ด้วย viewBox หรือ padding ติดลบ) เพื่อให้ภาพขยายเต็มพื้นที่
