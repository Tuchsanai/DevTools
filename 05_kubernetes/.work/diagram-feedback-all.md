# feedback จาก yolo1 เรื่องไดอะแกรม (2026-09-02) — ใช้กับทั้ง 45 ภาพ ทุกครั้ง

ผู้สอนดูภาพ `lab007-architecture.svg` แล้วชี้ว่า "ตำแหน่งเส้นที่ลากระหว่างกล่องไม่เหมาะสม ปกติไม่ค่อยมีใครวาดแบบนี้"
yolo1 ตรวจแล้วพบว่าเป็นปัญหาเชิงระบบของวิธีวาง element ไม่ใช่ภาพเดียว จึงกำหนด **กติกาเลย์เอาต์บังคับ** ด้านล่าง
ภาพใดไม่ผ่านกติกานี้ให้ **วาดใหม่ทั้งภาพ** (สร้าง element ใหม่จากพิกัดที่คำนวณบน grid) ไม่ใช่ขยับทีละนิด

## กติกาเลย์เอาต์บังคับ (ทุกภาพ)

1. **Grid** — วาง element ทุกตัวบน grid 40px · กล่องชนิดเดียวกันขนาดเท่ากันทั้งภาพ (เช่น Pod 200×110 · Service 220×90 · Deployment/RS 240×90)
   · กล่องในแถวเดียวกันมี y เท่ากันและระยะห่างเท่ากัน · กล่องแม่อยู่ **กึ่งกลาง** เหนือกลุ่มลูกเสมอ
2. **เส้นเชื่อมออกจากกึ่งกลางขอบ และตั้งฉากกับขอบ** — จุดเริ่ม = กึ่งกลางขอบล่าง/ขวา/บน/ซ้ายของกล่องต้นทาง · จุดจบ = กึ่งกลางขอบของกล่องปลายทาง
   · **ห้าม** ออกจากมุมกล่อง · ห้ามเข้ากล่องแบบเฉียง · ผูก `startBinding`/`endBinding` กับ element จริงเสมอ
3. **เส้นตรงหรือเส้นหักฉาก (orthogonal) เท่านั้น** — ไม่ใช้เส้นเฉียง ยกเว้นภาพทฤษฎีที่จงใจวาดเป็นวงกลม/ลูป
   · เส้นหักฉากมีจุดหักไม่เกิน 2 จุด · เส้นไม่พาดผ่านกล่องหรือข้อความอื่น · เส้นสองเส้นไม่ทับกัน ไม่ไขว้กันโดยไม่จำเป็น
4. **ความสัมพันธ์ 1 → N (Deployment→RS · RS→Pod · Service→Pod)** เลือกอย่างใดอย่างหนึ่ง:
   (ก) **ผังต้นไม้แบบ bus**: เส้นตั้งจากกึ่งกลางขอบล่างของแม่ ลงมาถึง "เส้นแนวนอน" (bus) ที่กว้างเท่ากลุ่มลูก แล้วเส้นตั้งแยกลงกึ่งกลางขอบบนของลูกแต่ละตัว
   (ข) **ชี้ไปที่กล่องกลุ่ม**: วาดกรอบกลุ่ม (เช่น "Pods · selector app=web") ล้อมลูกทั้งหมด แล้วลากเส้นเดียวจากแม่ไปกึ่งกลางขอบของกรอบกลุ่ม
   · **ห้าม** ลากเส้นเฉียงหลายเส้นกางออกจากจุดเดียว (fan)
5. **ทิศทางของเรื่อง** — traffic (Browser → Ingress → Service → Pod) วิ่ง **ซ้าย→ขวา บนแถวเดียว** · ownership (Deployment → RS → Pod) วิ่ง **บน→ล่าง** โดยให้ Pod อยู่แถวล่างสุดที่ทั้งสองแกนมาบรรจบ
   · ถ้า Service ต้องชี้ไปที่กลุ่ม Pod ให้ Service อยู่ **ซ้ายของกลุ่ม Pod ในแถวเดียวกัน** แล้วลากเส้นตรงแนวนอนเข้าที่กึ่งกลางขอบซ้ายของกรอบกลุ่ม (ไม่อ้อมขึ้น/ลง)
6. **ระยะ** — ระยะระหว่างกล่องที่มีเส้นเชื่อม ≥ 80px (เห็นหัวลูกศรชัด) · ระยะกล่องกับขอบโซน ≥ 40px · ชื่อโซน (namespace/node/selector) อยู่ **ในโซน มุมซ้ายบน** เยื้องจากขอบ 16px ไม่ทับเส้นประ
7. **ตัวอักษร** — ข้อความในกล่องจัดกึ่งกลางทั้งแนวตั้งและแนวนอน ไม่เกิน 3 บรรทัด · ป้ายกำกับเส้น (label) วางขนานเส้น ห่างจากเส้น 8px ไม่ทับเส้น · ขนาด ≥ 20px · ชื่อภาพบนสุด คำอธิบายใต้ชื่อ 1 บรรทัด
8. **เส้น** — ความหนา 2px (เส้นหลัก) / 1.5px เส้นประโซน · สีเส้นตัดกับพื้น · หัวลูกศรขนาดเดียวกันทั้งภาพ
9. **พื้นที่** — ภาพกว้าง 1400-1600 สูง 750-900 ใช้พื้นที่เต็มพอดี ไม่มีพื้นที่ว่าง > 20% ของภาพ (ปรับขนาดกล่อง/ระยะให้พอดี ไม่ใช่ปล่อยว่าง)
10. **หลังวาดใหม่** render ด้วย shot.js แล้ว **เปิดดูภาพจริง** ไล่ตามข้อ 1-9 ทีละข้อ ก่อน export ทับ

## ปัญหารายภาพที่ yolo1 เห็นแล้ว (ต้องแก้แน่นอน — นอกจากนี้ให้ตรวจภาพอื่นด้วยกติกาเดียวกัน)

### ครั้งที่ 1
- lab007-architecture — เส้น Service→กลุ่ม Pod ออกจากมุมซ้ายล่างของ Service แล้วอ้อมลงแตะมุมกรอบ selector (ผิดข้อ 2, 5) · Deployment→RS และ RS→Pod เป็น fan เส้นเฉียงจากจุดเดียว (ผิดข้อ 3, 4) · Deployment ไม่กึ่งกลางเหนือ RS ทั้งสอง · RS-new ไม่กึ่งกลางเหนือ Pod (ผิดข้อ 1) · Browser→Ingress เดินเส้นหักขึ้นแปลก ๆ → **วาดใหม่ทั้งภาพ**: แถวบน Deployment กึ่งกลาง · แถวกลาง RS-old / RS-new · แถวล่าง กรอบกลุ่ม "Pods · app=web" มี Pod 3 ตัว · Browser → Ingress → Service อยู่แถวเดียวกับกรอบกลุ่ม Pod ทางซ้าย
- lab006-architecture — เส้น traffic (เขียว) จาก Service พาดผ่านเส้น owner (น้ำเงิน) และหัวลูกศรชนข้อความ "selector: app=web" (ผิดข้อ 3, 7) · RS→Pod เป็น fan (ผิดข้อ 4) → วาดใหม่แบบเดียวกับ lab007 (แต่ไม่มี Deployment)
- lab005-architecture — Pod web-b กับ web-c วางเยื้องกันโดยไม่มีเหตุผล (ผิดข้อ 1) · เส้นจาก "kubectl get pods -l" จบที่ขอบ namespace ไม่ใช่ที่กรอบ selector (ผิดข้อ 2) · พื้นที่ว่างในโซน namespace มาก (ผิดข้อ 9) → จัด Pod 3 ตัวแถวเดียว (web-a v1 อยู่นอกกรอบ selector แต่แถวเดียวกัน) เส้นเข้าที่กึ่งกลางขอบซ้ายของกรอบ selector
- lab004-architecture — เส้น API server→Pod หักฉาก 2 ครั้งทั้งที่วาง Pod ให้อยู่แถวเดียวกันได้ (ผิดข้อ 3) · ตัวเชื่อม "◇" ระหว่าง desired/actual ไม่สื่อความ ให้ใช้ลูกศรสองหัวพร้อมป้าย "เทียบ" · Browser ควรอยู่ขวาสุดแถวเดียวกับ Pod และลูกศรตรงแนวนอน
- lab003-architecture — ผ่านเกือบหมด แต่ระยะ Pod web ↔ Pod web2 ↔ web-broken ไม่เท่ากัน และ web-broken ชิดขอบโซน (ข้อ 1, 6)
- ภาพทฤษฎี d01-d08 ครั้งที่ 1: ตรวจด้วยกติกาเดียวกัน (d02, d04 ที่ yolo1 ดูแล้วผ่าน)
