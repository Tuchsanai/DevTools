## 2. ไม่ใช้

**คำสั่งหรือ option ที่ไม่ใช่คำสั่งหลัก** เพราะทำให้นักศึกษาหลุดโฟกัสและงง เช่น

- ตารางอธิบาย YAML ทีละ field → ให้ comment ในไฟล์ YAML อธิบายแทน
- ส่วน Troubleshooting และ Checklist ส่งงาน

option พื้นฐานที่ใช้ได้: `-f`, `-o wide`, `-o yaml`, `-A`, `-l`, `--show-labels`, `-c`, `-it`

## 5. หน้าตาของแต่ละขั้น

ตัวอย่าง 1 ขั้น:

````markdown
### ขั้นที่ 1: สร้าง Pod

```bash
kubectl apply -f labs/lab02-first-yaml/nginx-pod.yaml
```

**Expected output**

<pre>
pod/web created
</pre>

รอสัก 10 วินาที แล้วดูสถานะ

```bash
kubectl get pods
```

**Expected output**

<pre>
NAME   READY   STATUS    RESTARTS   AGE
web    1/1     Running   0          11s
</pre>

`1/1 Running` แปลว่า Pod พร้อมใช้งานแล้ว
````

กติกา:

- **คำสั่ง** ใช้ ` ```bash ` (มีปุ่ม copy) 1 block ต่อ 1 คำสั่ง
- **ผลลัพธ์** ขึ้นหัว `**Expected output**` แล้วใช้ `<pre>` (ไม่มีปุ่ม copy จะได้ไม่สับสน)
  - ใน `<pre>` เขียน `<` `>` เป็น `&lt;` `&gt;`
  - ผลยาวให้ตัดด้วย `...` และบอกว่า "(ตัดเฉพาะส่วนสำคัญ)"
- YAML แสดงเฉพาะส่วนที่เกี่ยวกับขั้นนั้น
- จบทุก LAB ด้วย **ลบ Pod**, **สิ่งที่เห็น** (3–4 ข้อ) และคำถามชวนคิด 1 ข้อ

## 6. สรุปคำสั่งท้ายบท

ทุกบทจบด้วยหัวข้อ **สรุปคำสั่ง kubectl ในบทนี้** รวมทุกคำสั่งที่ใช้ในบท แบ่งเป็นกลุ่ม ตารางละ 2 คอลัมน์ ใช้ `<ชื่อ>` แทนชื่อเฉพาะ ตัวอย่าง:

**สร้าง / ลบ**

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `kubectl apply -f <ไฟล์>` | สร้าง/อัปเดตตามไฟล์ YAML |
| `kubectl delete -f <ไฟล์>` | ลบทุกอย่างที่อยู่ในไฟล์ |

**ดูสถานะ**

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `kubectl get pods` | รายการ Pod |
| `kubectl describe pod <ชื่อ>` | รายละเอียด + Events |

กลุ่มอื่นที่ใช้ได้ตามเนื้อหาของบท เช่น เข้าไปใน Pod / ดู log, แก้ object ที่รันอยู่, คลัสเตอร์และ image
