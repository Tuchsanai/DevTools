## 1. หลักการ

- **เขียนให้นักศึกษาอ่าน ไม่ใช่เขียนเป็นตำรา** อ่านแล้วต้องเข้าใจโดยไม่ต้องเปิดเอกสารอื่น
- **อิง LAB เป็นหลัก** สอนเฉพาะสิ่งที่นักศึกษาจะเจอใน LAB ของบทนั้น เรื่องที่ LAB ไม่ใช้ให้ตัดออกหรือพูดถึงแค่ 1 ประโยค
- **1 หัวข้อ = 1 ความคิด** เริ่มจากภาพ → อธิบาย 2–4 บรรทัด → ตัวอย่าง YAML หรือผลจริงจาก LAB
- **ใช้ภาษาพูดง่าย ๆ** และอุปมาท่าเรือกับน้องส้มตลอดบท ศัพท์อังกฤษใช้ได้ แต่ต้องแปลเป็นไทยง่าย ๆ ครั้งแรกที่เจอ
- **ตัวอักษรน้อย** ใช้ bullet แทนย่อหน้ายาว ย่อหน้าหนึ่งไม่เกิน 3–4 บรรทัด

---

## 2. ไม่ใช้

- บทคัดย่อ, วัตถุประสงค์การเรียนรู้แบบยาว, สารบัญรูปภาพ, เลข "ตารางที่ N" / "รูปที่ N"
- **ตารางเกินจำเป็น** ทั้งบทควรมีไม่เกิน ~6 ตาราง ใช้ตารางเฉพาะเมื่อเปรียบเทียบหลายสิ่งในหลายมิติ (เช่น restartPolicy, STATUS → สาเหตุ) นอกนั้นใช้ bullet
- รายละเอียดเชิงลึกที่ LAB ไม่ใช้ (เช่น CNI, CRI, pause container, grpc probe, set-based selector, QoS ทุกเงื่อนไข) → ตัด หรือพูดถึง 1 ประโยค
- คำสั่งที่ซับซ้อนในตัวอย่าง: `-o jsonpath`, ต่อท่อด้วย `grep` / `sed` / `head`, `&&`
- ผลลัพธ์ที่ไม่ได้มาจากการรันจริง หรืออ้าง LAB / ไฟล์ที่ไม่มีอยู่แล้ว
- รายการเอกสารอ้างอิงยาว → ใส่ลิงก์ Kubernetes Docs แบบรวบ 3–4 บรรทัดพอ

## 3. โครงเอกสาร

1. **หัวเรื่อง** `# บทที่ N: <เรื่อง> — <ชื่อเล่นของบท>` + 2 บรรทัดข้อมูล (รายวิชา · CLO, ลิงก์บทก่อนหน้า · LAB ของบท)
2. **"อ่านบทนี้จบแล้วควรทำได้"** 3–4 ข้อสั้น ๆ
3. **สารบัญ** (เฉพาะหัวข้อหลัก ไม่มีสารบัญรูปภาพ)
4. **1. เริ่มเรื่อง** น้องส้มเจอปัญหาอะไร + ทบทวนอุปมาท่าเรือเป็น bullet + ขอบเขตบท (1 บรรทัด)
5. **หัวข้อเนื้อหา** เรียงตามลำดับที่ LAB ใช้ (แนวคิด → YAML → คำสั่ง → ปัญหาที่เจอบ่อย)
6. **หัวข้อ YAML แบบละเอียด** (ดูข้อ 5) ทุกบทที่มีไฟล์ YAML ใหม่
7. **ปูทางบทถัดไป** ปัญหาที่เจอในบทนี้ → เครื่องมือในบทหน้า (bullet 3–5 ข้อ)
8. **สรุปและคำถามทบทวน** (ดูข้อ 7)
9. **เอกสารอ้างอิง** แบบรวบ + หมายเหตุภาพ AI 1 บรรทัด

## 4. หน้าตาของแต่ละหัวข้อ

````markdown
## 3. Pod อยู่ที่ไหน และคุยกันอย่างไร

<p align="center">
  <img src="images/06-pod-shared-network-localhost.png" alt="เครือข่ายร่วมภายใน Pod และ localhost" width="800">
</p>

container ใน Pod เดียวกันใช้เครือข่ายเดียวกัน เหมือนโปรแกรมหลายตัวในคอมเครื่องเดียว

- เรียกกันด้วย `localhost:<port>` ได้เลย
- **ห้ามฟัง port ซ้ำกัน**

ตัวอย่างจริงใน LAB 8:

```yaml
- name: DATABASE_URL
  value: postgres://som:meow1234@localhost:5432/catshop   # db อยู่ Pod เดียวกัน จึงใช้ localhost
```
````

กติกา:

- **ภาพมาก่อน** แล้วตามด้วยคำอธิบาย ภาพไม่ต้องมี caption (ใช้ `alt` อย่างเดียว) กว้าง `800`
- **หัวข้อย่อย** ใช้ `###` ตั้งชื่อเป็นคำถามหรือประโยคสั้น เช่น "ทำไม db ต้องเป็น sidecar?"
- **ผลลัพธ์จริง** ใช้ ` ```text ` ตัดให้สั้นเหลือเฉพาะบรรทัดที่สอนเรื่องนั้น และบอกว่ามาจาก LAB ไหน
- **กล่องเน้น** ใช้ `>` เฉพาะ 3 แบบ: **เคล็ดลับ**, **⚠️ กับดัก/ความปลอดภัย**, **ประโยคเดียวที่ต้องจำ** ไม่เกิน 1 กล่องต่อหัวข้อ
- อ้างอิง LAB ด้วยเลข LAB ปัจจุบันเสมอ (เช่น "LAB 6") ตรวจทุกครั้งที่ LAB เปลี่ยนเลข

## 5. สอน YAML แบบละเอียด (หัวใจของทุกบท)

นักศึกษาไม่ได้เขียน YAML เอง แต่ต้อง **อ่านออกทุกบรรทัด** สอนตามลำดับนี้

1. **พื้นฐาน YAML** (สอนเต็มในบท 002 บทถัดไปทบทวนสั้น ๆ แล้วลิงก์กลับ)
   - YAML มีแค่ 3 แบบ: ค่าเดี่ยว `key: value`, map (เยื้องเข้า), list (`- `)
   - **list ของ map** เน้นว่า "ขีด 1 อัน = 1 ชิ้น"
   - **การเยื้อง = ใครเป็นลูกใคร** (เยื้องเข้า = ลูก, เยื้องเท่ากัน = พี่น้อง)
   - ทางลัด `[ ]` `{ }` เทียบกับแบบหลายบรรทัด
   - ผิดบ่อยแก้ง่าย + วิธีอ่าน error จาก kube-apiserver
2. **อ่านไฟล์แรกของบททีละบรรทัด** ใช้ไฟล์จริงจาก `02_LAB/labs/...` แล้ว
   - ตาราง 2 คอลัมน์ "บรรทัด | ความหมาย" (ตารางเดียวที่อนุญาตให้อธิบาย YAML ทีละ field)
   - ปิดด้วย **แปลทั้งไฟล์เป็นประโยคเดียว** เช่น "ขอ Pod ชื่อ `web` ... ฟัง port 80"
3. **field ใหม่ของบท** แต่ละ field แสดง snippet สั้น ๆ พร้อม comment ท้ายบรรทัด (`# ...`) อธิบายเป็นภาษาไทย
4. **ไฟล์ใหญ่ของบท** (เช่น `som-shop-pod.yaml`)
   - เริ่มจาก **โครง (skeleton)** ที่พับเหลือแค่ key หลัก + comment บอกหน้าที่
   - แล้วเปิดดูทีละส่วน ชี้กลับว่า field ไหนเรียนในหัวข้อใด (`# ← หัวข้อ 7.2`)
   - มีภาพโครงไฟล์ประกอบ 1 ภาพ

YAML ที่ยกมาต้อง **ตรงกับไฟล์จริงใน LAB** (ตัดได้ด้วย `...` แต่ห้ามแก้ค่า)

## 6. รูปภาพ

- **ภาพแนวคิด** → image gen ผ่าน cyolo (Codex) สไตล์การ์ตูน flat vector มีน้องส้ม แนบ `images/00-character-som.png` เป็นภาพอ้างอิงทุกครั้ง
- อุปมาคงที่ทั้งชุด: container = ตู้สินค้า, Pod = กล่องห่อตู้สีเขียวอมฟ้ามีป้าย IP, Node = เรือ, Control Plane = หอบังคับการ
- ข้อความในภาพ **สั้นและสะกดถูก** ระบุคำตรงตัวใน prompt ห้ามมีวัตถุหรือคำของบทถัดไป
- **ทุกหัวข้อหลักมีภาพ 1 ภาพ** หัวข้อ YAML ควรมีภาพ map/list, ต้นไม้การเยื้อง และโครงไฟล์ใหญ่
- ตั้งชื่อ `NN-ชื่อภาษาอังกฤษ.png` เก็บ prompt ใน `images/imagegen-prompts.md` และลบรูปที่ไม่ใช้แล้ว
- ตรวจภาพทุกภาพด้วยตาก่อนใช้ (ตัวสะกด, น้องส้มมีตัวเดียว, ตรงกับเนื้อหา)

## 7. สรุปและคำถามทบทวน

- **สรุป** เป็นรายการเลข 8–10 ข้อ ข้อละ 1 บรรทัด
- **คำถามทบทวน** 8–10 ข้อ ผูกกับสิ่งที่เห็นใน LAB และต้องมีอย่างน้อย
  - 1 ข้อ **อ่าน YAML** (นับ container / บอกว่าบรรทัดนี้เป็นของใคร)
  - 1 ข้อ **หาจุดผิดใน YAML**
  - 1 ข้อ **อ่าน STATUS แล้วบอกสาเหตุ**
- แนวคำตอบซ่อนใน `<details><summary>แนวคำตอบ</summary> ... </details>` ตอบสั้น 1–3 บรรทัด
