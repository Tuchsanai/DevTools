🎯 สิ่งที่จะได้เรียนรู้

📦

git clone

ประตูทางเข้าที่สอง: ได้ไฟล์ + ประวัติทุก commit + การเชื่อมต่อ remote ฟรีในคำสั่งเดียว

🔖

origin/main

remote-tracking branch — "บุ๊กมาร์ก" ที่ทำให้ git status รู้ว่าเรา ahead/behind

🧭

อ่าน ahead / behind

อ่านสถานะให้ออก — และรู้ว่ามันเทียบกับบุ๊กมาร์ก ไม่ใช่ GitHub สด ๆ

📥

git fetch

ดึงของใหม่มาเก็บไว้ก่อน โดยไม่แตะไฟล์ที่กำลังทำงาน — ปลอดภัยเสมอ

🧮

สูตร pull

git pull = git fetch + git merge — ลองแยกทีละท่อนก่อน แล้วค่อยใช้ท่ารวบ

👀

โบนัส: detached HEAD

แอบดูของที่ fetch มาด้วย git checkout origin/main แบบไม่ต้องตกใจ

📦 ทฤษฎี ① — git clone: ประตูทางเข้าที่สอง

อ้างอิงสไลด์ 02_GIT.pdf หน้า 5–7, 47, 50–52

การพาโปรเจกต์มาเจอกับ GitHub มี 2 เส้นทาง:

💻
เส้นทาง A (LAB 01) — local เกิดก่อน
git init → branch: master
→remote add · branch -M main · push -u
☁️
GitHub
branch: main
☁️
เส้นทาง B (LAB นี้) — GitHub เกิดก่อน
Create repo + README → branch: main
→git clone — คำสั่งเดียวจบ ✓
💻
เครื่องเรา
ได้ branch: main ติดมาเลย

git clone <URL> ให้เราแบบครบเซ็ต:

  • ดาวน์โหลดทุกไฟล์ + ประวัติทุก commit ของ repo ณ ขณะนั้น (ไม่ใช่แค่ไฟล์เวอร์ชันล่าสุด)
  • ตั้ง remote origin ให้อัตโนมัติ — ไม่ต้อง git remote add
  • ได้ branch ชื่อ main ตามต้นทาง — ปัญหา Improper Reference (master ชน main, สไลด์หน้า 46) ไม่เกิดเลยในเส้นทางนี้ (สไลด์หน้า 47)
  • ผูก upstream ให้เสร็จ — git push / git pull ได้ทันทีโดยไม่ต้องใส่ -u
4

🔖 ทฤษฎี ② — origin/main: บุ๊กมาร์กที่เลื่อนเองไม่ได้

อ้างอิงสไลด์ 02_GIT.pdf หน้า 53–59

หลัง clone เครื่องเราจะมีตัวชี้ 2 ตัว ที่หน้าตาคล้ายกันแต่คนละหน้าที่:

ตัวชี้ชนิดใครขยับมัน
mainlocal branch ของเราเราขยับเอง — ขยับไปข้างหน้าทุกครั้งที่ commit
origin/mainremote-tracking branchเราขยับเองไม่ได้ — เป็นบุ๊กมาร์กจดว่า "เท่าที่รู้ล่าสุด main บน GitHub อยู่ตรงไหน" อัปเดตเฉพาะตอน sync (fetch / pull / push)
⬆️
commit ในเครื่อง 2 ครั้ง
main นำหน้า origin/main
→ status: "ahead by 2"
·คนละทิศ
⬇️
มีของใหม่บน GitHub
หลัง fetch: origin/main นำหน้า main
→ status: "behind by 2"
  • ดูบุ๊กมาร์กทั้งหมดที่เครื่องรู้จัก: git branch -r (สไลด์หน้า 55)
  • git status เทียบ main กับ origin/main แล้วรายงาน ahead (เรามีของที่ยังไม่ push) / behind (remote มีของที่เรายังไม่รับ) / up to date
⚠️ กับดักสำคัญ: git status ไม่ได้ต่อเน็ตไปถาม GitHub — มันเทียบกับบุ๊กมาร์กในเครื่องเท่านั้น ถ้าบุ๊กมาร์กเก่า (ยังไม่ fetch) มันจะตอบ up to date ทั้งที่ GitHub มีของใหม่แล้ว → เจอของจริงใน STEP 3

🔄 ทฤษฎี ③ — Fetch vs Pull: ดึงแบบระวัง vs ดึงแบบรวบรัด

อ้างอิงสไลด์ 02_GIT.pdf หน้า 63–76

การนำการเปลี่ยนแปลงจาก remote ลงมามี 2 วิธี (สไลด์หน้า 66):

☁️
Remote — GitHub
มี commit ใหม่
→git fetch
🔖
origin/main
บุ๊กมาร์กขยับ · เก็บใน .git
ยังไม่แตะไฟล์ที่ทำงานอยู่
→git merge origin/main
💻
main + ไฟล์จริง
ไฟล์บนโต๊ะทำงานอัปเดต
🧮 สูตรที่ต้องจำ (สไลด์หน้า 74): git pull = git fetch + git merge — ทีเดียวจบทั้งสองลูกศรบน
ประเด็นgit fetchgit pull
ดึงการเปลี่ยนแปลงจาก remote✅ ใช่✅ ใช่
อัปเดตบุ๊กมาร์ก origin/main✅ อัปเดต✅ อัปเดต
merge เข้า branch ปัจจุบัน + เปลี่ยนไฟล์จริง❌ ไม่ทำ✅ ทำให้อัตโนมัติ
โอกาสเกิด merge conflict❌ ไม่เกิด (ปลอดภัย)✅ อาจเกิดได้ — เจาะลึก Week 3
ความปลอดภัยทำได้ทุกเมื่อ — ตรวจก่อนค่อยตัดสินใจ merge เองสะดวก แต่ไม่แนะนำถ้ามีงานค้างยังไม่ commit
  • ระหว่างกลาง (fetch แล้วแต่ยังไม่ merge) ใช้ git log --oneline --all ดูได้ว่ามี commit ใหม่อะไรรออยู่ (สไลด์หน้า 63–64)
  • LAB นี้ทุก merge เป็นแบบ Fast-forward — เลื่อนตัวชี้ตามไปเฉย ๆ เพราะเราไม่มี commit สวนทาง · กรณีต่างคนต่างแก้จนชนกัน (merge conflict) เป็นเรื่องของ branch ใน Week 3

STEP 1 — clone ลงเครื่องแลป (uni-pc)

สมชายนั่งหน้าเครื่องแลป — ยกโปรเจกต์จาก GitHub ลงมาทั้งก้อนด้วยคำสั่งเดียว:

git clone https://YOUR_USERNAME:${GIT_TOKEN}@github.com/YOUR_USERNAME/lab-sync.git uni-pc
cd uni-pc
ls
Expected Output
Cloning into 'uni-pc'...
remote: Enumerating objects: 3, done.
remote: Counting objects: 100% (3/3), done.
remote: Total 3 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
Receiving objects: 100% (3/3), done.

README.md
📌 คำที่ต่อท้าย URL (uni-pc) = ชื่อโฟลเดอร์ปลายทาง (ถ้าไม่ใส่จะได้โฟลเดอร์ชื่อ lab-sync) · จำนวน objects/ความเร็ว ของแต่ละคนอาจต่างกันเล็กน้อย

สำรวจของแถมที่ clone ให้ฟรี — branch, บุ๊กมาร์ก และ remote:

git branch
git branch -r
git remote -v
Expected Output
* main

  origin/HEAD -> origin/main
  origin/main

origin	https://YOUR_USERNAME:${GIT_TOKEN}@github.com/YOUR_USERNAME/lab-sync.git (fetch)
origin	https://YOUR_USERNAME:${GIT_TOKEN}@github.com/YOUR_USERNAME/lab-sync.git (push)
📌 เทียบกับ LAB 01 ชัด ๆ: ไม่ต้อง git branch -M main (ได้ main ติดมาเลย — สไลด์หน้า 47) · ไม่ต้อง git remote add origin (ผูกให้แล้ว) · git branch -r โชว์บุ๊กมาร์กฝั่ง remote ที่เครื่องรู้จัก ส่วน origin/HEAD -> origin/main หมายถึง branch หลักของ remote คือ main
🔐 git remote -v โชว์ token เต็ม ๆ ใน URL — ระวังเวลาแชร์หน้าจอ/แคปภาพส่งรายงาน

ดูประวัติและสถานะ:

git log --oneline
git status
Expected Output

On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
📌 (HEAD -> main, origin/main, origin/HEAD) = ตอนนี้ main กับบุ๊กมาร์ก origin/main ชี้ commit เดียวกัน → git status จึงรายงาน up to date · hash ของแต่ละคนจะไม่เหมือนตัวอย่าง

STEP 3 — เช้าวันใหม่ที่แลป: git status โกหก?! → git fetch

เช้าวันอังคาร สมชายกลับมานั่งเครื่องแลป (uni-pc) — เครื่องนี้ยังไม่รู้อะไรเลยเกี่ยวกับงานเมื่อคืน ลองถามเข็มทิศดูก่อน:

cd ../uni-pc
git status
git log --oneline
Expected Output
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean

📋 สรุป + Cheat Sheet

คำสั่งทำอะไร
git clone <URL> [folder]ยก repo+ประวัติทั้งหมดลงเครื่อง พร้อมผูก origin/upstream ให้ฟรี
git branch -rดู remote-tracking branches (บุ๊กมาร์ก) ที่เครื่องรู้จัก
git statusรายงาน ahead/behind — เทียบกับบุ๊กมาร์ก ไม่ใช่ GitHub สด ๆ
git fetchอัปเดตบุ๊กมาร์ก origin/main — ไม่แตะไฟล์งาน ปลอดภัยเสมอ
git log --oneline --allส่องว่า origin/main ล้ำหน้า main อยู่กี่ commit หลัง fetch
git merge origin/mainนำของจากบุ๊กมาร์กเข้า branch เรา (LAB นี้เป็น Fast-forward)
git pullท่ารวบ = git fetch + git merge
git checkout origin/mainแอบดูสถานะที่บุ๊กมาร์ก (detached HEAD — ดูได้ กลับด้วย git checkout main)
🔁 วงจรทำงานหลายเครื่องที่ต้องจำ: นั่งลง → git pull → ทำงาน → git add → git commit → git push ก่อนลุก

✅ Checklist ก่อนไปต่อ

  • clone แล้ว git branch ตอบ * main และ git remote -v มี origin ครบ โดยไม่ได้ตั้งค่าเองสักคำสั่ง
  • เห็น git status ตอบ ahead of 'origin/main' by 2 commits ก่อน push (ฝั่ง home-laptop)
  • เห็น git status ตอบ up to date ทั้งที่ GitHub มีของใหม่ (ฝั่ง uni-pc ก่อน fetch) และอธิบายได้ว่าทำไม
  • หลัง git fetch: status เปลี่ยนเป็น behind by 2 แต่ ls ยังไม่เห็นไฟล์ใหม่
  • หลัง git merge origin/main: เห็น Fast-forward และไฟล์ใหม่โผล่ครบ
  • อ่าน output ของ git pull แล้วชี้ได้ว่าท่อนไหนคือ fetch ท่อนไหนคือ merge
  • git log --oneline ของทั้งสองโฟลเดอร์ และเลข Commits บนเว็บ GitHub ตรงกัน (5 commits)
