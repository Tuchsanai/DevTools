🌐 ทฤษฎี ① — Local ↔ Remote และชื่อ "origin"

อ้างอิงสไลด์ 02_GIT.pdf หน้า 38–42

💻
LOCAL — เครื่องเรา
lab-git/ (.git ครบทุก commit)
⇄git push ↗ · git pull ↙
☁️
REMOTE — GitHub
lab-git.git (สำเนาบน cloud)
  • remote = repository อีกก้อนที่อยู่บนเซิร์ฟเวอร์ เช่น GitHub, GitLab, Bitbucket
  • git remote -v (สไลด์หน้า 39) — ดูว่า repo เราเชื่อมกับ remote ไหนอยู่ · repo ที่ clone มาจะเห็น URL ทันที ส่วน repo ที่ git init เองจะว่างเปล่าจนกว่าจะ add
  • git remote add origin https://url.git (สไลด์หน้า 40) — ผูก remote พร้อมตั้งชื่อเรียกสั้น ๆ ว่า origin — เป็นธรรมเนียม ไม่ใช่คำสงวน จะตั้งชื่ออื่นก็ได้แต่แทบไม่มีใครทำ
  • เผื่ออนาคต (สไลด์หน้า 41): git remote rename <old> <new> · git remote remove <name>
  • ในแผนภาพมี git pull = ทิศตรงข้ามของ push คือดึงการเปลี่ยนแปลงจาก remote ลงเครื่อง (สไลด์หน้า 35–36) — LAB นี้โฟกัสขา push ส่วน pull ฝึกต่อในหัวข้อ Fetch vs Pull ของ Week 2
  • git push -u origin main (สไลด์หน้า 42) — push ครั้งแรกพร้อมตั้ง upstream (-u): จับคู่ branch ในเครื่องกับ branch บน remote → รอบถัดไป Git รู้เองว่าต้อง push ไปไหน

🌿 ทฤษฎี ② — master vs main: ปัญหาชนกันที่ต้องรู้ก่อน push

อ้างอิงสไลด์ 02_GIT.pdf หน้า 43–48

  • เดิม Git ตั้งชื่อ branch แรกว่า master — แต่ GitHub ประกาศเปลี่ยนธรรมเนียมชื่อ default branch เป็น main อย่างเป็นทางการ (สไลด์หน้า 43) repo ที่สร้างบนเว็บ GitHub ปัจจุบันจึงชื่อ main
  • แต่ git init ในเครื่องเรา (git 2.43 ใน container) ยังได้ master → เกิดสถานการณ์ Improper Reference (สไลด์หน้า 46): local กับ GitHub ถือ branch คนละชื่อ = คนละเส้น push/pull กันไม่เจอ

⇄✗git push · git pull ไม่เจอกัน

สองทางแก้

วิธีคำสั่งเหมาะกับ
เปลี่ยนชื่อ branch ปัจจุบันทันที (ใช้ใน LAB นี้)git branch -M mainrepo ที่ git init มาแล้วเป็น master — เป็นคำสั่งเดียวกับที่หน้า repo ใหม่บน GitHub แนะนำ (สไลด์หน้า 43)
ตั้งค่าถาวรทุก repo ใหม่git config --global init.defaultBranch mainตั้งครั้งเดียวจบ — repo ที่สร้างหลังจากนี้เป็น main ตั้งแต่เกิด (ทำแล้วใน LAB Configure Week 1)
📌 กรณี clone repo จาก GitHub ลงมา (สไลด์หน้า 47) จะไม่เจอปัญหานี้เลย — เพราะได้ branch main ติดมาตั้งแต่แรก · ปัญหาเกิดเฉพาะเส้นทาง "local folder เดิม → GitHub โดยไม่ได้ clone" (สไลด์หน้า 48) ซึ่งคือสิ่งที่เรากำลังทำใน LAB นี้พอดี

⚙️ เตรียมความพร้อม + Token

5.1 Container + ตัวตน

รัน container แล้ว SSH เข้าไป (password: passwd):

docker run -dit --name devtools --privileged -p 2222:22 tuchsanai/devtools:2569_1
ssh root@localhost -p 2222

ตั้งตัวตน — ใช้ชื่อและอีเมลของตัวเอง (ตัวอย่างทั้ง LAB ใช้ตัวตนสมมุติ):

git config --global user.name "somchai-dev"
git config --global user.email "somchai.dev@example.com"

5.2 Personal Access Token (PAT) ของตัวเอง

GitHub ไม่รับ password สำหรับ push แล้ว — ต้องใช้ token (วิธีสร้างอยู่ใน LAB ชุด token ของ Week 1: GitHub → Settings → Developer settings → Personal access tokens (classic) → เลือก scope repo)

export GIT_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx   # ← token ของตัวเอง
🔐 token = รหัสผ่าน — ห้ามส่งให้เพื่อน ห้าม commit ลงไฟล์ ห้ามแปะในรายงาน/สไลด์/แชท · เอกสารนี้จึงเขียนเป็นตัวแปร ${GIT_TOKEN} แทนค่าจริงเสมอ
🆕 GitHub ปัจจุบันมี token แบบใหม่ fine-grained (จำกัดสิทธิ์ราย repo ได้ละเอียดกว่า) ให้เลือกด้วย — ใน LAB นี้ใช้แบบ classic + scope repo ตามที่ฝึกใน Week 1 ก็เพียงพอ

STEP 1 — สร้าง local repo + commit แรก (ทบทวน LAB 00)

ขั้นนี้คือวงจรที่ฝึกมาแล้วทั้ง LAB 00 — รวดเดียวจบ:

mkdir lab-git
cd lab-git
git init
echo "Initial content for file 1" > file1.txt
echo "Initial content for file 2" > file2.txt
echo "Initial content for file 3" > file3.txt
git add file1.txt file2.txt file3.txt
git commit -m "Initial commit with three files"
git log --oneline
Expected Output (ย่อ)
[master (root-commit) 8f157da] Initial commit with three files
 3 files changed, 3 insertions(+)
 create mode 100644 file1.txt
 create mode 100644 file2.txt
 create mode 100644 file3.txt

8f157da Initial commit with three files
📌 hash ของแต่ละคนไม่เหมือนกัน — และสังเกตใน output: เรายังอยู่บน master ซึ่งกำลังจะเป็นปัญหาในขั้นถัดไป

STEP 2 — เปลี่ยน master → main (แก้ปัญหาจากทฤษฎี ②)

ดูชื่อ branch ปัจจุบัน → เปลี่ยนชื่อ → ตรวจซ้ำ:

git branch
git branch -M main
git branch
git status
Expected Output
* master

# (git branch -M main ไม่มี output — เงียบ = สำเร็จ)

* main

On branch main
nothing to commit, working tree clean
📌 -M = เปลี่ยนชื่อ branch (บังคับทับถ้าชื่อปลายทางมีอยู่แล้ว) — commit ทั้งหมดอยู่ครบ แค่ป้ายชื่อเปลี่ยน
💡 ถ้าเครื่องคุณตั้ง init.defaultBranch main ไว้จาก Week 1 — git branch จะตอบ * main ตั้งแต่แรก · สั่ง git branch -M main ซ้ำก็ไม่เสียหายอะไร

STEP 3 — สร้าง Remote Repository บน GitHub (ผ่านเว็บ)

  1. เข้า github.com → ปุ่ม New repository
  2. Repository name: lab-git
  3. เลือก Private
  4. ไม่ต้องติ๊ก "Add a README file" และไม่เลือก .gitignore / license ใด ๆ
  5. กด Create repository — จะเจอหน้า quick setup พร้อมชุดคำสั่งแนะนำ
🆕 สังเกตบล็อก "…or push an existing repository from the command line" บนหน้า quick setup — คือชุดคำสั่งเดียวกับที่เรากำลังทำเป๊ะ ๆ: git remote add origin … → git branch -M main (STEP 2 ของเรา) → git push -u origin main — จบ LAB นี้แล้วคุณจะอ่านหน้านั้นออกทั้งหมด
⚠️ ทำไมห้ามติ๊ก "Add a README file"? — เพราะเราจะ push ประวัติจาก local ขึ้นไปเอง ถ้าให้ GitHub สร้าง commit แรก (README) ไว้ก่อน remote จะมีประวัติที่ local ไม่มี → push ครั้งแรกจะโดน ! [rejected] ทันที

STEP 4 — เชื่อม local เข้ากับ remote

ก่อนเชื่อม — พิสูจน์ว่า repo ที่ git init เองยังไม่รู้จัก remote ใดเลย (ตรงตามทฤษฎี ①):

git remote -v
Expected Output
# (ว่างเปล่า — ไม่มี output ใด ๆ)

ผูก remote ชื่อ origin — ฝัง token ไว้ใน URL เพื่อให้ push ได้โดยไม่ต้องกรอกรหัสทุกครั้ง (แทน YOUR_USERNAME ด้วย username GitHub ของตัวเอง) แล้วตรวจซ้ำ:

git remote add origin https://YOUR_USERNAME:${GIT_TOKEN}@github.com/YOUR_USERNAME/lab-git.git
git remote -v
Expected Output
origin	https://YOUR_USERNAME:${GIT_TOKEN}@github.com/YOUR_USERNAME/lab-git.git (fetch)
origin	https://YOUR_USERNAME:${GIT_TOKEN}@github.com/YOUR_USERNAME/lab-git.git (push)
🔐 ในเครื่องจริง git remote -v จะโชว์ token จริงของคุณเต็ม ๆ ใน URL — ระวังเวลาแชร์หน้าจอหรือแคปภาพส่งรายงาน

STEP 5 — Push ครั้งแรก (-u = ตั้ง upstream)

git push -u origin main
Expected Output
Enumerating objects: 5, done.
Counting objects: 100% (5/5), done.
Delta compression using up to 32 threads
Compressing objects: 100% (2/2), done.
Writing objects: 100% (5/5), 379 bytes | 379.00 KiB/s, done.
Total 5 (delta 0), reused 0 (delta 0), pack-reused 0
To https://github.com/YOUR_USERNAME/lab-git.git

📌 บรรทัดสำคัญ: * [new branch] main -> main = สร้าง branch main บน GitHub สำเร็จ · branch 'main' set up to track 'origin/main' = ผลของ -u · ส่วนจำนวน threads / ความเร็ว KiB/s ขึ้นกับเครื่องแต่ละคน
git status
Expected Output
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean

สังเกตบรรทัดใหม่: Your branch is up to date with 'origin/main'. — เพราะมี upstream แล้ว git status จึงรายงานเทียบกับ remote ให้ด้วย · refresh หน้า repo บน GitHub จะเห็นไฟล์ทั้ง 3 แล้ว 🎉

📋 สรุป + Cheat Sheet

คำสั่งทำอะไร
git branch -M mainเปลี่ยนชื่อ branch ปัจจุบันเป็น main (ตามธรรมเนียม GitHub)
git remote -vดู remote ที่เชื่อมอยู่ — ว่างเปล่า = ยังไม่เชื่อม
git remote add origin <URL>ผูก remote ชื่อ origin เข้ากับ repo
git push -u origin mainpush ครั้งแรก + ตั้ง upstream
git push origin mainpush รอบถัดไป (มี upstream แล้ว จะพิมพ์แค่ git push ก็ได้)
git remote rename / removeเปลี่ยนชื่อ / ถอด remote — เผื่อใช้ในอนาคต
git pullดึง commit ใหม่จาก remote ลงเครื่อง (คู่ตรงข้ามของ push — ฝึกในหัวข้อ Fetch vs Pull)
🔁 วงจรที่ต้องจำให้ขึ้นใจ: แก้ไข → git add → git commit -m → git push

✅ Checklist ก่อนไปต่อ

  • git branch ตอบ * main ก่อน push ครั้งแรก
  • git remote -v ก่อน add ว่างเปล่า / หลัง add เห็น origin 2 บรรทัด (fetch, push)
  • push แรกเห็น * [new branch] main -> main และ set up to track
  • push รอบถัดไปเห็นรูปแบบ <hash เก่า>..<hash ใหม่> main -> main
