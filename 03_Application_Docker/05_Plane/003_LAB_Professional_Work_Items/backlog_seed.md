ทีมในห้องเรียนกำลังสร้าง **CampusEats** (แอปสั่งอาหารในมหาวิทยาลัย) ใช้ story ชุดนี้ฝึกเขียน work item ตาม `work_item_template.md`
(ใน LAB 3 ใช้ story ที่ 1 เป็น `PLAB-4`; story ที่เหลือใช้ต่อใน LAB 4–5)

| # | ชื่อ work item (ผลลัพธ์ที่ผู้ใช้ได้) | priority | label | เกณฑ์การยอมรับ (ย่อ) |
|---|---|---|---|---|
| 1 | นักศึกษาสมัครบัญชีและเข้าสู่ระบบด้วยอีเมล | High | feature | ใช้อีเมลมหาวิทยาลัยเท่านั้น · รหัสผ่านอ่อนถูกปฏิเสธพร้อมเหตุผล · เข้าสู่ระบบสำเร็จเห็นเมนูร้านค้าใน 2 วินาที |

| 4 | ร้านค้ารับออเดอร์และอัปเดตสถานะ "กำลังทำ → พร้อมรับ" | High | feature | ร้านเห็นออเดอร์ใหม่ภายใน 5 วินาที · เปลี่ยนสถานะแล้วนักศึกษาได้แจ้งเตือน · ออเดอร์ที่ถูกยกเลิกต้องบันทึกเหตุผล |

## บริบท
ในฐานะนักศึกษา ฉันต้องการสมัครบัญชีด้วยอีเมลมหาวิทยาลัย เพื่อสั่งอาหารและติดตามออเดอร์ของตัวเองได้
ที่มา: สัมภาษณ์ผู้ใช้ 12 คน (สัปดาห์ที่ 1) · ไม่รวม: login ด้วย Google/Facebook (งานแยก)

## เกณฑ์การยอมรับ
[] สมัครได้เฉพาะอีเมลโดเมนมหาวิทยาลัย — โดเมนอื่นเห็นข้อความ "ใช้อีเมลมหาวิทยาลัยเท่านั้น"
[] รหัสผ่านต่ำกว่า 8 ตัวหรือไม่มีตัวเลขถูกปฏิเสธพร้อมบอกเหตุผล
[] เข้าสู่ระบบสำเร็จแล้วเห็นหน้ารายชื่อร้านภายใน 2 วินาที

## Definition of Done
[] มี automated test ครอบคลุมทั้ง 3 ข้อและผ่าน
[] code review ผ่าน 1 คน
[] commit อ้าง PLAB-4 และแนบ link

- SMTP ของมหาวิทยาลัยอาจบล็อกอีเมลยืนยัน — ต้องทดสอบกับบัญชีจริงก่อน release
- ประมาณการ 2–3 วัน (ยังไม่ได้สำรวจระบบยืนยันอีเมล)
