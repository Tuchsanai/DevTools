# แม่แบบ work item แบบมืออาชีพ (คัดลอกไปวางใน description ของ Plane)

> กติกา: **ชื่อ** = ผลลัพธ์ที่ผู้ใช้ได้ (ไม่ใช่สิ่งที่โปรแกรมเมอร์จะทำ) · ทุกข้อใน "เกณฑ์การยอมรับ" ต้อง **ทดสอบได้** (ตอบได้ว่าผ่าน/ไม่ผ่าน) ·
> ตั้ง **priority · label · due date · assignee** ทุกครั้ง — ฟิลด์ว่างคือคำถามที่เพื่อนร่วมทีมต้องเสียเวลาถาม

## บริบท (Context)
ในฐานะ <ผู้ใช้แบบไหน> ฉันต้องการ <สิ่งที่ต้องการ> เพื่อ <คุณค่าที่ได้> · ที่มาของงาน (ใครขอ / bug report / ข้อกำหนด) · ขอบเขตที่ **ไม่** ทำในงานนี้

## เกณฑ์การยอมรับ (Acceptance Criteria)
พิมพ์ `[]` แล้วเว้นวรรคที่ต้นบรรทัดใน editor ของ Plane จะกลายเป็น checkbox
- [ ] <เงื่อนไข 1 — Given/When/Then หรือประโยคที่ตรวจได้>
- [ ] <เงื่อนไข 2>
- [ ] <เงื่อนไข 3 — กรณีผิดพลาด/ขอบเขต>

## Definition of Done (DoD)
- [ ] มี automated test ครอบคลุมเกณฑ์การยอมรับทุกข้อ และผ่านทั้งหมด
- [ ] code review ผ่านอย่างน้อย 1 คน (บันทึกใน comment)
- [ ] commit อ้างเลข work item (`PLAB-N: ...`) และแนบ link ไว้ที่ Links
- [ ] อัปเดตเอกสาร/README ที่เกี่ยวข้อง

## ความเสี่ยงและสมมติฐาน (Risks & Assumptions)
- ความเสี่ยง: <อะไรอาจทำให้งานนี้พลาด · ผลกระทบกับใคร>
- สมมติฐาน: <สิ่งที่เชื่อว่าจริงแต่ยังไม่ได้ยืนยัน>
- ประมาณการ: <ช่วงเวลา เช่น 2–3 วัน> พร้อมระดับความไม่แน่นอน (จรรยาบรรณข้อ 3.09)
