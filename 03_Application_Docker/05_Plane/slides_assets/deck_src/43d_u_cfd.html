CFD — ประวัติการไหลของงานทั้งระบบในภาพเดียว

แกนนอน = เวลา · แกนตั้ง = จำนวนงานสะสม · ความหนาของแต่ละแถบ = จำนวนงานในสถานะนั้น ณ เวลานั้น
Cumulative Flow Diagram (CFD) คือกราฟพื้นที่ซ้อนที่นับงานในแต่ละขั้นของ workflow ซ้ำทุกช่วงเวลา จึงเห็นพร้อมกันว่า งานเข้ามาเท่าไร · ค้างอยู่ตรงไหน · ปิดได้เร็วเพียงใด

ปัญหา · ภาพวันนี้ซ่อนอดีต

บอร์ดบอกเพียงว่าวันนี้มีงานอยู่คอลัมน์ใด แต่ไม่บอกว่าแถว Review เคยบวมกี่วัน หรือคิวกำลังยาวขึ้นต่อเนื่องหรือไม่ ค่าเฉลี่ยเดียวก็ซ่อนช่วงที่ระบบติดขัดได้

ทำไมสำคัญ · 4 สัญญาณร่วมกัน

CFD ช่วยอ่าน WIP จากความหนาแนวตั้ง · lead time โดยประมาณ จากช่องว่างแนวนอน · throughput จากความชัน Done · และ คอขวด จากแถบกลางที่กว้างขึ้น

CampusEats · เห็นคิวก่อนส่งช้า

ทีมรับคำขอช่วงเปิดเทอมเร็วกว่าที่ review และ deploy ได้ แถบ In Progress จึงอ้วนขึ้น แม้ทุกคนดูยุ่ง CFD ชี้ว่าควรหยุดดึงงานใหม่ แล้วช่วยกันระบายปลายน้ำ

ความเข้าใจผิดที่พบบ่อย — ❌ “CFD คือภาพสถานะของบอร์ดวันนี้” → ✅ CFD ต้องมี snapshot หลายวันจึงเห็นแนวโน้ม · ❌ “เส้นบนสูงขึ้นแปลว่าแย่” → ✅ เส้นบนคือ scope สะสม; ต้องอ่าน ความหนาและความชันของแต่ละแถบ ร่วมกัน

อ่าน CFD แล้วจัดการ flow — วัด · ตั้ง policy · ทบทวนตาม cadence

นับจำนวนงานปลายแต่ละวันแล้วซ้อนเป็นแถบ · ช่องว่างแนวนอนเป็นเพียงค่า lead time โดยประมาณ ไม่ใช่เวลาของงานใบใดใบหนึ่ง

กลไก · 3 ขั้น

1) นับงานในแต่ละสถานะ ณ สิ้นวัน 2) วางค่าเป็นแถบซ้อนต่อเนื่อง 3) เปรียบเทียบความหนา ความชัน และการเปลี่ยนรูปของแถบข้ามวัน

Class of service + explicit policy

Expedite ข้ามคิว ≤ 1 · Fixed date เริ่มตาม lead time · Standard เดินตามลำดับ backlog · Intangible จองความจุไว้ลด technical debt

Cadences · วงจร feedback

Replenishment เติม Ready → Daily Kanban แก้คอขวด → Delivery ส่งเมื่อพร้อม → Service delivery review อ่าน CFD แล้วปรับ policy

จากกราฟสู่การตัดสินใจ — เมื่อแถบ In Progress กว้างขึ้นต่อเนื่อง อย่าเร่ง “เริ่ม” เพิ่ม: หยุดดึงงาน · ช่วยขั้นปลายน้ำ · ตรวจ exit policy และ WIP limit แล้วดูรอบถัดไปว่าแถบกลับมาคงที่หรือไม่

Plane CE ไม่มี CFD ในตัว — สร้างจาก state activity ใน LAB 9

LAB 9 · Cumulative Flow 14 วัน: completed สีเขียว · started สีน้ำเงิน · unstarted สีเทา

ข้อจำกัดของ CE v1.4.2

Plane มี Analytics › Work items แต่กราฟ Created vs resolved นับรายเดือนตามเดือนที่สร้างและสถานะปัจจุบัน จึงไม่ใช่ CFD; ไม่พบกราฟ CFD สำเร็จรูปในรุ่นนี้

ข้อมูลต้นทาง · Activity + State

เมื่อ state เปลี่ยน Plane บันทึก activity ที่ field="state" พร้อม UUID เดิม/ใหม่; จับคู่ UUID กับ states.group แล้วสร้างจำนวนงานต่อกลุ่ม ณ สิ้นวันย้อนหลัง

Workflow · ดึง → ย้อนสถานะ → วาด

LAB 9 dashboard ดึง work items, states และ activities ผ่าน REST API · เริ่มจาก state ปัจจุบัน · ย้อน transition หลังจุดตัดเวลา · ทดสอบสูตรก่อนวาดแถบซ้อน

Mini exercise — จากภาพ ช่วง 27–30 ส.ค. แถบ started เปลี่ยนอย่างไร? สิ่งนี้บอกอะไรเกี่ยวกับ WIP และคอขวด? เสนอการตัดสินใจหนึ่งข้อ แล้วระบุว่าต้องดู metric ใดในวันถัดไปเพื่อพิสูจน์ว่าการแก้ได้ผล
