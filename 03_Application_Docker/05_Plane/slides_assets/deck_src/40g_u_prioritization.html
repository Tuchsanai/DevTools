ตอนที่ 3 · Prioritization · นิยาม

Prioritization คือ การตัดสินใจว่า “ทำอะไรก่อน”

ผลลัพธ์ต้องเป็น backlog ที่เรียงลำดับเดียว ไม่ใช่รายการงานที่ทุกใบติดป้ายว่า “ด่วน”
การจัดลำดับความสำคัญ คือการเปรียบเทียบงานทั้งกอง แล้วเลือก “ลำดับการทำ” ตามคุณค่า ต้นทุน ความเสี่ยง และเวลา— ทีมดึงงานจากบนลงล่างเมื่อมี capacity

ก่อน · ทุกอย่าง Urgent

ทีมสลับงานตามคนที่เร่งเสียงดังที่สุด งานสำคัญจริงรออยู่ และไม่มีใครบอกได้ว่างานถัดไปคืออะไร

หลัง · มีลำดับเดียว

ทุกคนเห็น trade-off เดียวกัน: ถ้างานใหม่ขึ้นอันดับ 1 งานเดิมต้องเลื่อนลง การเริ่มงานจึงเป็นการตัดสินใจร่วม ไม่ใช่การเดา

เหตุผล · ทรัพยากรมีจำกัด

เวลาและกำลังคนไม่พอทำทุกอย่างพร้อมกัน ลำดับที่ชัดช่วยส่งคุณค่าก่อน ลดงานค้าง และทำให้เหตุผลตรวจสอบได้

CampusEats · ตัวอย่างจริง

ก่อนเปิดเทอม 1 สัปดาห์ ทีมวาง “รีเซ็ตรหัสผ่าน” เหนือ “dark mode” เพราะผู้ใช้ที่เข้าไม่ได้สั่งอาหารไม่ได้ แม้ทั้งสองงานจะถูกขอมาเหมือนกัน

ความเข้าใจผิด

❌ Priority = ระดับความเร่งด่วนของแต่ละใบ
✅ Prioritization = เปรียบเทียบทุกใบจนได้ลำดับ 1, 2, 3… ป้ายเดียวกันยังต้องเรียงกันอีกครั้ง

ตอนที่ 3 · Prioritization · ใน Plane

Plane เก็บทั้ง ระดับ priority และลำดับของ backlog

ป้ายช่วยมองเห็นความเร่งด่วน ส่วนการเรียงลำดับบอกว่าทีมควรหยิบใบใดก่อน
Work item → Priority — ตัวเลือกคงที่ Urgent · High · Medium · Low · None
Work items → Display/Filters — เลือก layout · group by · order by Priority

1 · ระดับ

priority มี 5 ค่าและค่าเริ่มต้นคือ none; เมื่อเรียงตาม priority ระบบวาง urgent → high → medium → low → none

2 · ลำดับ

ลากจัดอันดับ backlog เพื่อแยกใบที่มี priority เท่ากันให้เป็นลำดับ 1, 2, 3…; ระบบเก็บตำแหน่งไว้ใน sort_order

3 · Expedite

CE ไม่มี WIP limit: ใช้ Urgent + policy ของทีม และบันทึกตัวกรองเป็น View; จำกัดจำนวนงานด่วน ไม่ให้ทุกใบข้ามคิว
