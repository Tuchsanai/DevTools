เจ็ดประโยคที่ "ฟังดูถูก" — แต่หลักฐานจากการรันจริงบอกอีกอย่าง

"container Up = แอปพร้อม"

LAB 1: /api/instances/ ตอบ 502 อีก ~110 วินาทีหลัง Up จน migrator เสร็จและ gunicorn ฟัง

"แก้ env แล้ว restart ก็เปลี่ยน"

LAB 1: ค่า instance config seed ครั้งเดียว (SKIP_ENV_VAR=1) และ restart ไม่อ่าน env ใหม่ — ต้อง god-mode หรือ up -d

"worker หยุด เว็บต้องพัง"

LAB 2: UI ปกติ แต่คิว celery โต — activity/notification/webhook เงียบ

"burndown มาจากประวัติ state"

LAB 4: มาจาก completed_at — ย้ายกลับจาก Done ค่าเป็น NULL กราฟเด้งขึ้น

"ส่ง identifier แทน UUID ได้"

LAB 7: /projects/PLAB/... = 404 · human key ใช้ได้เฉพาะ /work-items/PLAB-1/

"webhook ชี้ localhost ได้"

LAB 8: ถูกปฏิเสธ/400 SSRF จนใส่ WEBHOOK_ALLOWED_HOSTS และ recreate api+worker

"velocity สูง = ทีมเก่ง · เลขงานลบแล้วใช้ซ้ำได้"

LAB 4/9: velocity ใช้ forecast ไม่ใช่ประเมินคน · LAB 2/3: issue_sequences ไม่ใช้เลขซ้ำ แม้ลบงานทิ้ง

ตอนที่ 6 · สะพานสู่งานจริง

จากห้องเรียนสู่ production — สิ่งที่ต้องเติมก่อนใช้ Plane กับทีมจริง

ความปลอดภัย

SECRET_KEY/LIVE_SERVER_SECRET_KEY สุ่มและเก็บนอก repo · เปลี่ยนรหัส MinIO/RabbitMQ/Postgres · TLS ผ่าน Caddy (CERT_EMAIL) · TRUSTED_PROXIES จริง · ปิด sign-up สาธารณะ

ความทนทาน

backup volume (install.sh option 7) และทดสอบ restore · replicas ของ api/worker · monitoring (โมดูล Prometheus/Grafana) · log ไป central · อัปเกรดตาม release notes

กระบวนการทีม

SMTP สำหรับคำเชิญ/แจ้งเตือน · นโยบาย WIP/DoD ใน Pages · token ต่อคน/ต่อเครื่องมือ · webhook → CI/chat · dashboard เป็น "คำถาม" ไม่ใช่ "การจับผิด"

ทางเลือก — ทีมเล็กใช้ Trello · องค์กรใหญ่ใช้ Jira · ทีมที่ต้องการเป็นเจ้าของข้อมูลและปรับแต่งได้ใช้ Plane self-hosted — โมเดลข้อมูลเดียวกัน ย้ายได้ผ่าน API/CSV (LAB 7)

ตอนที่ 6 · Cheat sheet

คำสั่งที่ใช้ซ้ำทั้งชุด — จำได้แล้วทำทุก LAB เร็วขึ้น

# เครื่องเรียน
docker start devtools 2>/dev/null || docker run -dit --name devtools \
  --privileged -p 2222:22 -p 8080:8080 -p 9000:9000 -p 8090:8090 tuchsanai/devtools:2569_1
ssh root@localhost -p 2222

# Plane (pc = docker compose ของ ~/plane-selfhost)
pc ps            pc logs -f api        pc up -d api worker
bash wait_ready.sh
curl -s localhost:8080/api/instances/ | head -c 200
pc exec -T -e PGPASSWORD=plane plane-db psql -U plane -d plane -c "select ...;"
pc exec plane-mq rabbitmqctl list_queues -p plane name messages consumers
# REST API v1
export T=$(cat ~/.plane_token)
curl -s localhost:8080/api/v1/users/me/ -H "X-API-Key: $T"
curl -s ".../workspaces/devtools-lab/projects/?per_page=50" -H "X-API-Key: $T"
curl -s ".../projects/<uuid>/work-items/?per_page=25&cursor=25:1:0" ...
curl -X POST ".../work-items/" -H "X-API-Key: $T" -H 'Content-Type: application/json' \
  -d '{"name":"...","priority":"high","state":"<state uuid>",
       "external_source":"trello","external_id":"card-1"}'

# จบชุด
docker rm -f dashboard hookwall mq-ui minio-ui
pc down        # เก็บ volume   |   pc down -v   # ลบทั้งหมด
