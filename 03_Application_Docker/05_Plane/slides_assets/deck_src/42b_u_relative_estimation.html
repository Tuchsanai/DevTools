Relative estimation — เทียบขนาดกับเรื่องอ้างอิง ไม่เทียบกับนาฬิกา

นิยาม — Relative estimation คือการให้ขนาดของงานด้วยการเทียบกับ เรื่องอ้างอิง (reference story) ที่ทีมเข้าใจตรงกัน โดยถามว่า “ใหญ่กว่าเรื่องนี้กี่เท่า” แทนการทำนายว่า “ใช้เวลากี่ชั่วโมง”
ทำไมสำคัญ · ปัญหาที่แก้ — ก่อน: ถามเป็นชั่วโมงแล้วได้ 8h / 12h / 30h จากสามคนในทีมเดียวกัน ตัวเลขจึงถูกตีความเป็นกำหนดส่งที่ผิดตั้งแต่วันแรก · หลัง: คนตัดสิน “ใบไหนใหญ่กว่า” ได้ตรงกันกว่าการทาย “ใหญ่เท่าไร” เพราะการเทียบไม่ต้องรู้ค่าสัมบูรณ์ของงานที่ยังไม่เคยทำ และไม่ผูกกับว่าใครลงมือ ค่าจึงนิ่งพอจะบวกรวมไปคาดการณ์ต่อ
องค์ประกอบ — เรื่องอ้างอิงหนึ่งเรื่อง + สเกลร่วมของทีม + เกณฑ์เทียบสามด้าน (effort · complexity · uncertainty); ภาพนี้ใช้ “เข้าสู่ระบบด้วยอีเมล = 2 pt” เป็นฐาน แล้วเทียบงานอื่นเป็นครึ่งหนึ่ง สองเท่า และใหญ่เกินจนต้องแตก

กลไก · workflow 4 ขั้น

1) เลือกเรื่องอ้างอิงที่เล็ก ทำเสร็จแล้ว และทุกคนเข้าใจตรงกัน ให้เป็น 2 pt · 2) ถามทีละใบว่าใหญ่กว่าฐานกี่เท่า โดยชั่ง 3 ด้านพร้อมกัน · 3) เลือกค่าที่ใกล้ที่สุดจากสเกลของทีม แล้วจดเหตุผลไว้ · 4) ทวนแนวเทียบ (triangulation) เอาใบใหม่ไปวางข้างใบที่เคยได้ค่าเท่ากัน ถ้าขนาดไม่พอกันให้แก้ค่าใดค่าหนึ่ง

ตัวอย่าง · CampusEats

ฐานคือ PBI-02 ดูเมนูและราคา = 2 pt → PBI-09 เขียนเอกสาร API “พอ ๆ กัน” = 2 pt · PBI-03 ตะกร้าและแก้จำนวน “ใหญ่กว่านิดเดียว” = 3 pt · PBI-06 ไรเดอร์เห็นออเดอร์ที่พร้อมส่ง “ใหญ่กว่าชัดเจน” = 5 pt เพราะเพิ่มหน้าจอใหม่และเงื่อนไขสถานะ

❌ เข้าใจผิด — “ทีมชำนาญขึ้นแล้วต้องลด point ของงานเดิม” และ “งานที่ปริมาณมากแต่ไม่ยาก ควรได้ point ต่ำ”
✅ ใช้ให้ถูก — ฐานและสเกลต้องนิ่ง ความเร็วที่เพิ่มขึ้นให้สะท้อนที่ velocity ไม่ใช่ที่ point; และ point รวม effort ไว้ด้วย งานเยอะแต่ตรงไปตรงมาจึงใหญ่ได้

บันทึกผลการเทียบใน Plane — ช่อง Estimate ของ work item

Plane เก็บ “ค่าที่ทีมตกลงแล้ว” แต่ไม่ได้เทียบให้ การเปรียบเทียบและเหตุผลเกิดในวงคุยของทีมก่อนเลือกค่าเสมอ
PLAB-12 “สั่งอาหารและรับหมายเลขออเดอร์” (ครอบกลางภาพ) — แถบ Properties: In Review · dev1 · Urgent · Start Sep 02 / Due Sep 05, 2026 · Estimate 5 · Modules Ordering

1วิธี Plane รองรับ

ดรอปดาวน์ Estimate เสนอเฉพาะค่าในสเกลของโปรเจกต์ (ที่นี่คือ 1 · 2 · 3 · 5 · 8 · 13) ทีมจึงถูกบังคับให้เลือกจาก สเกลร่วมชุดเดียว ไม่มีช่องพิมพ์ตัวเลขอิสระ และไม่มีหน่วยชั่วโมง (Time เป็นของรุ่นเสียเงิน)

2ฟีเจอร์ที่เกี่ยวข้อง · Display

เปิด display property Estimate (ปุ่ม Display › Display Properties) ใน List/Table แล้ว ทวนแนวเทียบ: ทุกใบที่ 3 pt ใหญ่พอ ๆ กันจริงไหม · เหตุผลของค่าเขียนไว้ใน comment เพราะ Plane ไม่มีช่องเก็บ

3ขอบเขตของ CE

เมนู Display › Order by ไม่มี Estimate; หัวคอลัมน์ Estimate ใน Table มีเมนู Low → High แต่ backend v1.4.2 ไม่รับ order_by นี้ จึงถอยไปเรียง -created_at เงียบ ๆ — ถ้าต้องเรียงจริงให้ export CSV (มีคอลัมน์ estimate)
