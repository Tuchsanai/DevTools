Burn-up — แยก “ทำเสร็จแล้ว” ออกจาก “ขอบเขตทั้งหมด”

แกนนอน = เวลา · แกนตั้ง = จำนวนงานหรือ points · ระยะห่างระหว่างสองเส้นคืองานที่ยังเหลือ
อ่านฝั่งขวา: เส้นเขียว = Done สะสม · เส้นม่วง = Scope รวม · Scope เพิ่มวันที่ 5 จึงมองเห็นเหตุของช่องว่างได้ทันที
Burn-up คือกราฟสองเส้น: งาน Done สะสม และ Scope รวม ณ แต่ละวัน จึงเห็นทั้งความคืบหน้าและการเปลี่ยนขอบเขตในภาพเดียว

ทำไมสำคัญ · กลไก 3 ค่า

ค่า remaining เส้นเดียวแยกไม่ได้ว่าทีมช้าหรือ scope เพิ่ม จึงอ่าน Done(d) · Scope(d) และ Remaining(d) = Scope(d) − Done(d). เส้น Done ไม่ควรลด เว้นแต่แก้ข้อมูลหรือเปิดงานกลับ

CampusEats · Scope creep ที่มองเห็น

Sprint 2 เริ่มที่ 10 ใบ; วันที่ 4 เพิ่มเรื่อง “แจ้งเตือนสารก่อภูมิแพ้” 2 ใบ → Scope = 12. วันที่ 6 Done แล้ว 8 ใบ จึงเหลือ 4 ใบ กราฟบอกพร้อมกันว่า ทีมเดินหน้า 8 และ scope โต 2

❌ เข้าใจผิด → ✅ ใช้ให้ถูก

ผิด: เส้นที่สูงขึ้นแปลว่างานแย่ลง · ถูก: Done สูงขึ้นคือความคืบหน้า ส่วน Scope สูงขึ้นคือขอบเขตเพิ่ม; ต้องอ่านสองเส้นและเหตุการณ์บน backlog ร่วมกัน

Plane CE ไม่มีกราฟ Burn-up — ประกอบข้อมูลจาก Cycle เอง

ใช้ข้อมูลสมาชิกของ Cycle เป็น scope และ completed_at เป็นเวลาที่งานเข้าสู่ state group completed
LAB 9 · Mission Control ดึงข้อมูลจริงจาก Plane API มาคำนวณ metrics ภายนอก — ตัวอย่างแนวทางเมื่อ CE ไม่มีกราฟที่ต้องการ

ข้อจำกัดของ CE v1.4.2

หน้า Cycle มี Progress และ burndown; ค่าคงที่ burnup มีในโค้ดบางส่วน แต่ไม่มี renderer ของกราฟ Burn-up ใน UI จึงเปิดจากเมนูใดไม่ได้

ข้อมูลต้นทาง · cycle_issues + completed_at

สมาชิก Cycle บอก scope ปัจจุบัน; สำหรับแต่ละวัน d นับ Done(d) = Σ completed_at ≤ d. ถ้าต้องการเส้น scope ย้อนหลังที่ขึ้นเป็นขั้น ต้องเก็บวันที่เพิ่ม/ถอดสมาชิก Cycle ไว้ด้วย ไม่ใช่อ่านเฉพาะสมาชิกปัจจุบัน

Workflow · คำนวณ → ตรวจ → แสดงผล

LAB 4 ดัดแปลง cycle_report.py ให้คืน Done สะสมและ Scope · LAB 9 เพิ่ม panel Burn-up พร้อม test แล้วเทียบจำนวน Done กับ Cycle Progress

Mini exercise — CampusEats เริ่ม 10 ใบ · วันที่ 4 เพิ่ม 2 ใบ · วันที่ 6 Done สะสม 8 ใบ: จุดของเส้น Scope และ Done ในวันที่ 6 คือเท่าไร? ช่องว่าง 4 ใบบอกอะไร และคุณต้องตรวจเหตุการณ์ใดก่อนสรุปว่า “ทีมช้า”?
