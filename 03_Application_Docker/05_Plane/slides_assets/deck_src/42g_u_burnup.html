Burn-up — แยก “งานที่เสร็จแล้ว” ออกจาก “ขอบเขตทั้งหมด”

แกนนอน = เวลา · แกนตั้ง = จำนวนใบงานหรือ points · ระยะห่างแนวดิ่งระหว่างสองเส้น = งานที่ยังเหลือ
ครึ่งขวาของ d33 — เส้นเขียว = Done สะสม · เส้นม่วง = Scope รวม 40 pt ที่ขยับเป็น 48 pt ในวันที่ 5 · เส้นประในวันที่ 7 คือช่องว่าง “งานที่เหลือ”
นิยาม — Burn-up คือกราฟ สองเส้น ต่อรอบงานหนึ่งรอบ: งานที่ Done สะสม และ ขอบเขตรวม (scope) ณ แต่ละวัน จึงอ่านความคืบหน้าและการเปลี่ยนขอบเขตได้จากภาพเดียว

ทำไมสำคัญ · ปัญหาที่แก้

Burndown มีเส้นเดียว จึงบอกไม่ได้ว่า “ยังเหลือเยอะ” เพราะทีมช้าหรือเพราะมีงานเพิ่ม — Burn-up แยกสองสาเหตุออกจากกัน ทีมกับ PO จึงคุยกันถูกเรื่องตั้งแต่กลางรอบ

องค์ประกอบ · กลไกการอ่าน

ต้องมี 3 ค่า: Done(d) · Scope(d) · หน่วยเดียวกันทั้งกราฟ (ใบ หรือ points) — ช่องว่าง เหลือ(d) = Scope(d) − Done(d); เส้น Done อาจลดลงได้ถ้าเปิดงานที่ปิดไปแล้วกลับมา

Workflow · สร้างเส้นสองเส้นอย่างไร

ทุกวัน d: ① นับใบที่เข้าสถานะเสร็จภายในวันนั้น แล้วสะสม = Done(d) ② นับใบที่อยู่ในรอบงาน ณ วันนั้น = Scope(d) ③ วาดสองเส้นบนแกนเดียวกัน แล้วอ่านทั้งความชันและช่องว่าง
