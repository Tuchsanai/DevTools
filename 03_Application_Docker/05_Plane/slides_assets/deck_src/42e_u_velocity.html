Velocity — ปริมาณงานที่ทีมทำ Done ได้จริงต่อหนึ่ง Sprint

หนึ่งตัวเลขต่อหนึ่ง Sprint · ใช้ประวัติของทีมเองเพื่อวางแผน ไม่ใช่คำสัญญาว่ารอบหน้าต้องทำได้เท่าเดิม
นิยาม — Velocity คือ ผลรวม story points ของ work item ที่ผ่าน Definition of Done ภายใน Sprint นั้น งานที่เริ่มแล้วแต่ยังไม่ Done นับเป็น 0 — ไม่มีเครดิตครึ่งทาง หน่วย: points / sprint · เป็นมาตรวัดเฉพาะของทีมนั้น ไม่ใช่มาตรฐานกลาง
  • ทำไมสำคัญ — Sprint Planning เลือกงานจากสิ่งที่ทีม “เคยทำได้จริง” และตอบคำถาม “อีกกี่รอบจะเสร็จ” ด้วยหลักฐาน ไม่ใช่ความรู้สึก
  • ปัญหาที่แก้ — ทีมรับงานเข้ารอบตามความหวังทุกครั้ง จึงค้างงานสะสมและบอกกำหนดส่งมอบที่เชื่อถือได้ไม่ได้
  • เงื่อนไขที่ทำให้เชื่อถือได้ — ทีมชุดเดิม สเกล points เดิม DoD เดิม รอบยาวเท่าเดิม; ถ้าเปลี่ยนให้อ่านข้อมูลก่อน–หลังแยกกัน
ก่อน · ยังไม่มีประวัติหลัง · มีประวัติ 3 Sprint
“รอบนี้น่าจะรับได้ 30 points” → ค้างงานทุกรอบรับงานใกล้ช่วงที่เคย Done แล้วตอบเป็นช่วง “อีก 5.5–6.7 รอบ”
ขอบเขต — Scrum Guide 2020 ไม่ได้กล่าวถึง velocity เลย เป็นเทคนิคพยากรณ์ที่ทีมเลือกใช้เอง
ทีมใช้แนวโน้มจากหลายรอบที่ผ่านมาเป็นฐานของการวางแผนและการคุยเรื่องความไม่แน่นอน

ตัวอย่างจริง · CampusEats Sprint 1

LAB 4 ดึงเข้ารอบ 7 ใบ = 19 points แล้วแทรก action item อีก 1 ใบกลางรอบ (รวม 8 ใบ = 21 points) · ผ่าน DoD 3 ใบ: PBI-01 ค้นหาร้าน 3 pt + PBI-02 ดูเมนู 2 pt + PBI-10 ย้าย config 1 pt → velocity = 6 points; อีก 5 ใบนับ 0 และถูกโอนไป Sprint 2

ความเข้าใจผิด — ❌ velocity สูงกว่า = ทีมเก่งกว่า จึงตั้งเป้าให้เพิ่มขึ้นทุกรอบ · ✅ point เป็นสเกลภายในทีม และเมื่อถูกใช้เป็นเป้า ทีมจะเฟ้อ point หรือลดคุณภาพ (เช่น ตัดการทดสอบออกจาก DoD) เพื่อดันตัวเลข — ใช้ดูแนวโน้มของทีมเดิมเท่านั้น ห้ามเทียบข้ามทีม

จากประวัติ 3 Sprint สู่ ช่วงพยากรณ์ — ไม่ใช่เป้าที่ตั้งให้ทีม

อ่านซ้ายไปขวา: วัด velocity ของแต่ละรอบ → เฉลี่ย → หารงานที่เหลือเป็นจำนวนรอบ แล้วรายงานเป็นช่วง

1องค์ประกอบ

Sprint ที่ปิดแล้ว · DoD ชุดเดียวกันทุกรอบ · points ของทุกใบใน Sprint · ประวัติอย่างน้อย 3 รอบ · จำนวน points ที่ยังเหลือใน backlog

2วิธีทำงาน · วัดเมื่อรอบจบ

รวม points เฉพาะใบที่ Done ในรอบนั้น: 18 · 22 · 20 → เฉลี่ย 20 pt/sprint; นับเต็มใบในรอบที่ใบนั้น Done และไม่ย้อนไปแก้รอบก่อน

3Workflow · พยากรณ์แล้วคำนวณใหม่

120 pt ÷ 20 = 6 Sprint; ใช้ค่าดีสุด/แย่สุด 120÷22 … 120÷18 = 5.5–6.7 Sprint แล้วคำนวณซ้ำทุกครั้งที่ปิดรอบหรือ backlog เปลี่ยน
