ตอนที่ 3 · Continuous Improvement · นิยาม

Continuous Improvement — ปรับกระบวนการทีละน้อยจากหลักฐานจริง

Kaizen / PDCA ทำให้ทุก Sprint หรือ Cycle เป็นทั้งรอบส่งมอบงานและรอบเรียนรู้ว่า “ครั้งหน้าจะทำให้ดีขึ้นอย่างไร”
Continuous Improvement คือการ วัดผล · ทบทวนสาเหตุ · เลือกการเปลี่ยนแปลงเล็ก ๆ · ทดลองในรอบถัดไป แล้ววัดซ้ำ เพื่อให้กระบวนการดีขึ้นอย่างต่อเนื่องโดยไม่อาศัยความรู้สึกล้วน ๆ

ปัญหาที่แก้ · ก่อน

ปัญหาเดิมเกิดซ้ำทุกรอบ: Review ค้าง · งานย้ายข้าม Sprint · Retro คุยดีแต่จบแล้วไม่มีเจ้าของและไม่มีวันตรวจผล

ทำไมสำคัญ · หลัง

ทีมเห็นสัญญาณจากข้อมูล เลือกแก้เพียง 1–2 เรื่อง ทำเป็นงานจริง แล้วเทียบตัวชี้วัดก่อน–หลังในรอบถัดไป

ตัวอย่าง · CampusEats (LAB 4) — Retro ของ Sprint 1 บันทึกตัวเลขจริงไว้: committed 19 points · done 6 points · งานค้าง 4 ใบ (13 points) โอนไป Sprint 2 พร้อม action item อีก 1 ใบ · ทีมเลือก Stop ข้อเดียวคือ “เลิกดึงงานใหม่เข้า In Progress ทั้งที่งานเดิมยังไม่ Done” แล้วนัดวัดซ้ำด้วยจำนวนใบที่ต้องโอนตอนปิด Sprint 2
ทีมเปลี่ยนข้อสังเกตจากข้อมูลให้เป็นการทดลองขนาดเล็กที่มีเจ้าของและวัดผลได้

ความเข้าใจผิด · ❌ เปลี่ยนทุกอย่างพร้อมกัน

✅ เปลี่ยนทีละน้อยอย่างมีสมมติฐาน รักษาสิ่งที่ได้ผล และรอหลักฐานจากรอบถัดไปก่อนสรุป — ถ้าเปลี่ยน 5 อย่างพร้อมกันแล้วดีขึ้น ก็ยังไม่รู้ว่าอะไรได้ผล

ที่มาในทฤษฎี — วงจร PDCA (Shewhart/Deming) และ Kaizen ของสายการผลิตญี่ปุ่นคือรากของแนวคิดนี้ · Scrum Guide 2020 วาง Sprint Retrospective เป็นอีเวนต์ปิดท้ายทุก Sprint (timebox ≤ 3 ชม. สำหรับ Sprint 1 เดือน) และระบุว่าการปรับปรุงที่มีผลมากที่สุด “ควรลงมือทันที และอาจใส่ไว้ใน Sprint Backlog รอบถัดไป” — ฉบับ 2020 ไม่ได้บังคับให้ใส่ทุกครั้งเหมือนฉบับ 2017

ตอนที่ 3 · Continuous Improvement · กลไก

วงจร Kaizen / PDCA — วัด → ทบทวน → ตัดสินใจ → ลงมือ → วัดซ้ำ

หนึ่ง Sprint หรือ Cycle ทำหน้าที่เป็นหนึ่งรอบทดลอง: ปัญหาต้องมีหลักฐาน และ action item ต้องกลับเข้าแผนงานจริง
PDCA: Plan = เลือกการทดลอง · Do = ทำในรอบถัดไป · Check = วัดและทบทวน · Act = เก็บวิธีที่ได้ผลไว้เป็นมาตรฐาน หรือปรับสมมติฐานแล้ววนใหม่

1องค์ประกอบ · Measure

เลือก 1–3 สัญญาณที่ตรงกับปัญหา เช่น burndown · Cycle time · CFD · จำนวนงานที่ต้องโอนไปรอบถัดไป แล้วเก็บค่าเริ่มต้นไว้เทียบ

2องค์ประกอบ · Retrospective

Start / Stop / Continue ถามว่าจะเริ่ม เลิก และทำต่ออะไร · 4Ls ถาม Liked · Learned · Lacked · Longed for · ทั้งสองรูปแบบถาม “กระบวนการ” ไม่ใช่ “ใครผิด”

3องค์ประกอบ · Action item

เลือกเพียง 1–2 ข้อ เขียนให้มีเจ้าของ เงื่อนไขสำเร็จ และตัวชี้วัดที่จะตรวจ; สร้างเป็น work item แล้วใส่ใน Cycle ถัดไป ไม่ใช่แทรกกลางรอบที่กำลังจะปิด

Workflow ที่ปิดวงจร — Metric บอก “เกิดอะไร” → Retro ถาม “เพราะอะไร” → Action item ระบุ “จะลองเปลี่ยนอะไร” → รอบถัดไปตอบ “ดีขึ้นจริงหรือไม่” หากไม่มีเจ้าของ ไม่มีงานในแผน และไม่มีวันวัดซ้ำ นั่นคือบทสนทนา ไม่ใช่การปรับปรุง
