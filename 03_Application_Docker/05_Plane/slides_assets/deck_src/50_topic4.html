"การติดตาม" คือวงจร Plan → Do → Measure → Adapt ไม่ใช่การกรอกสถานะ

เครื่องมือมีหน้าที่ทำให้วงจรนี้หมุนได้ทุกวันโดยไม่ต้องถามในที่ประชุม
Plan = backlog + estimate · Do = งานเคลื่อนผ่าน state · Measure = burndown, velocity, lead time · Adapt = จัดลำดับใหม่, retrospective

Project tracking vs Product tracking

Project tracking วัดว่างานตามแผนเสร็จทันเวลาและงบหรือไม่ (scope · time · cost) ส่วน Product tracking วัดว่าสิ่งที่ส่งมอบสร้างคุณค่าจริงหรือไม่ และปรับลำดับความสำคัญได้ต่อเนื่อง — ทีม Agile ต้องการทั้งสองในเครื่องมือเดียว

Leading vs Lagging indicators

Leading เห็นก่อนผลลัพธ์ เช่น WIP, งานที่ค้างเกิน 5 วัน, จำนวนงานที่ถูก block — แก้ได้ทันที
Lagging สรุปผลย้อนหลัง เช่น velocity, lead time, bug หลังปล่อย — ใช้ประเมินและวางแผนรอบถัดไป

ตอนที่ 4 · Product Tracking · Jira boards

บอร์ดสองแบบ: Scrum board ผูกกับ sprint · Kanban board ผูกกับ WIP

Scrum board

  • Backlog view — จัดลำดับ ประมาณค่า แล้วลาก story เข้า sprint
  • Active sprint — คอลัมน์ตาม workflow เห็นเฉพาะงานใน sprint ปัจจุบัน
  • Complete sprint — งานที่ไม่เสร็จถูกส่งกลับ backlog หรือ sprint ถัดไป
  • รายงานประจำ: burndown, velocity, sprint report

Kanban board

  • ไม่มี sprint — งานไหลต่อเนื่องจาก backlog ผ่านคอลัมน์
  • Columns ↔ statuses — หนึ่งคอลัมน์ผูกได้หลาย status (board settings → Columns)
  • WIP limit ต่อคอลัมน์ (min/max) คอลัมน์เปลี่ยนสีเมื่อเกิน
  • Swimlanes แบ่งแถวตาม epic, assignee หรือ JQL
  • รายงานประจำ: cumulative flow diagram, control chart

จังหวะเวลา

Scrum: sprint 1–4 สัปดาห์ วางแผนและรีวิวเป็นรอบ · Kanban: ต่อเนื่อง ปล่อยงานได้ทุกเมื่อที่พร้อม

การประมาณค่า

Scrum: story points เพื่อคำนวณ velocity · Kanban: ไม่บังคับ ใช้ cycle time และ throughput แทน

ใน Plane

เปิด Cycles = ทำงานแบบ Scrum · ปิด Cycles แล้วใช้ Board + Intake = แบบ Kanban — เลือกได้ต่อโปรเจกต์

Quick filters — ปุ่มกรองบนบอร์ดที่นิยามด้วย JQL เช่น assignee = currentUser() · Plane: Board layout + Display (Group by / Sub-group by = swimlanes) + Views ที่บันทึกได้ — แต่ CE ไม่มี WIP limit ทีมต้องตกลงกันเอง

JQL — ภาษาคิวรี ที่อยู่เบื้องหลัง filter, board, report และ automation ของ Jira

# 1 งานของฉันที่ยังไม่ปิด
assignee = currentUser() AND resolution = EMPTY
# 2 bug ที่ต้องรีบทำในโปรเจกต์ PLAB
project = PLAB AND issuetype = Bug AND priority in (Highest, High)
# 3 งานใน sprint ที่กำลังทำ เรียงตามความสำคัญ
project = PLAB AND sprint in openSprints() ORDER BY priority DESC
# 4 งานที่ค้างใน In Progress โดยไม่ขยับมา 7 วัน
status = "In Progress" AND NOT status CHANGED AFTER -7d
# 5 งานที่ปิดในสัปดาห์นี้ (ใช้ทำรายงาน)
resolved >= startOfWeek() AND resolved <= endOfWeek()
ไวยากรณ์ field operator value เชื่อมด้วย AND / OR / NOT
เปรียบเทียบ= != > >= < <=
ข้อความ~ contains · !~ not contains
ชุดค่า / ค่าว่างIN NOT IN · IS EMPTY IS NOT EMPTY
ประวัติWAS WAS IN WAS NOT CHANGED + AFTER / BEFORE / BY / FROM / TO
ฟังก์ชัน · เวลาcurrentUser() openSprints() startOfWeek() · สัมพัทธ์ -7d -2w
เรียงลำดับORDER BY รับหลายคีย์ เช่น priority DESC, created ASC

เทียบกับ Plane

Views = filter ที่บันทึกไว้ (state group, priority, assignee, label, cycle, module, วันที่) ด้วยตัวดำเนินการ is / is any of / between — ไม่มีภาษาคิวรี และ REST v1 ตอบ 400 เมื่อส่ง ?pql= ใน CE · Workspace views แสดงได้เฉพาะ Table

Automation rules และ REST API v3 — ให้ Jira ทำงานแทนคน

Automation rule = Trigger → Condition → Action

Trigger issue created / transitioned / scheduled / incoming webhook
Condition JQL condition, ค่าฟิลด์, ผู้ใช้
Action transition, assign, comment, แก้ฟิลด์, สร้าง sub-task, ส่ง Slack/อีเมล

ตัวอย่างที่ทีมใช้บ่อย

เมื่อ sub-task ทุกตัวเป็น Done → ย้าย parent ไป Done · เมื่อ issue ค้างใน In Review เกิน 2 วัน → แจ้ง reviewer · เมื่อ PR ถูก merge (webhook) → transition ไป Ready for QA

Plane CE มี automation เพียง auto-archive และ auto-close ตามเวลา; rule แบบ trigger-action เป็นรุ่นเสียเงิน (Pro+)
# Basic auth = email:API token (สร้างที่ id.atlassian.com)
curl -u "you@example.com:$JIRA_TOKEN" \
  -H "Content-Type: application/json" \
  -X POST "https://your-site.atlassian.net/rest/api/3/issue" \
  -d '{"fields":{"project":{"key":"PLAB"},
        "summary":"Build Docker image",
        "issuetype":{"name":"Task"}}}'

# อ่านด้วย JQL (แบ่งหน้าด้วย nextPageToken)
curl -u "you@example.com:$JIRA_TOKEN" \
  "https://your-site.atlassian.net/rest/api/3/search/jql?jql=project=PLAB"

# ย้ายสถานะ = POST transitions ไม่ใช่แก้ฟิลด์ status ตรง ๆ
curl -u "you@example.com:$JIRA_TOKEN" -X POST \
  ".../rest/api/3/issue/PLAB-12/transitions" -d '{"transition":{"id":"31"}}'

สามกราฟหลัก: Burndown · Cumulative Flow · Velocity และสูตรเบื้องหลัง

Burndown / Burn-up

Remaining(d) = Total − Σ Done(≤ d) · เส้น ideal = Total × (1 − d/D) — Plane ใช้สูตรเดียวกันจาก completed_at · Burn-up วาด Done สะสมกับเส้น scope แยกกัน จึงเห็น scope creep

Velocity

Velocity = Σ points ของงานที่ Done ใน sprint · ค่าเฉลี่ย 3 sprint ล่าสุดใช้พยากรณ์: sprint ที่เหลือ ≈ backlog points ÷ velocity เฉลี่ย

Cumulative flow (CFD)

แต่ละแถบ = จำนวนงานในสถานะนั้น ณ สิ้นวัน · ความสูงแถบ In Progress = WIP · ความกว้างแนวนอน ≈ lead time · แถบที่อ้วนขึ้นเรื่อย ๆ = คอขวด

Webhook = เครื่องมือ ยิงเหตุการณ์มาหาเรา — ต้องตรวจลายเซ็นก่อนเชื่อ

Jira

ลงทะเบียนใน Settings → System → Webhooks หรือผ่าน API · เลือก event (issue created / updated / deleted) และกรองด้วย JQL · payload มี issue + changelog

Trello

POST /1/webhooks ระบุ callbackURL + idModel · Trello ยิง HEAD ตรวจ URL ก่อน · header X-Trello-Webhook = base64(HMAC-SHA1(body + callbackURL))

Plane

Workspace settings → Webhooks · เลือก event project / issue / module / cycle / issue_comment · header X-Plane-Event, X-Plane-Delivery, X-Plane-Signature (HMAC-SHA256 hex ด้วย secret plane_wh_…) · retry 5 ครั้งแล้วปิดเอง · URL localhost ไม่ผ่าน · ส่งไม่สำเร็จ retry สูงสุด 5 ครั้ง (backoff 600 s + jitter) แล้วปิด webhook อัตโนมัติ · URL localhost ถูกปฏิเสธตอนบันทึก และ private IP ถูกบล็อกตอนส่ง (log 400 ไม่ retry) เว้นแต่ hostname อยู่ใน WEBHOOK_ALLOWED_HOSTS

# payload: event · action (create|update|delete) · webhook_id ·
#          workspace_slug · data · activity
import hmac, hashlib

def verify(secret: str, raw_body: bytes, sig: str) -> bool:
    # คำนวณจาก raw bytes ตรง ๆ — ห้าม json.loads แล้ว dumps ใหม่ (ลำดับ/ช่องว่างเปลี่ยน = ลายเซ็นไม่ตรง)
    mac = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(mac, sig)

# ใน hookwall receiver (stdlib http.server, LAB 8)
raw = self.rfile.read(int(self.headers["Content-Length"]))
ok = verify(SECRET, raw, self.headers.get("X-Plane-Signature", ""))
ทำไมต้องตรวจ — ใครก็ POST มาที่ URL เราได้; ลายเซ็นพิสูจน์ว่ามาจากระบบที่ถือ secret เดียวกัน และใช้ compare_digest กัน timing attack

ตอนที่ 4 · Product Tracking · API concepts

ห้าแนวคิด API ที่นักศึกษาต้องรู้ ก่อนเขียนสคริปต์ตัวแรก

  • Token — สร้างที่ Settings → Developer → Personal Access Tokens แสดงครั้งเดียวขึ้นต้น plane_api_ ตั้งวันหมดอายุได้ อย่า commit ลง git
  • Cursor pagination — วนจนกว่า next_page_results เป็น falseส่ง cursor=next_cursor ในหน้าถัดไป ไม่ใช่เลขหน้า
  • Rate limit 429 — 60 req/นาที ต่อ tokenอ่าน X-RateLimit-Remaining แล้วหยุดรอถึง X-RateLimit-Reset
  • Idempotency — ส่ง external_source + external_idรันซ้ำได้ 409 พร้อม id เดิม แทนที่จะสร้างซ้ำ
  • UUID vs human key — path ต้องใช้ UUID ของโปรเจกต์PLAB-12 ใช้ได้เฉพาะ GET workspaces/<ws>/work-items/PLAB-12/
import os, requests, time
BASE = "http://localhost:8080/api/v1"; WS = "devtools"
H = {"X-API-Key": os.environ["PLANE_TOKEN"]}   # token จาก env ไม่ hard-code
projs = requests.get(f"{BASE}/workspaces/{WS}/projects/", headers=H).json()
pid = [p["id"] for p in projs["results"] if p["identifier"] == "PLAB"][0]
url = f"{BASE}/workspaces/{WS}/projects/{pid}/work-items/"
card = {"id": "64f1c0de", "name": "Build image"}   # การ์ดจาก Trello export
while True:
    body = {"name": card["name"],
            "external_source": "trello", "external_id": card["id"]}
    r = requests.post(url, headers=H, json=body)
    if r.status_code != 429: break
    time.sleep(int(r.headers["X-RateLimit-Reset"]) - time.time() + 1)  # แล้วส่งซ้ำ
if r.status_code == 409: print("มีอยู่แล้ว", r.json()["id"])
cursor = None
while True:
    q = {"per_page": 50, "cursor": cursor}
    page = requests.get(url, headers=H, params=q).json()
    for it in page["results"]: print(it["sequence_id"], it["name"])
    if not page["next_page_results"]: break
    cursor = page["next_cursor"]
