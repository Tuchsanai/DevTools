Sprint Backlog — เป้าหมาย · งานที่เลือก · แผนการทำงาน

รายการ Product Backlog ที่เลือกมาทำใน Sprint รวมกับแผนว่าจะทำอย่างไร โดยทีมผู้พัฒนา (Developers) เป็นเจ้าของ และใช้ Sprint Goal เป็นทิศทางร่วม
สามส่วนที่ต้องแยกให้ออก: Product Backlog = งานทั้งหมด · Sprint Backlog = งานที่เลือกพร้อมแผน · Increment = งาน Done ที่ใช้ได้จริง

ทำไมสำคัญ · แก้ปัญหาอะไร

ก่อนมี Sprint Backlog สมาชิกหยิบงานคนละทิศและไม่รู้ว่า Sprint นี้ต้องพิสูจน์อะไร หลังวางแผน ทุกคนเห็นเป้าหมายเดียว ขอบเขตใกล้ตัว และลำดับการทำงานร่วมกัน

กลไก · Why → What → How

Why ตั้ง Sprint Goal · What Developers เลือกงานจากลำดับบน Product Backlog ตามกำลังของทีม · How แตกเป็น task และปรับแผนทุกวันเมื่อเรียนรู้เพิ่ม

CampusEats · Sprint นี้

Goal: “ล็อกอินและหาเมนูได้” · เลือกล็อกอิน รีเซ็ตรหัสผ่าน ค้นหาเมนู และตะกร้า รวม 19 points แล้วแตกแต่ละเรื่องเป็น API · UI · test; ตะกร้าที่ยังไม่ผ่าน DoD ไม่รวมใน Increment

ความเข้าใจผิด — ❌ “Sprint Backlog คือสัญญารายการงานที่ห้ามเปลี่ยน” → ✅ เป็นแผนของ Developers ที่ปรับรายละเอียดและลำดับได้ตลอด Sprint ตราบใดที่ไม่ทำลาย Sprint Goal

ใน Plane — work items ที่อยู่ใน Cycle คือ Sprint Backlog

Plane ใช้ Cycle แทน Sprint; เปิด Cycle แล้วเลือกงานเดิมจากโปรเจกต์เข้ามา โดยไม่ต้องสร้าง work item ซ้ำ
Active Cycle · โมดัล “Add existing work items” สำหรับเลือกงานจากโปรเจกต์เข้า Sprint Backlog

วิธีทำเลือกงานเข้า Sprint

Project › Cycles › Active Cycle › Add existing work items → เลือกงาน → Add selected work items; เก็บ Sprint Goal ใน description ของ Cycle

Plane เก็บความสัมพันธ์อย่างไร

ความสัมพันธ์อยู่ในตาราง cycle_issues; ถ้าใบอยู่ Cycle อื่น การเพิ่มจะย้ายแถวเดิมมายัง Cycle ใหม่—งานไม่ถูกทำสำเนา

เงื่อนไขใน CE v1.4.2

Cycles มีใน CE แต่ค่าเริ่มต้นปิด: เปิดที่ Project settings › Features › Cycles; Cycle ที่จบแล้วเพิ่มงานไม่ได้

LAB 4ลองทำ — เขียน Goal 1 ประโยค เลือก 3 ใบรวมไม่เกิน 10 points แล้วอธิบายว่าใบที่ตัดออกช่วยรักษา Goal อย่างไร
