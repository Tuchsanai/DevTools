ตอนที่ 3 · Epic · นิยาม

Epic คือกลุ่มงานข้าม Sprint — ต้องแตกเป็น Stories

Epic ช่วยเชื่อมภาพระดับ roadmap กับงานเล็กที่ทีมทำและส่งมอบได้จริงในแต่ละรอบ
Epic คือ กลุ่มงานขนาดใหญ่ที่มุ่งสู่ผลลัพธ์เดียวกัน มักกินเวลาหลาย Sprint และยังใหญ่เกินกว่าจะหยิบไปทำตรง ๆ จึงต้องแตกเป็น User Stories ที่ส่งมอบและตรวจสอบได้

ก่อนมี Epic

roadmap เขียนว่า “ระบบสั่งอาหาร” แต่ backlog มีงานย่อยกระจัดกระจาย ทีมและผู้มีส่วนได้เสียจึงไม่รู้ว่างานใดร่วมเป้าหมายเดียวกัน หรือภาพรวมไปถึงไหนแล้ว

หลังจัดเป็น Epic

รวม Stories ตามผลลัพธ์เดียว ตั้งผู้รับผิดชอบและช่วงเวลา แล้วอ่านความคืบหน้าระดับ roadmap ได้โดยไม่ต้องไล่เปิดงานทีละใบ

ทำไมสำคัญ — Epic ทำหน้าที่เป็น “กล่องติดตาม” ระหว่าง Product Goal กับ backlog: ผู้บริหารเห็นทิศทาง ส่วนทีมยังทำงานผ่าน Stories ขนาดเล็ก
ทีมจัดกลุ่มบัตรงานย่อยใต้หมุดหมายบน roadmap เพื่อเห็นทั้งลำดับเวลาและภาพรวมของผลลัพธ์

❌ Epic = งานชิ้นใหญ่ที่ส่งให้คนเดียวทำ

✅ Epic ไม่ใช่ใบงานสำหรับเริ่มลงมือทันที แต่เป็นกรอบรวมหลาย Stories; แต่ละ Story ต้องให้คุณค่า ตรวจรับได้ และเล็กพอจบใน Sprint

CampusEats — Epic “สั่งอาหารล่วงหน้า” อาจรวม Stories: ดูเมนู · เพิ่มอาหารลงตะกร้า · เลือกเวลารับ · ยืนยันคำสั่งซื้อ; ทีมทยอยส่งมอบคนละ Sprint แต่ทุกใบพาไปสู่ผลลัพธ์เดียวกัน

ตอนที่ 3 · Epic · กลไก

แตก Epic ให้ไหลสู่การส่งมอบ — Stories คือหน่วยความก้าวหน้า

อย่าวัด Epic ด้วยคำว่า “ทำไปประมาณกี่เปอร์เซ็นต์” จากความรู้สึก ให้วัดจาก Stories ที่ผ่านเกณฑ์ Done
Epic แตกเป็น Stories ที่ให้คุณค่า; Task/Subtask อธิบายวิธีทำ · ใน Plane CE ใช้ Module → Work item → Sub-work item

1Plan · ระบุผลลัพธ์

ตั้งชื่อ Epic จากผลลัพธ์ กำหนดขอบเขต เจ้าของ และช่วงเวลา แล้วแตกเป็น Stories ตามลำดับคุณค่าหรือความเสี่ยง

2Do · ส่งมอบข้าม Sprint

เลือก Stories เข้าแต่ละ Sprint; งานภายใน Story อาจแตกเป็น Task/Subtask แต่ Epic ไม่จำเป็นต้องจบในรอบเดียว

3Track · นับ Done

progress = Stories ที่ Done ÷ Stories ทั้งหมด เช่น 3/5 = 60%; เมื่อขอบเขตเพิ่ม ตัวส่วนเพิ่มและเปอร์เซ็นต์อาจลดลงได้

วงจรสถานะ — Planned → In progress → Completed ใช้สื่อว่ากลุ่มงานอยู่ช่วงใด; เปลี่ยนเป็น Completed เมื่อผลลัพธ์และ Stories ที่จำเป็นผ่านเกณฑ์รับงาน ไม่ใช่เพียงเพราะถึงกำหนดวัน

ตอนที่ 3 · Epic · ใน Plane

Plane CE ใช้ Module แทน Epic — รวม Work items แล้วติดตามภาพรวม

Module คือวัตถุที่ใกล้เคียง Epic ที่สุดใน Plane v1.4.2 CE; Epic แบบ work-item type ไม่มีหน้าจอจัดการในรุ่นนี้
หน้า Modules ของ Plane Lab: รายการหรือ Gallery แสดง Module พร้อมแถบ progress
หน้า Module detail: work items ของ Module และแผง progress ด้านข้าง

1สร้างกรอบ roadmap

เปิด Project settings › Features › Modules แล้วสร้าง Module พร้อม name · description · lead · members · start/target dates และ status

2ผูกงานและอ่าน progress

เพิ่ม Work items เข้า Module; งานหนึ่งใบอยู่ได้หลาย Modules ส่วน progress แยกจำนวนงานตาม state groups และ points เมื่อใช้ Estimate ระบบ Points

3รู้ข้อจำกัดของ CE

Module status มี backlog · planned · in-progress · paused · completed · cancelled และเป็นค่าที่ผู้ใช้กำหนดเอง—ไม่ได้เปลี่ยนตาม progress อัตโนมัติ

LAB 6 ลองทำ — สร้าง Module “Ordering — สั่งอาหารล่วงหน้า” ตั้ง lead และช่วงเวลา ผูก CampusEats Stories 4 ใบ แล้วตอบ: ถ้า Done 3 ใบจาก 4 ใบ progress ควรสื่ออะไร และเหตุใดจึงยังไม่ควรเปลี่ยน status เป็น Completed?
