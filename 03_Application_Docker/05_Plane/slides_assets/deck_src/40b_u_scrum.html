Scrum คือกรอบงานเบาสำหรับงานซับซ้อน — เรียนรู้ผ่าน Sprint สั้น ๆ

Scrum ไม่ใช่รายการพิธีประชุม แต่เป็นระบบที่ทำให้ทีมเห็นความจริง ตรวจผล และเปลี่ยนแผนจากหลักฐานได้เป็นรอบ
Scrum คือ lightweight framework ที่ให้ทีมจัดการปัญหาซับซ้อนด้วย 3 accountabilities · 5 events · 3 artifacts ภายใน Sprint เพื่อสร้าง Increment ที่มีคุณค่าและใช้งานได้

ก่อนมีกรอบร่วม

แต่ละคนเลือกงานและนิยามคำว่า “เสร็จ” เอง ปัญหาโผล่ตอนรวมงานปลายภาค และผู้ใช้เห็นของจริงเมื่อแก้ยากแล้ว

เมื่อใช้ Scrum

ทีมเลือกเป้าหมายหนึ่งรอบ วางแผนร่วมกัน ทำงานให้ Done ตรวจ Increment กับผู้ใช้ แล้วปรับทั้งผลิตภัณฑ์และวิธีทำงาน

ทำไมสำคัญ — งานซับซ้อนไม่มีแผนที่ถูกทั้งหมดตั้งแต่วันแรก Scrum จึงย่นระยะจาก “ตัดสินใจ” ถึง “เห็นผลจริง” และจำกัดความเสียหายเมื่อสมมติฐานผิด
บอร์ดทำให้งานเป็นภาพร่วม แต่คุณค่าของ Scrum เกิดจากการคุย ตัดสินใจ และปรับแผนของทั้งทีม

Scrum Team หนึ่งทีม 3 บทบาท · ไม่มีหัวหน้าย่อยในทีม

Scrum Guide 2020 เรียกว่า accountabilities — ทีมเดียว โดยทั่วไปไม่เกิน 10 คน ทำงานข้ามสายและจัดการตนเอง
บทบาทรับผิดชอบ (accountable for)สิ่งที่ "ไม่ใช่" หน้าที่
Product Owner
1 คน		ทำให้ผลิตภัณฑ์มีคุณค่าสูงสุด: กำหนด Product Goal, เขียนและสื่อสาร backlog items, จัดลำดับ Product Backlog ให้โปร่งใสไม่ใช่คนสั่งว่าใครทำอะไร ไม่ใช่ผู้จดความต้องการตามลูกค้าโดยไม่คัดกรอง และไม่ใช่คณะกรรมการ (ต้องเป็นคนเดียวที่ตัดสินใจได้)
Scrum Master
1 คน		ทำให้ Scrum เกิดผล: สอนและโค้ชทีม, ขจัดอุปสรรค, ดูแลให้อีเวนต์เกิดขึ้นในกรอบเวลา, ช่วย PO จัดการ backlogไม่ใช่ project manager, ไม่ใช่คนอัปเดตบอร์ดแทนทีม, ไม่ใช่คนรายงานความคืบหน้าให้ผู้บริหารแทนทีม
Developers

Sprintกรอบเวลาที่ครอบอีเวนต์อื่นทั้งหมด; เริ่ม sprint ใหม่ทันทีที่ sprint เดิมจบ; ระหว่าง sprint ห้ามเปลี่ยนแปลงที่กระทบ Sprint Goal≤ 1 เดือนCycle มีวันเริ่ม–วันจบ

3 อาร์ติแฟกต์ แต่ละชิ้นผูกกับ commitment หนึ่งข้อ

Scrum Guide 2020 เพิ่ม commitment เพื่อให้ทุกอาร์ติแฟกต์วัดได้ว่า "ดีพอหรือยัง" — และทั้งสามชิ้นต้องโปร่งใสต่อทุกคน

1Product Backlog ↔ Product Goal

รายการงานทั้งหมดที่จัดลำดับแล้ว มีเจ้าของคนเดียวคือ PO; Product Goal คือเป้าหมายระยะยาวที่ backlog ทุกข้อควรพาไปถึง — ข้อที่ไม่พาไปถึงควรถูกตัดออก

2Sprint Backlog ↔ Sprint Goal

ชุดงานที่ Developers เลือกมาทำใน sprint นี้ + แผนว่าจะทำอย่างไร; Sprint Goal คือประโยคเดียวที่บอกว่า sprint นี้ "สำเร็จ" หมายถึงอะไร แม้บางงานทำไม่เสร็จ

3Increment ↔ Definition of Done

ผลรวมของงานที่ Done ทั้งหมดจนถึงตอนนี้ ต้องใช้งานได้จริง; Definition of Done คือเช็กลิสต์คุณภาพที่ทุกงานต้องผ่านก่อนนับเป็น Done

Plane รองรับ Scrum ด้วย Cycle · Board · Page · Progress

Plane เก็บข้อมูลและทำให้ความคืบหน้ามองเห็นได้ แต่ทีมยังต้องกำหนด Sprint Goal, Definition of Done และใช้แต่ละ event ให้เกิดการตัดสินใจจริง
Sprint 2 ของโปรเจกต์ Plane Lab: แผง Progress ด้านขวาและกราฟ burndown โหมด Work items

Cycle = Sprint

เปิด Project settings › Features › Cycles แล้วสร้าง Cycle พร้อมวันเริ่ม–จบ; work items ใน Cycle คือ Sprint Backlog

Board = ภาพร่วมของ Daily

ใช้ Board layout · Group by State · กรอง Cycle ปัจจุบัน เพื่อเห็นงานที่ยังไม่เริ่ม กำลังทำ และเสร็จแล้ว

Page = ข้อตกลงและบทเรียน

เก็บ Definition of Done และบันทึก Review / Retrospective ใน Page ของโปรเจกต์; action item ควรสร้างเป็น work item

Progress ที่เห็น — ตัวนับใช้ state group; burndown ลดเมื่อ work item เข้ากลุ่ม completed และมี completed_at · CE ไม่มีหน้า Active Cycles ระดับ workspace จึงติดตามจากหน้า Cycles ของแต่ละโปรเจกต์
