ตอนที่ 3 · Agile · นิยาม

Agile คือการเรียนรู้เป็นรอบสั้น — ส่งมอบทีละส่วน ทดลอง แล้วปรับ

เป้าหมายไม่ใช่ “ทำให้เร็วตลอดเวลา” แต่คือค้นพบให้เร็วว่าสิ่งที่กำลังสร้างตอบโจทย์ผู้ใช้จริงหรือไม่
Agile คือการพัฒนาผลิตภัณฑ์แบบ iterative (ทำเป็นรอบ) และ incremental (ของที่ใช้ได้เพิ่มขึ้นทีละส่วน) โดยรับ feedback ทุก 1–4 สัปดาห์ แล้วนำสิ่งที่เรียนรู้ไปปรับรอบถัดไป

ก่อนใช้แนวคิดนี้

ทีมวางแผนและสร้างนานหลายเดือน ผู้ใช้เห็นของจริงตอนท้าย หากเข้าใจปัญหาผิด งานจำนวนมากต้องแก้ใหม่

เมื่อทำเป็นรอบสั้น

เลือกส่วนเล็กที่มีคุณค่า → สร้างและทดสอบ → ให้ผู้ใช้ลอง → ปรับ backlog ก่อนลงทุนกับส่วนต่อไป

ทำไมสำคัญ — ความต้องการเปลี่ยนได้ และทีมอาจเข้าใจผู้ใช้ผิดได้เสมอ รอบ feedback ที่สั้นจึงลด “เวลาที่เดินไปผิดทาง” และทำให้ตัดสินใจจากหลักฐานแทนการคาดเดา
การร่วมดูของที่ทดลองใช้ได้ ทำให้ feedback อ้างอิงสิ่งเดียวกัน ไม่ใช่ภาพในใจคนละแบบ

ตอนที่ 3 · Agile · ใน Plane

CampusEats บน Plane — Cycle ทำให้รอบเรียนรู้มองเห็นและติดตามได้

Plane ไม่ได้ “ทำให้ทีมเป็น Agile” โดยอัตโนมัติ แต่ช่วยเก็บ backlog งานของแต่ละรอบและสถานะไว้ในแหล่งข้อมูลเดียว
หน้า Cycles ของโปรเจกต์ Plane Lab (PLAB): Sprint 1 ที่จบแล้ว และ Sprint 2 ที่กำลังดำเนินอยู่
การแมปใน Plane CE — เปิด Project settings › Features › Cycles; work items ที่เลือกเข้ารอบเชื่อมผ่าน cycle_issues ส่วนสถานะ current / completed คำนวณจากวันที่ของ Cycle · หน้า Active Cycles ระดับ workspace ไม่เปิดใช้ใน CE

1เริ่มจากสมมติฐาน

ทีมเรียง backlog แล้วเลือก “นักศึกษาสั่งอาหารล่วงหน้าจากมือถือ” เข้า Sprint 1 เพื่อทดสอบว่าผู้ใช้ต้องการลดเวลารอรับอาหาร

2ส่งมอบและเรียนรู้

ทำ flow เลือกร้าน → เลือกเมนู → ยืนยันคำสั่งซื้อให้ใช้ได้ แล้วให้นักศึกษาลอง; feedback พบว่าต้องเห็น “เวลารับอาหาร” ก่อนยืนยัน

3ปรับรอบถัดไป

ทีมเพิ่มเรื่องเวลารับอาหารและจัดขึ้นบน backlog จากนั้นเลือกเข้า Sprint 2 แทนการเดินตามแผนเดิมทั้งก้อน

❌ Agile = ไม่ต้องวางแผน

✅ วางแผนบ่อยขึ้นและละเอียดเฉพาะสิ่งใกล้มือ; ส่วนไกลเก็บเป็น backlog ที่เปลี่ยนลำดับได้เมื่อมีข้อมูลใหม่

❌ Agile = ไม่ต้องมีเอกสาร

✅ ทำเอกสารเท่าที่ช่วยให้สร้าง ทดสอบ ใช้งาน และดูแล increment ได้; ไม่ใช้ปริมาณเอกสารแทนผลลัพธ์ที่ใช้งานได้

LAB 4 ลองทำ — เลือก CampusEats 3 work items สำหรับ Cycle 2 สัปดาห์ แล้วตอบ: จะสาธิต increment อะไรให้ผู้ใช้ลอง และ feedback แบบใดจะทำให้คุณเปลี่ยนลำดับ backlog?
