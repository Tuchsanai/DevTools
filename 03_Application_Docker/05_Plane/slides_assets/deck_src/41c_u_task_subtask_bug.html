งานย่อยกับข้อบกพร่อง — ชื่อคล้ายกัน แต่ตอบคนละคำถาม

Task / Subtask บอกว่า “ต้องลงมือทำอะไร” ส่วน Bug บอกว่า “ระบบจริงต่างจากสิ่งที่ควรเป็นอย่างไร”
Task คือขั้นตอนเชิงเทคนิคขนาดชั่วโมง–ไม่กี่วัน · Subtask คืองานลูกของ story หรือ task · Bug คือข้อบกพร่องที่ผลจริง (actual) ไม่ตรงกับผลที่คาด (expected) และต้องอธิบายวิธีทำให้เกิดซ้ำ
แนวคิดใช้เมื่อคำถามที่ต้องตอบ
Taskแปลง story เป็นงานลงมือทำใครทำอะไร และส่งมอบหลักฐานอะไร?
Subtasktask ยังใหญ่หรือมีหลายคนร่วมกันงานลูกนี้ขึ้นกับงานแม่ใด?
Bugพฤติกรรมที่สังเกตได้ผิดจากความคาดหมายทำซ้ำอย่างไร · ควรได้อะไร · ได้อะไรจริง?

ก่อนแยกให้ชัด

story ใหญ่ค้างอยู่ที่ “กำลังทำ” · งานซ้ำกัน · bug เขียนเพียง “ใช้ไม่ได้” จนผู้แก้ทำซ้ำไม่ได้

เมื่อแยกให้ชัด

เห็นขั้นลงมือ เจ้าของ และ dependency · defect มีหลักฐานพอให้ triage แก้ และทดสอบซ้ำได้

ความเข้าใจผิด — ❌ Bug คือ “ชั้นที่เล็กกว่า Subtask” → ✅ Bug เป็น ชนิดของปัญหา จึงอยู่ระดับ story หรือ task ก็ได้; Subtask ต่างหากที่ต้องมีงานแม่
Bug triage เริ่มจากดูหลักฐานร่วมกัน ไม่ใช่เดาว่าใครเป็นคนทำผิด

CampusEats · จาก story สู่สิ่งที่ทำได้

Story: นักศึกษาสั่งอาหารล่วงหน้าจากมือถือ · Task: สร้าง API รับคำสั่งซื้อ · Subtask: ตรวจเวลารับอาหาร · Bug: หน้าจอขึ้น “ยืนยันแล้ว” แต่ร้านไม่พบคำสั่งซื้อ

Plane CE ใช้ Work item เดียว — แยกความหมายด้วย parent · relation · label

Story, Task และ Bug ไม่ใช่ work-item type แยกกันใน Community Edition v1.4.2
Sub-work items ของงานแม่: รายการงานลูกและ progress x/y
Relations ของ work item: Blocked by / Blocking
Project settings › Labels: รายการ label รวม bug

Parent → Sub-work item

งานลูกเก็บ parent ที่ชี้ไปยัง work item แม่หนึ่งใบ จึงใช้แสดงโครงสร้างและความคืบหน้า

Relations → Dependency

ใช้ Blocking / Blocked by เมื่อสองงานขวางกัน แต่ไม่ได้เป็นส่วนย่อยของกันและกัน

Label + Priority + ID

สร้าง label bug; บันทึก severity ใน description และใช้ priority จัดลำดับแก้ · รหัส PLAB-… มาจาก project identifier + sequence_id ซึ่งไม่ถูกนำกลับมาใช้ซ้ำ
