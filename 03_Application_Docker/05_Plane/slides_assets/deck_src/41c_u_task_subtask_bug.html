งานย่อยกับข้อบกพร่อง — ชื่อคล้ายกัน แต่ตอบคนละคำถาม

Task / Subtask ตอบว่า “จะลงมือทำอะไรให้ story เสร็จ” ส่วน Bug ตอบว่า “ระบบจริงต่างจากสิ่งที่ควรเป็นตรงไหน”
นิยาม Task = ขั้นลงมือเชิงเทคนิคที่ทีมวางแผนเอง เล็กพอจะจบได้ราวหนึ่งวันหรือน้อยกว่า · Subtask = งานลูกที่แตกต่อจาก task/story เมื่อยังใหญ่หรือแบ่งกันทำหลายคน · Bug = ข้อบกพร่องที่พฤติกรรมจริง (actual) ต่างจากพฤติกรรมที่ควรเป็น (expected) และต้องบอกขั้นทำซ้ำได้Scrum Guide 2020 พูดถึงเพียงการแตกงานเป็นชิ้น “หนึ่งวันหรือน้อยกว่า” — Task · Subtask · Bug เป็นแนวปฏิบัติของทีม ไม่ใช่ artifact ของ Scrum
แนวคิดใช้เมื่อคำถามที่ใบนั้นต้องตอบให้ได้
Taskแปลง story เป็นขั้นลงมือทำใครทำอะไร · เสร็จแล้วเห็นหลักฐานอะไร?
Subtasktask ยังใหญ่หรือมีหลายคนทำงานลูกนี้อยู่ใต้งานแม่ใบใด?
Bugพฤติกรรมจริงต่างจากที่ตกลงไว้ทำซ้ำอย่างไร · ควรได้อะไร · ได้อะไรจริง?

ปัญหาที่แก้ · ก่อน

story ใบใหญ่ค้างที่ “In Progress” ทั้งสัปดาห์โดยไม่มีใครบอกได้ว่าเหลืออะไร · ใบ bug ชื่อ “แก้บั๊ก” ไม่มีขั้นทำซ้ำ ผู้แก้ต้องกลับไปถามผู้รายงานทุกครั้ง

ทำไมสำคัญ · หลัง

เห็นขั้นลงมือ เจ้าของ และลำดับก่อนหลัง · ความคืบหน้าอ่านเป็น x/y ได้ · defect มีหลักฐานพอให้แก้และทดสอบซ้ำ (lint ของ LAB 3: 8/25 → 13/25 เพราะแก้ใบเดียว)

ความเข้าใจผิด ① — ❌ “Bug คือชั้นที่เล็กกว่า Subtask” → ✅ Bug เป็น ชนิดของปัญหา ไม่ใช่ชั้นในลำดับ จึงอยู่ระดับ story หรือ task ก็ได้ และไม่ต้องมีงานแม่; Subtask ต่างหากที่นิยามด้วยการมีงานแม่เสมอ
Bug triage เริ่มจากดูหลักฐานร่วมกัน ไม่ใช่เดาว่าใครเป็นคนทำผิด

แตกงานให้ติดตามได้ — แล้วเขียน Bug ให้คนอื่นทำซ้ำได้

ลำดับชั้นอธิบาย “ส่วนประกอบของงาน”; bug report อธิบาย “หลักฐานของความผิดปกติ”
ซ้าย แนวคิด Agile: งานใหญ่ถูกแบ่งจนเล็กพอจะทำเสร็จได้ · เส้นประของ Bug = defect เกาะได้ทั้งระดับ story และ task · ขวา ชื่อเดียวกันนี้ใน Plane CE

Plane นำไปใช้อย่างไร · Parent

งานลูกคือ work item เต็มใบที่ตั้ง parent ชี้แม่ได้ ใบเดียว · ตัวนับ x/y Done นับเฉพาะลูกชั้นแรกที่อยู่กลุ่ม completed และ Plane ไม่ปิดใบแม่ให้เอง

ฟีเจอร์ที่เกี่ยวข้อง · Relations

UI มี 4 แบบ: Blocked by · Blocking · Relates to · Duplicate · ใส่ด้านเดียวพอ อีกใบเห็นคู่กลับเอง (PLAB-5 Blocked by PLAB-4 ⇒ PLAB-4 เห็น Blocking)

ข้อจำกัด CE · ชนิดงานและ severity

CE จัดการ work-item types ไม่ได้ จึงแยกชนิดด้วย label bug · ไม่มีช่อง severity ให้กรอก ต้องเขียนใน description แล้วใช้ priority จัดลำดับ

ความเข้าใจผิด ② — ❌ “ติ๊ก checkbox ในคำอธิบายก็ถือว่าแตกงานแล้ว” → ✅ checkbox ไม่มี state · assignee · เลขใบ และไม่นับใน x/y — งานที่ต้องมอบหมายหรือติดตามได้ ต้องเป็น sub-work item
LAB 3 แบบฝึกหัด / ทบทวน — สร้าง sub-work item 3 ใบใต้ PLAB-4 แล้วปิดใบแรก · แก้ใบ “แก้บั๊ก” เป็น “ตะกร้าคำนวณราคาผิดเมื่อมีโปรโมชันซ้อนกัน” พร้อม steps / expected / actual / environment / severity, label bug, priority Urgent แล้วตั้งเป็น Blocked by PLAB-4 · คำถาม: ตัวนับใต้ PLAB-4 อ่านว่าอะไร · PLAB-4 จะขึ้น relation ชื่อใด · เหตุใดคู่ bug–story นี้จึงไม่ควรใช้ parent?
