Issue คือ ใบงานหนึ่งใบที่มีเจ้าของ สถานะ และประวัติ

ไม่ใช่ข้อความว่า “ช่วยทำหน่อย” ที่ลอยอยู่ในแชท แต่เป็นบันทึกหนึ่งหน่วยที่ระบุงาน ผู้รับผิดชอบ ขั้นปัจจุบัน และร่องรอยการเปลี่ยนแปลงไว้ที่เดียว
นิยาม — “Issue คือบันทึกงานหนึ่งหน่วยที่ตอบได้ว่า ต้องทำอะไร · ใครรับผิดชอบ · ตอนนี้อยู่ขั้นไหน · เคยเปลี่ยนอะไรมาแล้วบ้าง”

ปัญหา · ก่อนมี tracker

คำขอกระจายอยู่ในแชท · อีเมล · สเปรดชีต บางเรื่องจึงถูกลืม สองคนแก้เรื่องเดียวกันโดยไม่รู้ตัว และคำถาม “ตอนนี้ใครทำอะไรถึงไหน” ต้องไล่ถามใหม่ทุกครั้ง

ผลลัพธ์ · เมื่อมี tracker

ทุกคนอ้างถึงใบเดียวกัน เห็นเจ้าของและสถานะล่าสุด อ่านเหตุผลของการตัดสินใจย้อนหลังได้จากประวัติ และใช้รายการเดียวเป็น single source of truth

ทำไมจึงสำคัญ — Issue tracking เปลี่ยนความจำของบุคคลให้เป็นความจำขององค์กร: ส่งต่องานได้ ตรวจสอบความรับผิดชอบได้ และเรื่องไม่สูญหายเมื่อคนออกจากห้องสนทนาหรือออกจากทีม
คำขอจากผู้ใช้กลายเป็นงานที่ติดตามได้เมื่อถูกบันทึกเป็น issue ไม่ใช่ค้างอยู่ในบทสนทนา

CampusEats: จาก “แก้บั๊ก” สู่ งานที่ทำซ้ำและพิสูจน์ผลได้

นำ PLAB-5 ของ LAB 3 (ใบที่มีแต่ชื่อว่า “แก้บั๊ก”) มาเดินตาม lifecycle จนกลายเป็นใบที่คนอื่นทำซ้ำ แก้ และตรวจผลได้เอง
ขั้นการตัดสินใจของทีมหลักฐานที่เพิ่มลง issueผลลัพธ์
1 · Reportนักศึกษาแจ้งว่ายอดรวมในตะกร้าผิดเมื่อใช้โปรโมชันซ้อนกันตั้งชื่อใหม่ให้บอกอาการ · ขั้นทำซ้ำ: ใส่อาหารลงตะกร้า → ใช้โปรโมชัน 2 รายการ → เทียบยอดจริงกับยอดที่ควรได้ · แนบภาพหน้าจอทีมทำซ้ำอาการเดียวกันได้
2 · Triageทำซ้ำได้และกระทบการชำระเงิน จึง รับเข้า (accept)Expected/Actual ชัดเจน · label bug · priority Urgent · assignee dev1 · due date +3 วันเข้าคิวงานจริงและมีเจ้าของ
3 · Fixแก้ logic คำนวณโปรโมชันซ้อนลิงก์ commit/PR · กรณีทดสอบครบ 10 กรณีพร้อม regression test · ย้าย In Progress → In Review (state ที่ทีมเพิ่มเองใน LAB 5)โค้ดและหลักฐานพร้อมตรวจ
4 · VerifyQA รันทดสอบ 10 กรณีซ้ำเกณฑ์การยอมรับผ่านทุกข้อ · automated test และ code review ตาม DoD ของทีมครบย้ายไป Done · ถ้าไม่ผ่านย้ายกลับ (reopen)

ความเข้าใจผิด 1 · ❌ “Issue แปลว่า bug”

✅ Issue คือหน่วยของงานทุกชนิด: feature · task · bug · research หรือคำขอ support ต่างกันที่เนื้อหาและป้ายกำกับ ไม่ใช่ต้องแยกไปใช้ tracker คนละระบบ

ความเข้าใจผิด 2 · ❌ “ย้ายเป็น Done แล้วถือว่าเสร็จ”

✅ Done ต้องผ่าน Definition of Done: เครื่องมือจดเวลาให้ (Plane ตั้ง completed_at เมื่อ state เข้ากลุ่ม completed) แต่ไม่ได้ตรวจแทนทีมว่าผลงานผ่านเกณฑ์จริง

หลักคิด — Issue ที่ดีทำให้คนซึ่งไม่ได้อยู่ตอนรับแจ้งทำซ้ำอาการ แก้ และตรวจผลได้เอง · ขั้น Triage คือ “การตัดสินใจของทีม” ไม่จำเป็นต้องใช้หน้า Intake ของ Plane — LAB 3 ตัดสินใจบนบอร์ดโดยตรง
