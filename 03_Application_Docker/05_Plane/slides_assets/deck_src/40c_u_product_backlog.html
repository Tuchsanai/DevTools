Product Backlog — รายการเดียว · เรียงลำดับ · มองทั้งผลิตภัณฑ์

ไม่ใช่รายการงานตายตัว แต่เป็นภาพรวมงานที่อาจจำเป็นเพื่อพาผลิตภัณฑ์ไปสู่ Product Goal
“Product Backlog คือรายการเดียวที่เรียงลำดับของทุกสิ่งที่ผลิตภัณฑ์อาจต้องมี โดย Product Owner รับผิดชอบให้รายการนี้ชัดเจนและมีลำดับ”

ก่อนมี Backlog

คำขอแยกอยู่ในแชต อีเมล และไฟล์หลายชุด แต่ละคนเลือกงานเอง จึงเกิดงานซ้ำ งานหล่น และไม่มีคำตอบว่า “ทำอะไรก่อน”

เมื่อมี Backlog

ทุกฝ่ายเห็นรายการเดียว ลำดับเดียว และเหตุผลเดียวกัน ทีมจึงใช้เวลาที่จำกัดกับงานซึ่งสำคัญต่อเป้าหมายมากที่สุด

CampusEats · ตัวอย่างจริง

PO รวม “สั่งอาหารล่วงหน้า”, “รีเซ็ตรหัสผ่าน”, “ค้นหาเมนู”, “ตะกร้า”, “จ่ายเงิน” และ “รีวิวร้าน” ไว้ในรายการเดียว แล้ววางงานที่ช่วยเป้าหมาย “สั่งอาหารในแคมปัสได้” ไว้ด้านบน

การจัดลำดับเป็นการตัดสินใจร่วมบนข้อมูลเดียว โดย Product Owner รับผิดชอบผลลัพธ์ของ Product Backlog
ความเข้าใจผิด — ❌ “อยู่ใน backlog = รับปากว่าจะทำทั้งหมด” → ✅ backlog คือชุดทางเลือกที่เปลี่ยนได้ งานล่างยังหยาบหรือถูกนำออกได้เมื่อเป้าหมายและข้อมูลเปลี่ยน

จากเป้าหมายสู่ Increment — เรียง · เตรียม · เลือก · ส่งมอบ · เรียนรู้

อ่านซ้าย→ขวา: รายการทั้งผลิตภัณฑ์ → งานที่ทีมเลือกพร้อมแผน → ของที่ผ่าน DoD และใช้งานได้

1ส่วนประกอบ

items = ความต้องการ งานแก้ และความรู้ที่ต้องหา · order = ก่อน–หลัง · Product Goal = เป้าหมายที่ผูกทุกชิ้นเข้าด้วยกัน

2กติกาการเรียง

ดูคุณค่าต่อผู้ใช้ ความเสี่ยง dependency และความพร้อม—not แค่ป้าย Urgent; งานบนต้องชัดและเล็กพอให้เลือกเข้า Sprint

3วงจรการทำงาน

PO เรียง → ทีม refine/estimate → Planning เลือก → ทำจนผ่าน DoD → Review → เพิ่ม ลบ หรือเรียง backlog ใหม่

DEEP — Detailed appropriately · Emergent · Estimated · Prioritized/ordered; Product Goal คือ commitment ของ Product Backlog

ใน Plane — Product Backlog คือ work items ของโปรเจกต์ที่ยังอยู่กลุ่ม backlog

ไม่มีกล่อง Product Backlog แยกต่างหาก: state group เป็นตัวบอกว่างานอยู่ช่วงใด และ sort_order เก็บลำดับแบบ manual
Plane Lab (PLAB) · Work items · List layout · Group by State — รายการงาน CampusEats ใน backlog

เปิดดูรายการ

เข้าโปรเจกต์ → Work items → เลือก List แล้ว Group by = State; state เริ่มต้น Backlog อยู่ใน group backlog

เรียงและช่วยตัดสินใจ

ลากงานเมื่อใช้ลำดับแบบ manual เพื่อเปลี่ยน sort_order; ใช้ priority urgent/high/medium/low/none และ filters ช่วยมอง—แต่ priority ไม่แทนลำดับเดียวของ PO

Related feature · Views

บันทึก filters, layout และ display properties เป็น View เพื่อเปิดมุม “งานพร้อมเข้า Sprint” ซ้ำได้ โดยไม่สร้าง backlog อีกชุด

ขอบเขตของ Plane CE v1.4.2 — ไม่มีพื้นที่ Product Backlog หรือฟิลด์ Product Goal โดยเฉพาะ: backlog คือ work items ใน state group backlog; ทีมจึงต้องเขียน Product Goal ไว้ใน Page ของโปรเจกต์แล้วใช้อ้างอิงตอนเรียงงาน
LAB 3–4 Mini exercise — จาก CampusEats 5 ใบ เลือก 3 ใบที่ช่วย Product Goal “สั่งอาหารล่วงหน้าได้ครบวงจร” มากที่สุด แล้วอธิบายเหตุผลของลำดับ 1→3; จากนั้นระบุว่าใบใดควรยังอยู่ Backlog และใบใดพร้อมเข้า Cycle
