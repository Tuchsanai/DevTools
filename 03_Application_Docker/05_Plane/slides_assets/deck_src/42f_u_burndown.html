Burndown คือกราฟ “งานคงเหลือเทียบกับเวลา”

แกนนอน = วันใน Sprint · แกนตั้ง = งานที่ยังไม่ Done · เส้น ideal เป็นเพียงแนวอ้างอิง ไม่ใช่คำสั่งว่าทีมต้องเดินตามทุกวัน
ทุกสิ้นวัน ถามเพียงว่า “เหลืองานอีกเท่าไร” แล้วพล็อตค่าลงกราฟ จึงเห็นความเสี่ยงของ Sprint ก่อนถึงวันสุดท้าย

ทำไมสำคัญ

ทีมเห็นแนวโน้มร่วมกันว่า Sprint Goal ยังมีโอกาสสำเร็จหรือไม่ และคุยเรื่องการแตกงาน ช่วยกันปิดงาน หรือลด scope ได้เร็ว

ปัญหาที่แก้

คำว่า “เสร็จ 80%” ตรวจสอบยากและมักค้างหลายวัน; burndown ลดเฉพาะเมื่อชิ้นงานผ่านเกณฑ์ Done จึงไม่ซ่อนงานเกือบเสร็จ

CampusEats — Sprint มี 40 points: ทีมทำโค้ดหน้าสั่งอาหารไปครึ่งหนึ่งแต่ยังไม่ผ่าน test ค่า remaining ยังเป็น 40; เมื่อ story 8 points ผ่าน Definition of Done จึงลดเหลือ 32
เข้าใจผิด — ❌ เส้นสูงกว่า ideal = ทีมล้มเหลว  →  ✅ กราฟคือสัญญาณให้ตรวจสาเหตุและปรับแผน ไม่ใช่คะแนนประเมินคน
ทีมใช้กราฟเพื่อถามหาความเสี่ยงและสิ่งกีดขวาง ไม่ใช่จับผิดรายบุคคล

อ่าน burndown ให้เป็น — ideal · actual · รูปแบบที่บอกปัญหา

อ่านฝั่งซ้าย: ideal ลดสม่ำเสมอ · actual ลดเป็นขั้นเมื่อมีงาน Done และกระโดดขึ้นเมื่อ scope เพิ่ม
  • องค์ประกอบแกนเวลา · หน่วยงาน (ใบหรือ points) · ideal · actual
  • วิธีทำงานเริ่มที่ total → ทุกวันหักเฉพาะงาน Done → สิ้น Sprint ควรเข้าใกล้ 0
  • ราบนานแล้วดิ่งงานใหญ่ หรือ review/test กองปลาย Sprint
  • กระโดดขึ้นscope เพิ่มกลาง Sprint; ถ้าไม่จดเหตุการณ์จะตีความว่า “ทีมช้า” ผิดสาเหตุ
  • เหนือ ideal ต่อเนื่องremaining ลดช้ากว่าแผน ควรตรวจ blocker และขนาดงาน
  • ต่ำกว่า idealเสร็จเร็วกว่าแนวอ้างอิง แต่ยังต้องตรวจคุณภาพตาม Definition of Done
workflow การอ่าน — ดู “รูปทรง” → หาเหตุการณ์จริงบนบอร์ด → คุยเหตุและทางเลือกกับทีม; อย่าสรุปจากเส้นเดียว เพราะ burndown ไม่บอกเองว่างานติดที่ใครหรือขั้นใด

Plane คำนวณ burndown จาก Cycle · completed_at · Estimates

Sprint 2 ในหน้า Cycles ของโปรเจกต์: แผง Progress และ burndown โหมด Work items
Cycle เดิมเมื่อสลับเป็น Estimates: เส้น remaining ใช้ผลรวม points

1เลือก Cycle

เปิด Cycle ที่มีวันเริ่ม–จบ; แผง Progress ของ active cycle แสดงความคืบหน้าและกราฟตามวันในช่วงนั้น

2เลือกหน่วย

Work items นับใบละ 1; Estimates รวม point และใช้ได้เมื่อระบบ estimate ของโปรเจกต์เป็นชนิด points

3อัปเดต Done

remaining(d) = total − Σ completed_at ≤ d; ย้ายเข้า state กลุ่ม completed แล้วเส้นลด ส่วน cancelled ไม่ถูกหักออก

ข้อควรระวัง — เปิดงานกลับจาก completed จะล้าง completed_at และงานกลับมาเป็น remaining; จึงต้องย้าย state ตามเหตุการณ์จริง ไม่ใช่ย้ายรวบยอดปลาย Sprint
