Compose เปลี่ยนแบบสถาปัตยกรรมให้รันได้ — 13 services · 10 volumes · 1 published port

docker-compose.yml บอกว่ารันอะไรและพึ่งใคร ส่วน plane.env ใส่ค่าที่เปลี่ยนไปตามเครื่อง
Plane CE v1.4.2 ประกาศ 13 services กับ 10 named volumes · ค่า ${VAR} ถูกแทนด้วยค่าจาก plane.env ตอน up · proxy เป็น service เดียวที่ publish พอร์ตออก host

Compose ทำงานอย่างไร

หนึ่ง service = หนึ่งหน้าที่ · depends_on จัดลำดับเริ่ม · named volume เก็บสถานะไว้นอกตัว container

ตัวอย่างจริง · เครื่องของทีม CampusEats

LAB 1 ตั้ง APP_DOMAIN/WEB_URL/CORS_ALLOWED_ORIGINS = localhost:8080 · ผลที่ต้องเห็น: 13 services · 10 volumes · 12 Up + migrator Exited (0)

ค่าที่พลาดแล้วเจ็บ

ความเข้าใจผิด — ❌ แก้ plane.env แล้ว restart ก็พอ → ✅ ต้อง up -d ให้สร้าง container ใหม่ · ❌ down = ข้อมูลหาย → ✅ มีแต่ down -v ที่ลบ volume

หยุดบริการอาการที่วัดได้จริงใน LAB 2
plane-dbหน้าเว็บและ /api/instances/ ยังตอบ 200 เพราะค่าอยู่ใน cache แต่ endpoint ที่อ่าน DB จริงตอบ 500 — readiness ที่ผ่าน cache จึงโกหกได้
plane-redis/api/instances/ ตอบ 500 ทันที ทุกหน้าจึงโหลดไม่ขึ้น และ live วน reconnect · แต่ยัง login อยู่ เพราะ session เก็บใน PostgreSQL
plane-mqงานเบื้องหลังไม่มีที่ส่ง · ถ้าบูต api ใหม่จะไม่ผ่านขั้น register_instance ที่ต้อง publish task เข้า broker
workerUI ยังลื่นและ CRUD ปกติ แต่ activity, notification, webhook, export กองในคิว celery · เปิดกลับมาแล้วระบายหมดในไม่กี่วินาที
plane-minioแนบไฟล์/ดาวน์โหลด/export ล้ม เพราะเบราว์เซอร์ POST ไฟล์ตรงไปที่ /uploads · แต่ api ยังบูตได้ตามปกติ
ฟีเจอร์ที่เกี่ยวข้อง · ภาพจริงใน Plane — /god-mode/ › Settings › General: ชื่อ instance DevTools Lab, อีเมลผู้ดูแล, Instance ID และสวิตช์ Telemetry
