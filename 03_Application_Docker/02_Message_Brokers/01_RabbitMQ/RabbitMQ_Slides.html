RabbitMQ และคำศัพท์หลัก

รู้จัก broker ที่เราจะใช้ และคำ 6 คำที่ต้องแม่นก่อนเขียนโค้ด — Message · Producer · Queue · Consumer · Broker · Connection/Channel
RabbitMQ · คำศัพท์หลัก

RabbitMQ คืออะไร?

RabbitMQ คือ message broker แบบ open-source ที่ใช้กันแพร่หลายที่สุดตัวหนึ่ง — ทำหน้าที่ รับ · เก็บ · ส่งต่อ ข้อความระหว่างโปรแกรม ผ่านโปรโตคอลมาตรฐาน AMQP

ทำงานเป็น "ที่ทำการไปรษณีย์"

โปรแกรมฝั่งส่งฝากข้อความแล้วไปทำอย่างอื่นต่อได้ — RabbitMQ รับและคัดเส้นทางตามกฎที่ตั้งไว้ ส่วนงานที่ต้องการยืนยันการรับจริงจะเพิ่ม publisher confirm ภายหลัง

คุยได้ทุกภาษา

Python · Java · Go · JavaScript ฯลฯ ต่อเข้า broker เดียวกันได้หมด — ในแล็บเราใช้ Python กับไลบรารี pika

มี Management UI ให้

หน้าเว็บดูสถานะ queue, อัตราการไหลของข้อความ และ consumer แบบเรียลไทม์ — ใช้ debug ได้ดีมาก

เขียนด้วย Erlang — ทนทานสูง รันเป็น container ได้ในคำสั่งเดียว ใช้จริงในระบบใหญ่ทั่วโลก
RabbitMQ · คำศัพท์หลัก

คำศัพท์ 6 คำที่ต้องแม่น

คำความหมายเทียบกับไปรษณีย์
Messageก้อนข้อมูลที่ส่งหากัน (ในแล็บคือข้อความสั้น ๆ / ในงานจริงมักเป็น JSON)จดหมาย
Producerโปรแกรมฝั่งส่ง — สร้างและส่ง messageคนส่งจดหมาย
Queueที่พัก message โดยพื้นฐานเรียงตามลำดับที่เข้า; หลาย consumer / requeue อาจทำให้ลำดับที่ประมวลผลเสร็จเปลี่ยนได้ตู้จดหมายของผู้รับ
Consumerโปรแกรมฝั่งรับ — รอรับ message จาก queue ไปประมวลผลคนเปิดตู้อ่านจดหมาย
Brokerเซิร์ฟเวอร์ตัวกลาง (RabbitMQ) ที่รับ เก็บ และส่งต่อให้ที่ทำการไปรษณีย์
Connection / Channelท่อ TCP ที่ต่อถึง broker / ช่องสื่อสารย่อยข้างในท่อถนนไปไปรษณีย์ / ช่องบริการ
Producer กับ Consumer ไม่เคยคุยกันตรง ๆ — ไม่รู้จักกัน ไม่ต้องออนไลน์พร้อมกันด้วยซ้ำ

Connection vs Channel

สองบรรทัดแรกของโค้ดทุกไฟล์ในแล็บ — ต้องรู้ว่ากำลังสร้างอะไร
  • Connection = ท่อ TCP จริง ๆสร้างแพง (จับมือ + ล็อกอิน) — เปิดครั้งเดียวใช้ยาว ๆ
  • Channel = ท่อย่อยในนั้นสร้างถูกและเร็ว — คำสั่งทุกอย่าง (ประกาศ queue, ส่ง, รับ) วิ่งผ่าน channel
connection = pika.BlockingConnection(...)
channel = connection.channel()

AMQP Model

ความจริงที่ซ่อนอยู่ : ข้อความไม่ได้ถูกส่ง "เข้า queue" ตรง ๆ — มันผ่าน Exchange เสมอ · Exchange · Binding · Routing Key
RabbitMQ · AMQP Model

เส้นทางจริงของ Message

Exchange = ด่านคัดแยก ตัดสินใจว่าข้อความใบนี้ควรไปเข้า queue ไหนบ้าง · Binding = กฎที่ผูก queue เข้ากับ exchange · Routing Key = ป้ายที่แปะบนข้อความ ใช้ประกอบการตัดสินใจ
RabbitMQ · AMQP Model

Exchange 3 ชนิดหลัก + default

ต่างกันที่ "ใช้อะไรตัดสินใจ" ว่าข้อความไปเข้า queue ไหน
ชนิดกติกาการส่งใช้เมื่อ
directส่งให้ queue ที่ binding key ตรงกับ routing key เป๊ะ ๆแยกงานตามประเภทชัด ๆ เช่น severity ของ log
fanoutสำเนาให้ทุก queue ที่ bind ไว้ — ไม่สน routing key เลยbroadcast — ประกาศให้ทุกระบบรู้พร้อมกัน
topicจับคู่ routing key กับ pattern (* = 1 คำ, # = กี่คำก็ได้ รวมศูนย์คำ)เลือกรับแบบยืดหยุ่น เช่น kern.*
default ("")direct พิเศษที่ RabbitMQ สร้างให้ — ทุก queue ถูก bind ด้วยชื่อของตัวเองอัตโนมัติส่งตรงถึง queue ตามชื่อ (LAB 1–2 ใช้ตัวนี้)
สามชนิดแรกคือหัวใจของ LAB 3–4 — เดี๋ยวดูภาพทีละชนิด (จริง ๆ ยังมีชนิด headers อีกแบบ — ไม่ใช้ในคอร์สนี้ แต่จะเห็นเป็น amq.match/amq.headers ตอนรัน rabbitmqctl list_exchanges)
