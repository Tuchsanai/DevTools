## 4. สถาปัตยกรรม — เปลี่ยนเป็น build pipeline ก่อนแตะเนื้อหา

เหตุผล: มี 4 agent ต้องแก้เนื้อหาพร้อมกันบนไฟล์เดียว 1.3 MB · และบทเรียนจากชุด Dockerfile คือ
**"อย่าแก้ไฟล์ deck ตรง ๆ"** (เคยโดน agent ลบบล็อก `<pre>` ทิ้งเงียบ ๆ และสลับ body ของสไลด์)

```
deck_build/
  _head.html        <!DOCTYPE> … </style></head><body><div id="stage">
  s0_open.html      ปก · overview · คำถามเดียว
  s1_customer.html  ตอนที่ 1
  s2_require.html   ตอนที่ 2
  s3_design.html    ตอนที่ 3
  s4_lab1.html      ตอนที่ 4
  s5_lab2.html      ตอนที่ 5
  s6_lab3.html      ตอนที่ 6
  s7_lab4.html      ตอนที่ 7
  s8_lab5.html      ตอนที่ 8
  s9_summary.html   ตอนที่ 9
  _tail.html        </div> … ctl/ov/help … <script id="assets"> … นำทาง
  build_deck.py     ประกอบ → ../Fullstack_App_Example.html แล้วเรียก embed_slide_assets.py
  CHANGELOG_v3.md   บันทึกทุกบล็อกที่ตัด/ย้าย/แตก
```

**ด่านความปลอดภัยที่ต้องผ่านก่อนเริ่มแก้เนื้อหา:**
`build_deck.py` ที่ประกอบจาก part ปัจจุบัน ต้องได้ไฟล์ **byte-identical** กับ `Fullstack_App_Example.html` วันนี้
(round-trip identity test) ถ้าไม่ identical = pipeline ผิด ห้ามเดินต่อ

เลขหน้าและหน้า Overview คำนวณจาก JS ตอน runtime (`slots.length` + `data-sec`) อยู่แล้ว
→ **แตกสไลด์เพิ่มได้โดยไม่ต้องไล่แก้เลขหน้า** แต่ `verify_slides.py` ที่ hardcode `EXPECTED_SLIDES=60` ต้องแก้
