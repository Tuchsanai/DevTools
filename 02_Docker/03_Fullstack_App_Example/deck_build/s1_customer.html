หัวหน้าสำนักงาน

"ปัญหาใหญ่สุดคือ ของหาย ครับ ไม่ใช่ของหายจริง ๆ นะ แต่คือ เรื่อง หาย
อาจารย์ทักในไลน์กลุ่มตอนสามทุ่ม พอเช้ามาข้อความมันเลื่อนขึ้นไปแล้ว ผมก็ลืมจด งานก็ค้าง
อาจารย์ก็มาถามอีกทีตอนสองอาทิตย์ผ่านไป ว่าเรื่องที่แจ้งไปถึงไหนแล้ว ผมตอบไม่ได้" → กลายเป็น US-1 · REQ-01
"ผมไม่รู้ว่างานไหนค้างอยู่กี่วัน สมุดผมมีแต่วันที่รับเรื่อง ไม่มีวันที่ปิดงาน เวลาผู้บริหารถามว่าเดือนนี้ซ่อมไปกี่งาน ค้างกี่งาน ผมต้องนั่งนับเอง ใช้เวลาครึ่งวัน" → กลายเป็น US-5 · REQ-08 · REQ-09
"ผมอยากเห็นหน้าจอเดียวที่บอกว่า ตอนนี้มีงานอะไรอยู่ในมือใครบ้าง แค่นั้นพอ" → กลายเป็น US-2 · REQ-02 · REQ-03 · REQ-04
ประโยคของลูกค้าคือ หลักฐาน ของทุกข้อกำหนด — ข้อไหนชี้กลับมาที่ประโยคจริงไม่ได้ แปลว่าเราคิดเอง ต้องตัดทิ้งหรือกลับไปถาม

ช่างซ่อมบำรุง และ เจ้าหน้าที่พัสดุ

"ผมอยากรู้ว่างานไหนเป็นของผม ไม่ใช่ต้องเดินมาถามหัวหน้าทุกเช้า แล้วเวลาซ่อมเสร็จ ผมอยากกดปิดงานได้เลยตรงนั้น ไม่ต้องกลับมาบอกที่สำนักงาน" ช่างซ่อมบำรุง → US-3 · REQ-04
"เรื่องอะไหล่ ผมยอมรับว่าบางทีก็ลืมบอกพัสดุจริง ๆ ครับ มือเปื้อนอยู่ ซ่อมเสร็จก็ไปงานต่อ ถ้ามันบันทึกตอนปิดงานได้เลยว่างานนี้ใช้อะไหล่อะไรไปบ้าง ก็จะดีมาก" ช่างซ่อมบำรุง → US-4 · REQ-05 · REQ-07
"สมุดยืม-คืนคือฝันร้ายค่ะ คนมายืมโปรเจกเตอร์ตัวเดิม วันเดียวกัน สองคน … พอคนแรกมาถึงก็ไม่มีของ ทะเลาะกันหน้าเคาน์เตอร์มาสองรอบแล้ว" เจ้าหน้าที่พัสดุ → US-6 · REQ-10 · REQ-11
"แล้วก็ อะไหล่หมดโดยไม่รู้ตัว ค่ะ กว่าจะรู้ว่าหลอดโปรเจกเตอร์หมดก็คือตอนช่างมาขอ ถ้ามีตัวเลขบอกว่าเหลือเท่าไหร่ แล้วเตือนตอนใกล้หมด จะสั่งซื้อทันเวลา" เจ้าหน้าที่พัสดุ → US-7 · REQ-06 · REQ-12

ข้อจำกัด 3 ข้อ — และเหตุผลที่ระบบนี้ต้องมาในรูปของ container

เรื่องสิ่งที่ลูกค้าพูดแปลว่า Docker ต้องรับหน้าที่อะไร
งบประมาณไม่มีงบเช่า cloud — ต้องรันบนเครื่องที่คณะมีอยู่ทั้งระบบต้องอยู่บน เครื่องเดียว ได้จริง
คนดูแลไม่มีฝ่าย IT ประจำ — ติดตั้งต้องง่าย ย้ายเครื่องต้องได้image + compose.yaml ไฟล์เดียว → NFR-1
ข้อมูลข้อมูลยืม-คืนย้อนหลัง ห้ามหาย แม้ต้องย้ายเครื่องหรือ restartnamed volume → NFR-2

"ใช้บนคอมที่สำนักงานพอ" — เจ้าหน้าที่พัสดุ
