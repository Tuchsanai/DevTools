## งานที่ต้องทำ

### G1 · หลักฐานจำนวน `[PASS]` (ทำก่อนเป็นอย่างแรก)
clone ชุดจาก GitHub ลงกล่อง แล้วรัน **หนึ่งครั้ง** ในโฟลเดอร์แล็บตัวเอง
```
bash verify.sh ; echo "exit code = $?"
```
- LAB 5 ให้รัน **โดยไม่ตั้ง `HUB_USER`** (เส้นทางปกติของผู้เรียน) — ผลที่คาดคือมี `[SKIP]` หนึ่งบรรทัด
- นับบรรทัด `[PASS]` ที่ได้จริง แล้วเขียนไฟล์ `logs/verify_counts/lab<N>.json`
  ```json
  {"lab": <N>, "pass": <จำนวนจริง>, "skip": <จำนวนจริง>, "exit": <exit code>, "all_checks_passed": true|false}
  ```
- เก็บ output เต็มไว้ที่ `logs/u-d6-lab<N>.log`
- **ถ้า verify.sh ไม่ผ่าน ห้ามแก้ verify.sh ให้ผ่าน** — ให้รายงาน root cause กลับมา แล้วหยุด

### G2 · ตัวเลขในไฟล์ต้องเป็นความจริง
- **จำนวนการทดลอง** = นับหัวข้อ `การทดลองที่ N` ในไฟล์ตัวเอง (ค่าจริง: LAB1=10 · LAB2=11 · LAB3=9 · LAB4=9 · LAB5=9)
- แก้ทุกที่ในไฟล์ตัวเองที่เขียนตัวเลขนี้ไว้ผิด
- **จำนวน `[PASS]`** ในไฟล์ตัวเองต้องตรงกับ `logs/verify_counts/lab<N>.json` ที่เพิ่งวัดได้
- **เวลา** ที่เขียนในไฟล์ตัวเองคือค่าจริง — ห้ามแก้ให้ตรงกับ root readme (root จะถูกแก้ตามทีหลัง) แต่ให้**รายงานค่าที่ถูกต้อง**กลับมา

### G3 · หนึ่งคำสั่งต่อหนึ่งบรรทัด
แยกบรรทัดที่อัดหลายคำสั่งด้วย `&&` **เฉพาะคำสั่งที่ผู้เรียนพิมพ์เองใน fenced ```bash``` เท่านั้น**

**ห้ามแตะ** (ไม่ใช่คำสั่งของผู้เรียน):
- `RUN ... && ...` ใน Dockerfile — เป็นคำสั่งเดียวโดยเจตนา
- บรรทัดที่เป็น *ผลรัน* (build log, `docker history` output)

รูปแบบที่ถูก:
```bash
mkdir -p ~/labwork
cd ~/labwork
```
คำสั่งเดียวที่ยาวใช้ `\` ต่อบรรทัดได้ตามเดิม

### G4 · ทุกการทดลองต้องมี `✅`
ทุกหัวข้อ `การทดลองที่ N` ต้องมี `✅` อย่างน้อยหนึ่งจุด **ก่อน**หัวข้อถัดไป
(ไม่ใช่ทุก code block — block ที่เป็น output / source / config ไม่ต้องมี)

### G5 · caption ของภาพ
census ภาพ **ทุกใบ** ในโฟลเดอร์ `images/` ของแล็บตัวเอง — ทุกใบต้อง
- ถูกอ้างในเอกสารด้วยลิงก์ที่ไม่เสีย · มี caption ใต้ภาพ
- caption **ระบุหลักฐานที่ต้องเห็นในภาพ** และ **ใส่ตัวเลขจริงเมื่อภาพมีตัวเลข**
- **ภาพหน้าจอ UI (`ui-*.png`) ต้องเป็น 1440×900**
  · **แผนภาพทฤษฎี (`theory-*.svg` / `theory-*.png`) ให้คงสัดส่วนเดิม ห้ามยืดหรือเติมแถบว่างให้เป็น 1440×900**
ถ้ามีภาพที่ไม่ถูกอ้างถึงเลย ให้รายงาน อย่าเพิ่งลบ

### G6 · ห้ามมี
- หัวข้อ "ทำให้พัง" (error ต้องอยู่ในตาราง "แก้ปัญหาที่พบบ่อย")
- ชื่อบัญชี Docker Hub จริง · อีเมลจริง · token จริง → ใช้ `<DOCKER_USER>` `<DOCKER_TOKEN>`
  (**ยกเว้น** ชื่อเจ้าของ repo สาธารณะบน GitHub ซึ่งผู้เรียนต้องใช้ clone จริง — เก็บไว้ตามเดิม)
- คำสั่งตรวจสอบที่ยาวเกินจำเป็น: `--format` · `grep -q` · `awk/jq/cut/tr` ที่ไม่ใช่หัวใจแล็บ

## สิ่งที่ห้ามทำเด็ดขาด
- ห้ามเพิ่ม/ลด/สลับลำดับ "การทดลอง" — รอบนี้คือกวาดให้ตรงมาตรฐาน ไม่ใช่เขียนแล็บใหม่
- ห้ามแก้ `verify.sh` ให้ผ่าน
- ห้ามแต่งผลรันขึ้นเอง — ทุก `✅` ต้องมาจาก log จริงในรอบนี้หรือของเดิมที่ยังตรง
- ห้ามลบ container/image/volume ที่ไม่ได้ขึ้นต้นด้วยชื่อของ unit ตัวเอง
