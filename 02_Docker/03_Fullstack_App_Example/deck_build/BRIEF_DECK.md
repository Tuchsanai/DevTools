> **ห้ามทิ้งข้อมูล** — ทุกบล็อกที่ตัดออกต้องบันทึกใน `deck_build/COVERAGE.md` ว่าย้ายไปไหน

## วิธีทำงาน

```
# 1) แก้เฉพาะไฟล์ part ของ unit ตัวเอง
# 2) ประกอบไปไฟล์ชั่วคราว (ห้ามเขียนทับเด็คตัวจริง)
python3 deck_build/build_deck.py --output /tmp/<unit>.html

# 3) ตรวจ
python3 tools/ui/check_deck.py --deck /tmp/<unit>.html --report     # ดูตัวเลขทุกหน้า

```

**ห้ามรัน `python3 deck_build/build_deck.py` เปล่า ๆ** เพราะจะเขียนทับเด็คตัวจริงที่ U-D7 เป็นเจ้าของ

## เกณฑ์ที่ต้องผ่าน (gate ตรวจให้อัตโนมัติ)

| กฎ | เกณฑ์ |
|---|---|
| prose ต่อสไลด์ | ≤ **800** ตัวอักษร (ไม่นับข้อความใน `<svg>` · eyebrow · footer) |
| code ที่แสดง | ≤ **14** บรรทัดที่ render จริง รวมทุก `<pre>` ในหน้า |
| แถวตาราง | ≤ **13** แถว รวมทุกตารางในหน้า |
| ฟอนต์เล็กสุด | ≥ **12.0px** — **ห้ามย่อฟอนต์เพื่อยัดเนื้อหา** ให้แตกหน้าแทน |
| ของหนัก | ≤ **1** ชิ้น {svg diagram · รูป · `pre` > 6 บรรทัด · ตาราง > 4 แถว} |
| ไม่ล้นกรอบ | บังคับ |
| ตัวอักษรรวมทั้งเด็ค | ≤ 40,050 (baseline 36,409) — **ห้ามเขียนเพิ่ม รอบนี้คือย้ายและตัด** |

**ข้อยกเว้นที่ใช้ได้**
- สไลด์เปรียบเทียบ before/after หรือ command/output ที่มีคุณค่าทางการสอน ใส่ `class="slide cmp"`
  → ให้ของหนัก 2 ชิ้นได้ ถ้า **ชนิดเดียวกัน** และ **ชิ้นละ ≤ 8 บรรทัด**
- ถ้าจำเป็นต้องเกินงบจริง ๆ ใส่ `data-waiver="เหตุผลสั้น ๆ"` ที่ `<section>` **และต้องขึ้นทะเบียนใน `COVERAGE.md`**
  ใช้ให้น้อยที่สุด · U-D7 เป็นผู้อนุมัติหรือปฏิเสธ

## รูปแบบสไลด์ที่ต้องรักษา

```html
<!-- ===== 0 : ชื่อสั้น ๆ ===== -->
<div class="slot">                        <!-- ใส่ data-sec="N" เฉพาะแผ่นแรกของตอน -->
<section class="slide">
  <div class="s-head">
    <div class="eyebrow">ตอนที่ 5 · ทฤษฎี · layer cache</div>
    <h2>หัวข้อที่เป็น <em>ข้อสรุป</em> ไม่ใช่ชื่อหัวข้อลอย ๆ</h2>
  </div>
  <div class="s-body"> … </div>
  <div class="s-foot"><span>ตอนที่ 5 · LAB 2 · REQ-01</span><span class="pg"></span></div>
</section>
</div>
```
- เลข `<!-- ===== N -->` ไม่ต้องไล่เอง `build_deck.py` เรียงให้ · เลขหน้าใน `.pg` JS เติมให้
- **eyebrow ต้องขึ้นต้นด้วย `ตอนที่ N ·` และมีคำใดคำหนึ่งใน `ทฤษฎี` `ลงมือ` `หลักฐาน`**
  - `ทฤษฎี` = อธิบายกลไก (แผนภาพ · เหตุผล)  · `ลงมือ` = คำสั่งที่ผู้เรียนพิมพ์  · `หลักฐาน` = ผลรัน/ภาพหน้าจอจริง
- ใช้คลาสที่มีอยู่แล้วใน CSS เท่านั้น (`card` `grid2` `grid3` `g11` `g21` `bul` `code` `tbl` `note` `fig` …)
  ต้องการคลาสใหม่ให้ **ขอมา อย่าแก้ `_head.html` เอง** · ปรับเล็กน้อยใช้ `style=""` inline ได้

## ข้อห้ามเด็ดขาด

- **ตัวเลขในเด็คต้องตรงกับแล็บ** — gate มี `check_stale_sizes` ที่จับตัวเลขขนาดในเด็คที่หาไม่เจอในแล็บ/เอกสาร
  ที่ค้างอยู่ตอนนี้ **7 ตัว ต้องแก้ให้ตรงกับ readme ของแล็บ**:
  `49.7 MB` → `49.9 MB` · `680 kB` / `680kB` → `668 kB` / `668kB` · `49.7MB` → `49.9MB` ·
  `35 kB` → `21048 ไบต์` · `73.2MB` และ `310MB` → ใช้ค่าจาก `003_LAB_Build_The_Web/readme.md` เท่านั้น
- **ห้ามแต่งตัวเลข ผลรัน ชื่อไฟล์ หรือคำสั่งขึ้นเอง** — ทุกอย่างที่คงไว้ต้องคัดลอกจากเด็คเดิม
  หรือจาก `readme.md` ของแล็บ (gate มี fidelity check ที่จะจับได้)
- ห้ามแตะไฟล์ part ของ unit อื่น · `_head.html` · `_tail.html` · `build_deck.py` · `Fullstack_App_Example.html`
- ห้ามสลับเนื้อหาระหว่างสไลด์ — หัวข้อกับเนื้อหาต้องตรงกันเสมอ
- ห้ามย้ายข้อความหนีเข้าไปใน `<svg>` เพื่อเลี่ยง gate
- ห้ามลด `font-size` ลงต่ำกว่า 12px
- ห้ามใส่ชื่อบัญชี Docker Hub จริง อีเมลจริง หรือ token จริง
- **ห้ามใช้คำสั่งตรวจสอบที่ยาวเกินจำเป็นในสไลด์** — ที่พบแล้วต้องแก้:
  - หน้า 33 `docker build -t ops-api:1.0 . 2>&1 | grep -A2 "load build context"` → ใช้ `docker build -t ops-api:1.0 .` แล้วชี้บรรทัดที่ต้องดู
  - หน้า 36 `curl … | python3 -c 'import sys,json …'` → ตัดบล็อกนี้ทิ้ง เหลือ pointer ไป readme
