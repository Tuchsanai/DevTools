เราต่อกล่องกันด้วย IP — และ IP ไม่ใช่ของที่ใครจองไว้

-e DATABASE_URL="postgresql://opsuser:labpass@$(docker inspect -f '…' ops-db):5432/campusops"
IP เป็นเลขที่ Docker แจกตามลำดับที่กล่องเข้ามาอยู่บน network — พอฐานข้อมูลถูกสร้างใหม่ เลขก็เปลี่ยน คำสั่งที่จดไว้เมื่อวานก็ใช้ไม่ได้อีก

default bridge ไม่มี DNS · user-defined network มีให้ในตัว

# บน default bridge : DATABASE_URL ใช้ชื่อ ops-db
[api] รอฐานข้อมูลไม่สำเร็จ: [Errno -2] Name or service not known → HTTP 503
# คำสั่งเดิมเป๊ะ ต่างแค่ --network ops-net
$ docker exec ops-api getent hosts ops-db
172.19.0.2      ops-db   # ตรงกับ docker inspect ของ ops-db
ยกใหม่โดยสลับลำดับ (api ก่อน db) แล้ว getent hosts ops-db ได้ 172.19.0.3 ซึ่งเป็นเลขใหม่ — แต่ /health ยังตอบ db up เพราะไม่มีใครจดเลขไว้เลย

NFR-3 ผ่านเพราะเรา ไม่พิมพ์ -p ไม่ใช่เพราะตั้งค่าอะไรเพิ่ม

$ docker port ops-db → (ว่างเปล่า = ไม่มีพอร์ตถูก publish)
$ curl -sS -m 5 http://localhost:5432 → curl: (7) exit = 7
$ docker ps --filter name=ops- --format 'table {{.Names}}\t{{.Ports}}'
ops-web   0.0.0.0:3000->3000/tcp, [::]:3000->3000/tcp
ops-db    5432/tcp        ops-api   8000/tcp
5432/tcp ในตารางคือป้าย EXPOSE ของ image ไม่ใช่ประตูที่เปิดจริง · ประตูจริงต้องมี 0.0.0.0:…-> — ไม่ต้องตั้ง firewall เลยสักบรรทัด

สายที่เป็น ชื่อล้วน ๆ : browser → web → ops-api → ops-db

docker run -d --name ops-web --network ops-net -p 3000:3000 \
  -e API_BASE_URL="http://ops-api:8000" campusops-web:lab4
GET /        -> HTTP 200 · 31260 ไบต์
GET /tickets -> HTTP 200 · 71881 ไบต์
GET /loans   -> HTTP 200 · 46734 ไบต์
GET /parts   -> HTTP 200 · 70876 ไบต์
ทุกหน้าเรนเดอร์ฝั่ง server — ถ้า DNS ของ ops-net ไม่ทำงาน หน้านี้ขึ้น error ทันที ตัวเลขบนการ์ดจึงเป็นหลักฐานว่าสายทั้งเส้นวิ่งด้วยชื่อจริง
$ docker exec ops-tools getent hosts ops-db
ก่อน connect : exit = 2
$ docker network connect ops-net ops-tools
$ docker exec ops-tools psql "postgresql://…@ops-db:5432/…"
     8   # ต่อด้วยชื่อได้ทันที ไม่ต้องสร้างกล่องใหม่
