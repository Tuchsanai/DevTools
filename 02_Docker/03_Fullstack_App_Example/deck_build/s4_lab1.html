แก้ความเข้าใจ 3 ข้อ ก่อนเปิดกล่องเรียน

สิ่งที่มักเข้าใจผิด

  • คิดว่า ไม่ใส่ POSTGRES_PASSWORD ก็รันได้จริง ๆ กล่องหยุดทันทีตั้งแต่วินาทีแรก
  • คิดว่า ลบกล่องแล้วข้อมูลยังอยู่ เพราะ image ยังอยู่จริง ๆ ข้อมูลอยู่ใน writable layer ที่ตายพร้อมกล่อง
  • คิดว่า แก้ไฟล์ใน db/initdb/ แล้วสร้างกล่องใหม่มีผลเสมอจริง ๆ ถูกข้ามทันทีที่ volume ไม่ว่าง

พิมพ์บนเครื่องของเราเอง

docker rm -f devtools-fs-lab1 2>/dev/null
docker run -dit --name devtools-fs-lab1 --privileged \
  -p 2251:22 tuchsanai/devtools:2569_1
ssh root@localhost -p 2251        # password : passwd
แล็บนี้ ไม่ต้องเปิดพอร์ตแอปเลย เพราะเราคุยกับฐานข้อมูลผ่าน docker exec ทั้งหมด

ข้อมูลของ PostgreSQL ไปนอนอยู่ที่ไหน

ฝั่งซ้ายกล่องหายแล้วข้อมูลหายด้วย เพราะข้อมูลอยู่ในตัวกล่อง · ฝั่งขวาข้อมูลไม่เคยอยู่ในกล่องตั้งแต่แรก — ต่างกันแค่บรรทัดเดียวคือ -v ops-pgdata:/var/lib/postgresql/data

ส่งค่าครบแล้ว ฐานข้อมูลขึ้นโดยไม่เปิดพอร์ต

docker run -d --name ops-db \
  -e POSTGRES_DB=campusops -e POSTGRES_USER=opsuser \
  -e POSTGRES_PASSWORD=labpass \
  -v "$PWD/db/initdb:/docker-entrypoint-initdb.d:ro" \
  postgres:17-alpine

ops-db    postgres:17-alpine   Up 8 seconds   5432/tcp

มี volume เพียงบรรทัดเดียวก็ทำให้ ใบที่ 9 รอด

ทั้งสองฝั่งใช้คำสั่งเดียวกันทุกตัวอักษร ต่างกัน บรรทัดเดียว
ไม่มี volume
count 9
$ docker rm -f ops-db
count 8
ใบที่ 9 หายถาวร · เลข 8 ที่กลับมาไม่ใช่ข้อมูลเดิม แต่เป็น seed ที่ init script ใส่ให้ใหม่ทั้งชุด
มี named volume
-v ops-pgdata:/var/lib/postgresql/data
$ docker rm -f ops-db
 id | title | status
  9 | ไมโครโฟน… | NEW
ใบที่ 9 ยังอยู่ — บรรทัดเดียวนี้เปลี่ยนคำตอบของ NFR-2 ทั้งข้อ

ตัวตัดสินคือ data directory ว่างหรือไม่ ไม่ใช่ "กล่องใหม่หรือเก่า" — แก้ db/initdb/*.sql ทีหลังจึงไม่มีผล จนกว่าจะลบ volume ทิ้ง
