ใน 10 คำสั่ง มีเพียง 6 คำสั่งสร้าง layer

FROM python:3.12-slim
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY main.py .
RUN useradd --create-home --uid 10001 appuser \
    && chown -R appuser:appuser /app
USER appuser
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
FROM · WORKDIR · COPY · RUN ทำให้เห็น [1/6]–[6/6] · ENV · USER · EXPOSE · CMD เขียน metadata

ผล build ยืนยัน 6 layer และ context 28.54kB

#7 transferring context: 28.54kB done
#6 [1/6] FROM docker.io/library/python:3.12-slim
#8 [2/6] WORKDIR /app
#9 [3/6] COPY requirements.txt .
#10 [4/6] RUN pip install --no-cache-dir -r requirements.txt

[4/6] = ขั้นที่ 4 จาก 6 ขั้นที่สร้าง layer · 28.54kB คือ context ที่ส่งจริง ไม่ใช่ขนาด image
คำสั่งที่ไม่สร้าง layer: ENV · USER · EXPOSE · CMD

จุด . ท้ายคำสั่ง docker build ไม่ใช่ ที่อยู่ของ Dockerfile

. คือโฟลเดอร์ที่ยกให้ daemon ทั้งก้อน ไม่ใช่ที่อยู่ของ Dockerfile — ไฟล์นอกโฟลเดอร์นี้ COPY ไม่ได้เลย ต่อให้เขียน ../
อยากใช้ Dockerfile ที่อยู่คนละที่กับ context ให้ชี้ด้วย -f — context ยิ่งใหญ่ ยิ่งส่งนาน ยิ่ง build ช้าตั้งแต่ยังไม่เริ่ม

ลำดับบรรทัดใน Dockerfile คือ เรื่องของเวลา

กฎเดียวที่ต้องจำ — ขั้นไหนเปลี่ยน ขั้นนั้นและทุกขั้นใต้ลงไปต้องทำใหม่ จึงเรียง COPY จาก "เปลี่ยนน้อยที่สุด → เปลี่ยนบ่อยที่สุด" เสมอ
ในแล็บนี้ต่างกัน ~6 เท่า เพราะ dependency มีแค่ 4 ตัว · ของจริงที่มี package หนัก ๆ ต่างกันหลายสิบเท่า และเราจ่ายค่านี้ทุกครั้งที่แก้โค้ด

โฟลเดอร์โต 4.9M แต่ context ยังเหลือ 66B

# สร้างไฟล์ log ขนาด 5MB

จากนั้นรัน docker build -t ops-api:1.0 .
4.9M	.
#7 [internal] load build context
#7 transferring context: 66B done
#7 DONE 0.0s
สั่ง docker build ธรรมดา แล้วชี้บรรทัด transferring context — ต้องไม่มีคำว่า MB

EXPOSE เป็นป้าย ไม่ใช่ประตู

$ docker port ops-api            # กล่องที่รันโดยไม่มี -p
(ว่างเปล่า)   ·   $ curl -m 3 localhost:8088/health → exit=7
$ docker run -d --name ops-api -p 8088:8000 …
$ docker port ops-api → 8000/tcp -> 0.0.0.0:8088
$ curl -s localhost:8088/health → {"status":"ok","db":"up"}
image เดียวกัน ที่ประกาศ EXPOSE 8000 เหมือนกัน ต่างแค่มี -p หรือไม่ — -p 8088:8000 = ซ้ายพอร์ตเครื่อง · ขวาพอร์ตในกล่อง
