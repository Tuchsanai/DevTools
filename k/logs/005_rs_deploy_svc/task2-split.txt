ลำดับการเรียนรู้ (สำคัญ): ตอนเรียนบท 005 ยังไม่รู้จัก Service/Deployment; บท 006 รู้ ReplicaSet แล้วแต่ยังไม่รู้ Deployment (ใช้ ReplicaSet เป็นตัวสร้าง Pod หลัง Service ได้เลย เพราะ Service เลือก Pod ด้วย label ไม่สนว่าใครสร้าง); บท 007 รู้ทั้ง RS และ Service แล้ว ห้ามใช้สิ่งที่ยังไม่เรียนในขั้นตอน LAB (กล่าวปูทางได้) แต่ละบทต้องจบด้วยปัญหาที่บทถัดไปแก้ เรื่องเล่าน้องส้มต่อเนื่อง

เนื้อหาแต่ละบท (ขยายให้ละเอียดเต็มบท ไม่ใช่แค่ตัดแบ่ง):
- 005 ReplicaSet: ทบทวนปัญหา Pod เดี่ยว, controller/reconciliation loop, ReplicaSet spec (replicas, selector matchLabels/matchExpressions, template, ownerReferences, pod naming), self-healing (ลบ Pod, node ล่ม ต่อจากบท 003), scale (kubectl scale/apply/edit), กับดัก label (Pod เดี่ยวที่ label ตรงถูกรับเลี้ยง/Pod เกินถูกลบ, ถอด label ออกให้ Pod หลุดจาก RS เพื่อ debug), selector immutable, การลบ RS แบบ cascade vs --cascade=orphan, แก้ template แล้ว Pod เก่าไม่เปลี่ยน (ปูทาง Deployment), ReplicationController (ประวัติสั้น), RS กับ namespace/quota (ต่อบท 004), RS กับ scheduling/anti-affinity กระจาย replica (ต่อบท 003). LAB 8–10 ข้อ. LAB สุดท้าย: "ร้านน้องส้ม 3 บูธด้วย ReplicaSet" — Pod template ร้านแบบ all-in-one (web + db sidecar จากบท 002/004, image som-shop-web:1.1 ของบท 004 ที่อ่าน header/footer จาก env) replicas 3 กระจายคนละ node ได้, ลบ Pod แล้วเกิดใหม่, scale 3→5→2, เห็นปัญหา: แต่ละบูธมี DB ของตัวเอง ออเดอร์ไม่ตรงกัน, IP เปลี่ยนต้อง port-forward ทีละ Pod, แก้ image ใน template แล้ว Pod เดิมไม่อัปเดต → ปูทาง Service และ Deployment
- 006 Service: ทำไมต้องมี, selector → EndpointSlice, ClusterIP, port/targetPort/nodePort, NodePort range 30000–32767 และพอร์ต 30080–30082 ที่ map ไว้ตั้งแต่บท 001 (เปิด http://localhost:30080 บนเครื่องนักศึกษาได้ตรง ๆ), LoadBalancer (kind ไม่มี external IP), ExternalName, headless, DNS <svc>.<ns>.svc.cluster.local + ข้าม namespace ต่อบท 004 + search domain, kube-proxy (แนวคิด iptables/nftables), การกระจายโหลด + keep-alive ของ browser, sessionAffinity, readinessProbe กับ endpoints, Service selector ผิด → endpoints ว่าง → debug, env var ของ Service, NetworkPolicy กับ Service (ต่อบท 004). LAB 9–11 ข้อ. LAB สุดท้าย: "แยก web กับ db ครั้งแรก" — db = ReplicaSet replicas 1 (postgres:17.11-alpine, emptyDir) + Service ClusterIP som-db; web = ReplicaSet replicas 3 (som-shop-web:1.2 ที่ต่อ DB ผ่าน host som-db, seed ด้วย initContainer ที่ใช้ pg_advisory_xact_lock ตามผล pre-check, หน้า 503 อ่านง่ายเมื่อ DB หาย) + Service NodePort 30080; curl วนเห็นการกระจายโหลดทุก replica แต่ออเดอร์รวมที่ DB เดียว (แก้ปัญหาบท 005), ลบ Pod db → RS สร้างใหม่ IP ใหม่ แต่ชื่อ som-db เดิมใช้ได้ (ข้อมูลหายเพราะ emptyDir → ปูทาง PVC), ปัญหาที่เหลือ: อยากอัปเดตเป็น 1.3 ต้องลบ Pod เองทีละตัว/ร้านสะดุด → ปูทาง Deployment
- 007 Deployment: Deployment→ReplicaSet→Pod, pod-template-hash, rolling update (maxSurge ปัดขึ้น / maxUnavailable ปัดลง), Recreate, minReadySeconds, readinessProbe กับ rollout, preStop + terminationGracePeriodSeconds เพื่อ zero-downtime (ผล pre-check: ไม่มี preStop error 3/300, มี preStop sleep 5 + maxUnavailable 0 ได้ 0/300), progressDeadlineSeconds/ProgressDeadlineExceeded, rollout status/history/undo/pause/resume/restart, change-cause และกับดัก (สืบทอดข้อความ, undo เลื่อน revision), revisionHistoryLimit, set image/scale/edit/apply, การย้ายจาก RS เป็น Deployment (adopt?), blue/green และ canary ด้วย label + Service (ทฤษฎีสั้น/ทดลองเล็ก), HPA ปูทาง. LAB 9–11 ข้อ. LAB สุดท้าย: "ร้านน้องส้มแบบโปรดักชันจริง" — แปลง web และ db เป็น Deployment (db strategy Recreate), Service เดิม (som-db, NodePort 30080), rolling update 1.2→1.3 ระหว่าง curl วนไม่มี error, rollback, รุ่นพัง 1.4 (tag ไม่มี) → ProgressDeadlineExceeded แต่ร้านยังขายได้ → undo, scale 3→5, rollout restart
- ทุกบทใช้ภาพจำนวนมากได้เต็มที่ (ผู้ใช้อนุญาตให้ใช้ image gen ไม่จำกัด): ทฤษฎีบทละอย่างน้อย 32 ภาพ, LAB บทละอย่างน้อย 18 ภาพ (ทุก LAB มีภาพเปิด, LAB สุดท้ายหลายภาพ) ใช้ prompt ในบทรวมได้ถ้าตรงเนื้อหา แล้วเพิ่ม/แก้ให้ครบ ภาพเปิดบทและภาพสรุปบทต้องเป็นของแต่ละบท
