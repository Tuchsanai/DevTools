- บทนี้ "ปลดล็อก" สิ่งที่บทก่อน ๆ เกริ่นไว้: Pod เดี่ยวหายแล้วไม่มีใครสร้างใหม่ → ReplicaSet/Deployment; IP เปลี่ยน/port-forward หลุด → Service. นักศึกษายังไม่ได้เรียน PersistentVolume/PVC, StatefulSet, Ingress, ConfigMap/Secret แบบละเอียด, HPA (กล่าวถึงเป็นการปูทางได้ ไม่ใช้ใน LAB ยกเว้นจำเป็นและอธิบายสั้นพอ)

- LAB ละเอียด 10–12 ข้อ จากง่ายไปยาก (ทุกข้อทดสอบจริงได้ใน k8s-lab) เช่น ReplicaSet + self-healing → กับดัก label/รับเลี้ยง Pod → Deployment แรก + scale → rolling update ดู RS เก่า/ใหม่ + rollout history/undo → maxSurge/maxUnavailable/Recreate เทียบกัน (watch) → rollout พังด้วย image ผิด + readinessProbe แล้ว rollback → Service ClusterIP + DNS + curl จาก Pod อื่น ดูการกระจายโหลด (hostname) → Service selector ผิด debug endpoints → NodePort 30080 เปิดจาก browser บนเครื่องนักศึกษา → zero-downtime rollout ระหว่างยิง curl วน (นับ error) → ข้าม namespace ด้วย DNS → LAB สุดท้าย
- LAB สุดท้าย (แนะนำ ปรับได้ถ้ามีเหตุผล): "ร้านน้องส้มแบบโปรดักชันจริงครั้งแรก" แยก web กับ db ที่บทก่อน ๆ รวมไว้ใน Pod เดียว: db = Deployment replicas 1 (postgres:17.11-alpine, strategy Recreate, emptyDir พร้อมอธิบายว่าข้อมูลยังหายถ้า Pod db ถูกสร้างใหม่ — บทหน้าจะใช้ PVC/StatefulSet) + Service ClusterIP ชื่อ som-db; web = Deployment replicas 3 (som-shop-web เวอร์ชันใหม่ เช่น 1.2 ที่ต่อ DB ผ่าน DATABASE_URL host som-db และแสดงชื่อ Pod/เวอร์ชันบนหน้า เพื่อเห็น load balancing) + Service NodePort 30080 เปิด http://localhost:30080 บนเครื่องนักศึกษาได้ตรง ๆ (ไม่ต้อง port-forward/ssh -L แล้ว), seed ทำด้วย initContainer ของ web หรือ Job (ถ้าใช้ Job ต้องอธิบายสั้น) ระวัง seed ซ้ำพร้อมกันจาก 3 replicas (idempotent ON CONFLICT), scale web 3→5, ลบ Pod web แล้วถูกสร้างใหม่อัตโนมัติ, rolling update เป็นเวอร์ชันใหม่ (เช่น 1.3 เปลี่ยนธีม/ป้าย "เวอร์ชัน") ระหว่างยิงคำขอวนแล้วไม่มี error, rollback, จำลองเวอร์ชันพัง (image tag ไม่มี หรือ readiness ล้ม) แล้ว rollout ค้างแต่ร้านยังขายได้ → rollout undo, ลบ Pod db → ข้อมูลหาย (ปูทาง PVC) ระบุผลที่ต้องเห็นและจุดที่ต้องยืนยันตอนทดสอบจริง (เช่น NodePort 30080 ผ่าน extraPortMappings ได้จริงจาก host ของนักศึกษา, การกระจายโหลดเห็นได้จาก browser หรือไม่ (keep-alive อาจติด Pod เดียว → ให้ใช้ curl วน), เวลา rollout, ข้อความ ProgressDeadlineExceeded จริง)
