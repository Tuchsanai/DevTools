บท 010 ConfigMap — ทฤษฎีละเอียด: ปัญหาค่าตั้งค่าฝังใน image/YAML (12-factor config), ConfigMap คืออะไร (key-value, data vs binaryData, ขนาด ≤1MiB, namespaced), วิธีสร้าง (--from-literal, --from-file, --from-env-file, YAML, kubectl create ... --dry-run=client -o yaml), วิธีใช้ใน Pod: env.valueFrom.configMapKeyRef, envFrom (+prefix), volume mount ทั้ง ConfigMap / items เลือกบาง key / subPath / defaultMode, args อ้าง $(VAR), optional: true กับ ConfigMap หรือ key ที่ไม่มี (CreateContainerConfigError — ยืนยันข้อความจริง), การอัปเดต: env ไม่เปลี่ยนจนกว่า Pod ใหม่ / volume อัปเดตเอง (หน่วงเวลาตาม kubelet sync — วัดเวลาจริง) / subPath ไม่อัปเดต / ลิงก์ ..data symlink, แอปต้องอ่านไฟล์ใหม่เอง (เช่น nginx -s reload) / rollout restart หรือเปลี่ยน annotation (checksum pattern), immutable: true, ConfigMap ข้าม namespace ไม่ได้, ConfigMap ใน kube-system (เช่น coredns, kube-proxy) ให้ดูเป็นตัวอย่าง, ConfigMap กับ RBAC, kustomize configMapGenerator แบบสั้น (kubectl apply -k ใช้ได้ใน kubectl v1.37 — ยืนยัน) ทำให้ชื่อมี hash → rollout อัตโนมัติ, แนวปฏิบัติ, ตารางเลือก env vs volume. LAB 9–11 ข้อจากง่ายไปยาก (ทุกข้อทดสอบจริง). LAB สุดท้าย: "ร้านน้องส้มเปลี่ยนป้ายไม่ต้อง build ใหม่" — ย้าย SHOP_NAME/header/footer/ธีม (ตามที่แอปรองรับจริง) ไปไว้ใน ConfigMap ผ่าน envFrom, เปลี่ยนชื่อร้าน/โปรโมชันด้วยการแก้ ConfigMap + rollout restart (เห็นว่าก่อน restart ยังเป็นค่าเดิม), เพิ่ม ConfigMap สำหรับไฟล์ตั้งค่าที่ mount เป็น volume ที่ทดสอบการอัปเดตอัตโนมัติได้ (เช่น หน้าประกาศ/เมนูพิเศษที่แอปหรือ sidecar nginx อ่านไฟล์ — ถ้าแอปไม่รองรับการอ่านไฟล์ ให้เพิ่มความสามารถเล็ก ๆ ในแอปเป็นรุ่นใหม่ เช่น som-shop-web:1.5 อ่านไฟล์ /etc/som/announcement.txt ทุก request หรือใช้ nginx sidecar เสิร์ฟ /announce — เลือกแบบที่ง่ายและเสถียรที่สุดแล้วยืนยันจริง) แล้วเห็นการเปลี่ยนโดยไม่ restart, ทดลอง immutable, ปิดบทด้วยปัญหา: รหัสผ่าน DB ยังอยู่ใน YAML/ConfigMap อ่านได้ทุกคน → บท 011
บท 011 Secret — ทฤษฎีละเอียด: Secret ต่างจาก ConfigMap อย่างไร (base64 ≠ เข้ารหัส — สาธิต decode), type ต่าง ๆ (Opaque, kubernetes.io/basic-auth, dockerconfigjson, tls, service-account-token), สร้างด้วย --from-literal/--from-file/YAML data vs stringData, ใช้งาน env/envFrom/volume (tmpfs, 0400/defaultMode, ไฟล์ต่อ key), imagePullSecrets (สาธิตแนวคิด หรือ registry ภายในถ้าทำได้ง่ายและเสถียร ไม่ใช้ Docker Hub จริงของผู้ใช้), TLS secret (สร้าง cert ตัวอย่างด้วย openssl แล้ว mount ให้ nginx HTTPS ทดสอบด้วย curl -k — ถ้าทำได้), การอัปเดต (เหมือน ConfigMap), immutable, RBAC กับ Secret (ใครอ่านได้ — ต่อบท 004: ServiceAccount ที่มีสิทธิ์ get pods อ่าน secret ไม่ได้ / คนที่สร้าง Pod ได้อ่าน secret ทางอ้อมได้), encryption at rest ใน etcd (สาธิตด้วยการอ่าน etcd ใน lab-control-plane ว่าเป็น plaintext — ถ้าทำได้ปลอดภัยใน container ทดลอง; การเปิด EncryptionConfiguration อธิบายเป็นทฤษฎี), ข้อควรระวัง (อย่า commit secret ลง git, log/env รั่ว, kubectl describe ไม่แสดงค่า, kubectl get -o yaml แสดง), แนวทาง external (Sealed Secrets, External Secrets, Vault — ปูทาง), projected volume (configMap+secret+downwardAPI), ตารางสรุป ConfigMap vs Secret. LAB 9–11 ข้อ. LAB สุดท้าย: "ร้านน้องส้มซ่อนรหัสผ่าน" — ย้ายรหัส DB ของ StatefulSet postgres และ DATABASE_URL ของ web ไปไว้ใน Secret (stringData หรือ --from-literal) web ใช้ secretKeyRef, เปลี่ยนรหัส DB จริง (ALTER USER + อัปเดต Secret + rollout restart web) ร้านกลับมาขายได้ ออเดอร์ยังอยู่, RBAC: ServiceAccount intern ดู Pod/ConfigMap ได้แต่อ่าน Secret ไม่ได้ (Forbidden จริง), ถ้าทำ TLS ได้ให้มี HTTPS ผ่าน nginx หรือแยกไว้ใน LAB ก่อนหน้า ปิดบทปูทาง Ingress (TLS ที่ Ingress), HPA, Helm
