- LAB ละเอียด 9–11 ข้อ จากง่ายไปยาก แนวทาง: สำรวจ node (get/describe/labels/allocatable/สำรวจ node container ด้วย docker exec lab-worker crictl ps) → scheduler กับ Pending (requests เกิน allocatable) → nodeName → ติด label node + nodeSelector → node affinity required/preferred → pod anti-affinity/affinity → topologySpreadConstraints → taint/toleration (รวมทดลองวางบน control-plane) และ NoExecute+tolerationSeconds → cordon/drain → จำลอง node ล่มด้วย docker stop lab-worker2 (ใน k8s-lab node คือ container) ดู NotReady, taint อัตโนมัติ, Pod ที่ตั้ง tolerationSeconds สั้นถูก evict แล้ว docker start คืน → static pod (เขียน manifest ลง /etc/kubernetes/manifests ใน lab-worker ด้วย docker exec) → LAB สุดท้าย
- LAB สุดท้าย (แนะนำ ปรับได้ถ้ามีเหตุผล): "เปิดร้านน้องส้มหลายสาขาบนกองเรือ" ใช้ image som-shop-web:1.0 + postgres:17.11-alpine เดิมจากบท 002 (build จาก 002_kubernetes_pod/02_LAB/som-shop/app ถ้ายังไม่มี และใช้วิธี kind load ตามที่บท 002 ทดสอบไว้ รวม workaround postgres) สร้าง Pod ร้านแบบ all-in-one 2 สาขา (som-shop-a, som-shop-b) ที่ใช้ podAntiAffinity บังคับให้อยู่คนละ worker, nodeAffinity เลือก node ที่ติด label เช่น shop=open, ใช้ Downward API ใส่ NODE_NAME แล้วตั้ง SHOP_NAME="ร้านอาหารแมวน้องส้ม สาขา $(NODE_NAME)" ให้หน้าเว็บโชว์ว่าสาขาอยู่บนเรือลำไหน, เปิดทั้ง 2 สาขาด้วย port-forward คนละ port + ssh -L, จากนั้นจำลองเรือลำหนึ่งล่ม/ drain → สาขานั้นปิด อีกสาขายังขายได้ แต่ไม่มีใครสร้าง Pod ใหม่ให้ → ปูทาง Deployment/Service บทหน้า ระบุผลที่ต้องเห็น และจุดที่ต้องยืนยันตอนทดสอบจริง (เช่น เวลาที่ node เป็น NotReady, ข้อความ Events จริง)
