## 0. ภาพรวมและข้อกำหนด

- ผู้เรียนผ่าน 001–010 (รวม ConfigMap: env/envFrom/volume, อัปเดต ~1 นาที, immutable, RBAC ของ ConfigMap)
- โฟลเดอร์ LAB: `docker cp 011_kubernetes_secret k8s-lab:/workspace/` → `cd /workspace/011_kubernetes_secret/02_LAB` (LAB1–8 `cd labs/labNN-*`, LAB9 `cd som-shop-v7`)
- **ใช้ได้ใน LAB:** 001–010 + Secret ทุก type, imagePullSecrets กับ registry ภายใน (registry:2 + htpasswd บน network `kind`), TLS กับ nginx, projected volume, etcdctl (อ่านอย่างเดียว)
- **ยังไม่ใช้:** Ingress (TLS ที่ Ingress ปูทาง), HPA, Helm, Sealed Secrets/External Secrets/Vault (แนวคิด), EncryptionConfiguration (ทฤษฎี — ไม่แก้ kube-apiserver ใน LAB)
- **อุปมาใหม่:** Secret = ซองสีกรมท่าปิดผนึกครั่งรูปอุ้งเท้าสีส้ม เก็บในกล่องกุญแจเหล็กบนผนังโซนข้างกระดานประกาศ; **base64 = ซองใส** (แค่เขียนด้วยตัวอักษรอีกชุด ใครก็แปลงกลับได้ — ไม่ใช่กุญแจ); encryption at rest = ประตูตู้นิรภัยกลมในหอบังคับการหน้าตู้เอกสาร etcd; RBAC = บัตรพนักงานคล้องคอ (แถบเขียวเปิดกล่องได้ / แถบเทา intern ดูได้แค่กระดานและบูธ); Secret volume = ถาดฟองน้ำความจำ (tmpfs ไม่เขียนลงดาดฟ้าเรือ); TLS = ท่อส่งแก้วปิดสนิทพร้อมเหรียญใบรับรอง; imagePullSecrets = บัตรผ่านประตูคลังตู้สินค้าส่วนตัว; projected = แฟ้มห่วงรวมการ์ด+ซอง+ป้ายชื่อบูธ; service-account-token = บัตรพนักงานหุ่นยนต์แถบบาร์โค้ดยาว
- รหัสในภาพ: `●●●●` หรือค่าตัวอย่าง `meow1234`/`bWVvdzEyMzQ=` (เฉพาะภาพสาธิต base64)

## 4. ผล pre-check ที่ยืนยันแล้ว (5 ต.ค. 2569)

1. `describe secret` แสดง `password:  8 bytes`; `get -o yaml` แสดง base64; `echo meow1234 \| base64` = `bWVvdzEyMzQK` (มี newline), `echo -n` = `bWVvdzEyMzQ=`
2. data + stringData key ซ้ำ → stringData ชนะ (`b3ZlcnJpZGUtYnktc3RyaW5nRGF0YQ==`); **`kubectl apply` เก็บ stringData เป็นข้อความใน `last-applied-configuration`** (ส่วน `create … --dry-run=client -o yaml \| kubectl apply -f -` annotation เก็บเป็น base64 ใน `data`)
3. basic-auth ใส่แค่ password ได้ (`bad … DATA 1`); ว่าง → `[data[username]: Required value, data[password]: Required value]`; tls: `data[tls.key]: Required value`, `tls: failed to find any PEM data in key input`
4. volume Secret = `tmpfs (ro,relatime,size=…,noswap)`; 0400 → `-r--------`; projected 0440 → `-r--r-----`; อัปเดต volume 47 วิ, env ไม่เปลี่ยน; immutable → Forbidden
5. service-account-token: ระบบเติม 3 key, describe **แสดง token เต็ม**, `kubectl create token builder --duration=10m` ใช้ได้
6. TLS nginx + NodePort: `(60) SSL certificate problem: self-signed certificate`; `-k`/`--cacert` ผ่าน; `--resolve shop.som.local:30081:127.0.0.1` ผ่าน
7. **imagePullSecrets:** registry:2 + htpasswd + `hosts.toml` ใช้ได้ไม่ต้อง restart containerd; error ไม่มีบัตร/บัตรผิดตามตาราง; ผูก SA ได้; **kubelet v1.37 ตรวจบัตรซ้ำสำหรับ image ที่เคยดึงด้วย Secret** — Pod `cached` (ns อื่น, ไม่มีบัตร, `nodeName: lab-worker`) `ErrImagePull … no basic auth credentials`; ผลข้างเคียงที่เจอ: เพราะ push `som-shop-web:1.5` ตัวเดียวกัน (image ID `6cd0ee39…`) ขึ้น registry แล้วดึงด้วย regcred บน lab-worker → Pod ร้าน (`som-shop-web:1.5`, IfNotPresent, ไม่มีบัตร) บน lab-worker ติด `Init:ErrImagePull … docker.io/library/som-shop-web:1.5 … insufficient_scope` (record `credentialMapping: kind-registry:5000/som-shop-web → regcred`) แก้ได้ด้วยลบ record + restart kubelet (ไม่ให้นักศึกษาทำ) → **LAB5 ต้องใช้ image แยก `som-menu:1.0`** และห้าม `crictl rmi` (ใน pre-check `crictl rmi` ลบ tag `som-shop-web:1.5` ออกจาก Node ไปด้วยเพราะ image ID เดียวกัน)
